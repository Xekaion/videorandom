# 1.9.41 · ASR·발화 검출의 공동 누락과 재검사 입력 가속

2026-11-15. 사용자가 CRPD-180의 앞 대사를 반복 누락 사례로 지정했다. 서버의 보관 결과 중 최근 세 건은 원문 644/672/690개이고 모두 첫 시작이 40.6초였다. 앞 60초에는 원문이 한 개뿐이며, 첫 40.6초는 누락 검사 목록에도 없었다. 이는 발화 검출과 ASR이 함께 놓친 범위를 재검사 계획에 넣지 않는 구조적 빈틈과 일치한다. 정확한 누락 대사와 음향의 관계는 원본 파형·정답 대조가 필요하다. 현재 PC에는 해당 원본 영상이 없고 원격 접수 결과만 있으므로 실제 CRPD-180의 앞부분을 새 모델로 재생·재인식하거나 정확도 향상률을 측정하지 않았다.

## 변경

기존 전체 음성 처리와 VAD 기반 누락 검사를 유지하면서 독립 음향 후보를 추가한다. 20ms RMS·peak와 30초 블록의 상대 잡음 바닥을 numpy로 계산한다. 전체 영상을 복사하지 않고 블록 단위 임시 배열을 사용하며 원본 신호는 변경하지 않는다. 변조가 있는 작은 소리를 잡되 일정한 잡음·지속음은 억제한다. 이 검사는 언어 발화 판별기가 아니고, 음악·효과음도 후보가 될 수 있으며 모든 소리를 검출한다는 보장은 없다.

별도로 첫 대사 전의 빈 범위는 최대 90초까지 재검사한다. 이 범위는 VAD와 음향 후보가 모두 없어도 계획에 넣는다. 초기 전체 입력 범위를 줄이거나 영상을 건너뛰지 않는다. 실제 CLI의 정확 모드에 적용하며, 빠름·초고속의 생략 정책은 바꾸지 않는다.

재검사에서 `no_speech_threshold`와 `hallucination_silence_threshold`를 끄므로 최초의 건너뛰기 조건을 그대로 반복하지 않는다. 기존 VAD·불확실 구간의 보수적 병합 조건은 유지한다. 새 음향/앞부분 후보는 유효한 단어 시각과 높은 신뢰도 조건을 만족한 실제 인식 대사만 병합한다. 공백·낮은 신뢰도·단어 정렬 없는 후보로 임의의 대사를 만들지 않는다. 남은 음향 후보는 `possible_missing_audio`로 표시하고 음악·효과음일 수 있음을 안내한다. 검사 실패는 `acoustic_audit_unavailable`로 남겨 완료를 인증하지 않는다.

속도 개선은 NumPy 배열의 저음량·잡음 판정을 벡터 계산으로 바꾼 것이다. 일반 대사는 기존처럼 첫 높은 peak에서 바로 제외하며 사용자 정의 시퀀스와 너무 긴 구간은 기존 경로를 쓴다. RMS·상관도·프레임 에너지 비율의 임계점 근처에서는 원래 순차 누적을 다시 계산한다. 소리·대사 제외 조건을 완화하지 않는다. large-v3·beam 5·best-of 5·온도 fallback·단어 정렬·최대 두 GPU 작업자·OOM fallback과 기존 30초 코어·3초 문맥·최대 1.2배 입력 예산을 유지한다.

인식 revision은 4로 올렸다. 이전 결과를 읽고 보관할 수 있지만 정확 모드의 현재 인식 증거로 재사용하지 않는다. 이전 원문을 입력으로 넣지 않는 **원문부터 다시 분석**이 실제 적용 경로다. 테스트의 현재 형식 증거를 revision 4로 갱신하고 revision 3의 캐시 재사용 거부를 별도로 검사한다.

## 측정과 검증 범위

`artifacts/asr-blindspot-v1941-benchmark.json`: 합성 10초 구간의 저음량·잡음 판정 함수, 각 5회 중앙값. 고정 잡음 0.06491→0.00281초(23.14배), 작은 지속음 0.06685→0.00215초(31.16배), 무음 0.06440→0.00122초(52.83배)이며 모두 판정이 동일했다. CPU 함수의 실측이며 전체 ASR·영상 배속이 아니다. 기존 재검사 계획의 동일성도 비교했다.

합성 600초 배열(0.2초 tone 200개)을 검사한 5회 중앙값은 0.0305초이며 후보 200개·40초를 찾았다. 실제 사용자 음성의 누락률을 뜻하지 않는다. 새 검사가 실제 재검사 범위를 넓히므로 전체 작업 시간이 늘어나는 영상도 있을 수 있다. 활성 서버의 GPU 작업에는 개입하지 않았다.

중립 Python 검사 17개: 조용한 소리·짧은 소리·무음·지속음·고정 잡음·블록 경계·유효하지 않은 파형·마지막 블록·ASR/VAD 공동 누락·모든 검출기가 놓친 앞부분·낮은 신뢰도 및 정렬 없는 텍스트 차단·검사 실패·빠름 모드·기존 재검사 예산·반올림 1,000개·잡음 판정의 무작위 300개 및 임계점 차등 검사·실제 main 진입점의 새 검사와 최소 발화 64ms 연결. 기존 Python ASR 99개, 문맥 검사 10개와 잡음 조기 종료 10개도 유지한다. 직접 함수 검사는 가짜 모델을 사용하므로 실제 대사 정확도 개선 실측으로 해석하지 않는다.

추가로 로컬 `small` CPU int8·한 스레드와 중립 합성 영어 60초로 24초 재검사 코어 실험을 했다. 기존 방식은 49.65/44.89초, 실험 방식은 56.94/59.64초이고 실제 encoder 호출은 모두 4개였다. 단순 패딩량 감소가 실제 추론 가속으로 이어지지 않아 24초 변경은 배포에서 제거했다. 생산 정확 모드 모델은 large-v3 그대로다. `artifacts/native-decoder-v1941.json`과 `.log`는 **제외한 실험**의 측정이며 최종 버전 배속으로 인용하지 않는다.

[고정 faster-whisper VAD 소스](https://github.com/SYSTRAN/faster-whisper/blob/v1.2.1/faster_whisper/vad.py)와 [transcribe 소스](https://github.com/SYSTRAN/faster-whisper/blob/v1.2.1/faster_whisper/transcribe.py)를 로컬 설치본과 함께 확인했다. 짧은 발화 제외와 no-speech·환각 건너뛰기 경로를 기준으로 수정했다.
