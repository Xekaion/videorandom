# 1.9.2 · 분석 서버의 연결 PC 진단 기록

2026-10-18. 원격 영상 분석이 일부만 끝났을 때 원본 PC의 오류 문구를 다시 물어야 했던 문제를 개선한다. 분석 서버에서 파일명·PC·프로그램 버전·처리 단계·저장한 자막 구간 수·기술 오류를 검색하고 전체 JSONL로 내보낸다.

## 기록과 전송

서버는 작업 접수·단계 변경·번역 초안/검수·체크포인트 저장·최종 결과를 남긴다. 전송 작업 자체가 종료됐다는 상태와 실제 분석 결과의 완료/일부 완료/실패를 구분한다. 자막 개수 오류에는 요청 범위와 기대 개수·실제 반환 개수·저장된 진척을 보관하며, 응답 배열이 없으면 반환 개수를 추정하지 않는다.

원본 PC에서는 작업 시작 전 검사·연결·업로드·자막 파일 및 분석 결과 저장 오류를 기록한다. 원본 PC의 기록은 연결 설정에 지정한 서버로 인증하여 보고한다. 연결이 끊기면 메타데이터만 로컬 전송 대기에 남기고, 다음 연결에서 수신 확인된 항목만 지운다. 수신 확인을 별도 보관하므로 같은 과거 오류를 프로그램 시작마다 재전송하지 않는다. 이 전송은 분석 요청·음성 인식·한국어 번역을 재시도하지 않는다.

각 PC의 식별자·이름·프로그램 버전과 서버가 확인한 접속 주소를 기록한다. 클라이언트가 보고하는 이름은 장치 인증의 증거가 아니다. 서버와 클라이언트 작업 ID를 함께 남겨 업로드 이후의 결과 저장 실패도 같은 작업과 대조할 수 있다.

## 보존·조회·민감 정보

진단은 기존 결과·연결 설정과 같은 데이터 폴더의 `diagnostics` 아래에 원자적으로 저장한다. 자동으로 오래된 기록을 삭제하지 않는다. 화면은 최대 200개씩 조회하고 커서로 이전 기록을 불러온다. 검색은 파일명·PC·작업 ID·단계·오류 코드/메시지에 적용하며 전체 내보내기는 검색과 관계없이 보관한 모든 기술 기록을 포함한다.

진단 입력은 허용한 필드만 보관한다. 대사·줄거리·이미지·프롬프트·원본 전체 경로·연결 코드·Authorization·스택·임의의 서비스 응답은 제외한다. 오류는 알려진 기술 분류의 고정 문구와 제한된 숫자·코드로 바꾸며, 알려지지 않은 오류를 임의의 원인으로 단정하지 않는다. 서버 API는 기존 사설 네트워크·연결 코드 인증을 사용하고, 클라이언트 보고 크기와 개수를 제한한다. 화면은 로그 값을 HTML로 실행하지 않는다.

## 기존 결과와 적용 범위

저장돼 있는 원격 분석 실패 결과와 서버 완료 작업에서 기술 정보만 가져온다. 다시 실행해도 동일한 과거 기록을 중복 생성하지 않는다. 이전 분석의 시각과 알려진 원래 버전, 이번 기록을 보고한 프로그램 버전은 구별한다. 당시 버전·단계·반환 개수가 없으면 현재 값으로 채우지 않는다. 1.6.5처럼 서버의 오류를 메모리에만 두었던 버전에서 이미 사라진 오류는 복원할 수 없다.

서버와 원본 PC가 모두 새 버전이어야 클라이언트에서 발생한 오류를 원격으로 모을 수 있다. 오프라인 PC의 기록은 다시 같은 서버에 연결돼야 도착한다. Node 소스 서버에는 EXE 자동 교체가 적용되지 않으므로 새 코드를 실행해야 한다.

## 검증 범위

합성 열차 안내·모의 번역 응답·독립 임시 데이터 폴더·직접 만든 테스트 서버만 사용한다. 실제 사용자 영상·대사·이미지를 열지 않으며 운영 서버를 중지하거나 재시작하지 않는다.

검사는 번역 응답 개수 불일치의 정확한 숫자·초안/검수 단계, 로그 콜백 실패 시 기존 분석 보존, 원문/자막/연결 정보가 로그로 새지 않음, 재시작 후 기록·오프라인 전송 대기 보존, 중복 보고 수신 및 수신 확인, 인증·보고 크기 제한, 클라이언트 저장 실패의 서버 조회, 과거 버전 미상 보존, 검색·페이지·전체 내보내기, 화면의 오래된 응답·필터·자동 갱신·안전한 텍스트 표시를 포함한다.

## 배포 확인 결과

* 전체 Node 회귀: `node --test --test-concurrency=4 --test-timeout=60000 test/*.test.js`, **714개 통과, 실패·취소·건너뛰기 0개**, 약 50.3초. 기존 음성 인식 Python 모의 검사도 포함한다. 실제 모델 추론은 실행하지 않았다.
* 최초의 기본 병렬 실행에서는 테스트의 임시 폴더 삭제가 해당 테스트 서버와 로그 저장 종료보다 먼저 실행되어 `ENOTEMPTY`가 발생했다. 폴더 정리를 테스트 서비스 종료 뒤로 옮기고 최종 전체 검사를 완료했다. 브라우저에서 금지한 임시 포트가 배정되는 기존 LAN 검사도 모의 HTTP 전송 경로를 사용하도록 고쳤다. 조치는 직접 만든 테스트 프로세스와 임시 폴더에 한정했다.
* Windows EXE 빌드 성공. **99,376,524바이트**, SHA-256 `e90f3530b688961e9de5dce184e37b4b496e18251abae7a419cd655abada73b9`. `update.json`을 실제 파일 크기·해시·MZ 헤더와 대조했고 다운로드 주소는 `v1.9.2` 태그에 고정했다.
* 최종 EXE의 HTML·CSS·진단/목록/진행/업데이트 스크립트가 소스와 일치했다. 별도 클라이언트 EXE의 과거 실패 가져오기 → 인증된 모의 분석 서버 수신 → 중앙 조회를 연결해 **총 1,819개·저장 160개·요청 80개·반환 37개**의 합성 수치와 초안/검수 단계·원래 버전·보고 버전이 보존되는지 확인했다. JSONL에는 대사·프롬프트·원본 전체 경로·연결 코드가 포함되지 않았다.
* 기존 EXE 기능인 한국어 번역만 복구, 원래 자막 시각, 영상 옆 SRT 저장, 기존 완성 자막·원문·사용자가 중지한 대기열도 합성 자료로 확인했다.
* 복사한 **실제 1.9.1 EXE → 1.9.2 EXE** 업데이트와 기대 버전을 일부러 다르게 만든 시작 실패의 **1.9.1 복구·재실행**을 확인했다. 두 경로 모두 합성 결과·SRT·중지 대기열·암호화한 클라이언트/서버 연결·진단 PC 식별자·진단 이벤트·미전송 보고의 **8개 파일이 바이트 단위로 유지**됐다. 도우미가 실행한 프로세스와 테스트 포트·폴더만 사용했다.

이 결과는 새 진단 기능과 회귀·업데이트 보존 검증이다. 기존 사용자 영상의 번역이 끝까지 완료됐다는 의미는 아니며, 당시 저장되지 않은 오류나 반환 개수를 복원한 검사도 아니다.
