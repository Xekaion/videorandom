# 1.9.33 · 정확 모드의 병합 검색과 준비 대기 감소

2026-10-27. 1.9.32를 기준으로 정확 모드의 추가 가속을 검토했다. 실제 사용자 영상·음성·전사·요약·제공자 원시 응답을 열거나 실제 모델·GPU 추론·ASR·번역을 실행하지 않았다. 검증은 중립 자막 메타데이터, 수치 배열, 가짜 모델·오디오 로더, 가짜 FFmpeg·LAN·CLI와 별도 시험 저장소로 제한했다. 운영 프로세스·설정·분석 작업은 변경하지 않는다.

## 유지한 기준과 측정 한계

정확 모드는 이미 large-v3, beam 5·best-of 5, 원래 온도 fallback, 전체 입력 음성 처리, 단어 시각과 독립 발화 검수·재인식, 검증된 메모리 조건에서 GPU 작업자 최대 2개를 사용한다. 번역도 이미 80구간·12,000자 분할, 독립 원문 대조 검수와 다음 초안 중첩이 적용돼 있다. 이를 새 기능으로 주장하지 않는다.

이 모델·옵션·입력 범위·문맥·검수·시각·순서·완료 판정을 유지한다. 정확 모드에 다른 배치 디코더나 더 작은 모델을 대신 넣거나 검수·재확인을 줄이지 않았다. 일반 디코더의 seek·fallback과 다른 배치 API, chunk별 clipping·padding과 달라지는 전역 mel 재사용도 사용하지 않는다. 실제 인증·사용량·거절·통신 오류를 우회하지 않으며 1.9.32의 출력 제한별 큐 진행과 사용자 중지를 유지한다.

**아래 수치는 특정 CPU 함수 또는 가짜 지연의 준비 단계 측정이다. 실제 영상 전체가 몇 배 빨라졌다는 실측은 없고 GPU 음성 추론 자체의 배속을 의미하지 않는다.**

## 변경

### 복구 결과 병합의 시간 인덱스

`merge_recovery`와 새 단어 병합은 후보·단어마다 전체 자막을 반복 검색했다. 새 시간 인덱스는 멀리 떨어진 자막만 제외하고 기존 비교식으로 실제 겹침·개선·이웃 충돌을 판단한다. cue와 word 시각을 함께 감싸는 보수적 경계, 원래 입력 순서의 leaf, 삭제된 위치를 유지하는 tombstone과 append 순서를 사용한다. 원래의 첫 충돌·역순 제거·삽입 묶음·동률 정렬·신뢰도·진단 flag를 보존한다. 종료 시각 개수는 실제 cue end를 별도로 집계해 단어 경계의 영향을 받지 않는다.

비정상·비유한 시각·일회성 iterator 등은 기존 선형 경로를 그대로 사용한다. ASR revision을 올려 보관된 올바른 원문을 다시 인식하게 만들지 않으며 모델·체크포인트 형식은 바꾸지 않는다.

### 모델 준비와 오디오 디코딩 중첩

모델 생성·CUDA 설정·warmup은 호출 스레드에서 그대로 실행하며, 독립된 CPU 오디오 디코딩만 한 작업자에서 함께 시작한다. 같은 `decode_audio`에 같은 절대 경로·16kHz 인수를 전달하고 같은 배열을 인식에 사용한다. 두 작업 모두 끝난 뒤에만 인식을 시작한다. 실패하면 시작된 디코딩을 정리하며, 두 로더가 모두 실패하면 원래 직렬 처리와 같이 모델 오류를 우선한다. 모델 상주화나 새 GPU 작업자는 추가하지 않는다.

### 이미지와 정확 음성 준비 중첩

새 extraction의 검증된 메타데이터가 준비된 뒤 정확 모드·한국어 자막·음성 트랙 조건에서만 음성을 준비해 이미지 추출과 겹친다. 필요한 공간·로컬 분석 환경 또는 서버 호환 확인을 먼저 수행한다. 기존의 FLAC 수준 0·동일 PCM·이미지 시점을 유지하며, 음성 준비 1개와 기존 이미지 작업자 2개로 상한을 둔다. 로컬 추출만·빠른 모드·초고속·캐시 재사용은 이 새 경로를 사용하지 않는다. 같은 준비 음성은 provider에 전달해 두 번 준비하지 않는다.

프레임 보관·진행률 단조성·취소와 최초 오류를 보존하고, 시작한 작업을 모두 정리한 뒤 자기 임시 파일만 삭제한다. private metadata hook이 없는 테스트/확장 extractor는 기존 직렬 경로를 사용한다.
