# 1.9.28 · 중단 원인별 복구와 응답 검증 경계

2026-10-27. 1.9.27에서 모든 실패 원인을 해결한 것은 아니다. 이번 변경은 남아 있던 로컬 응답 검증의 영상 전체 중단, 접수 전 연결 실패의 복구, 복구 대기열의 저장·재실행 경계와 원인별 안내를 대상으로 한다.

실제 영상·음성·대사·요약·제공자 원시 응답은 열지 않았다. 기술 메타데이터를 대조하고 가짜 CLI·엔진·로컬 HTTP와 중립 합성 자료로 검사한다. 실제 ASR·번역 요청, 운영 작업 재접수·변경 또는 운영 프로그램 재시작은 수행하지 않는다.

## 로그 대조 결과

보관된 기술 이벤트 8,187개에는 오류 이벤트 132개와 경고 169개가 있다. 서버·클라이언트·과거 이력 수입이 같은 시도를 중복 표현할 수 있으므로 고유 실패 영상 수로 합산하지 않는다. 서버 최종 결과 40개는 번역 전체 보관·원문 검증 미완료 11개, 전체 구간 처리 뒤 일부 번역 누락 10개, 번역 중단 19개로 나뉜다. 작업의 최종 상태 `completed`만으로 자막 완성을 판정해서는 안 된다.

조사 시 실행 중인 화면 프로그램과 분석 서버는 1.9.26이었다. 1.9.27 클라이언트가 보고한 최근 3개 이벤트는 과거 실패의 이력 수입이며 새 실패 시도가 아니다. 이번 소스·EXE 검증이 해당 운영 프로세스에 이미 적용됐다는 뜻은 아니다.

오래된 `UNKNOWN/provider-error` 2건은 정확한 하위 원인이 소실됐다. 경과 시간만으로 로컬 제한·모델 혼잡·서비스 거절이라고 단정할 수 없다. 새로운 진단 보존 기능은 이후 실패의 근거를 보관하며, 과거에 없어진 근거까지 복원하지 않는다. 안전한 조사 자료는 Git에서 제외한 `artifacts/failure-audit-v1928-technical.json`, `artifacts/failure-remediation-v1928-inventory.json`에 보관한다.

## 화면과 API

영상 목록·상세·작업의 실패 항목에 서버가 계산한 `recovery` 계획을 제공한다. 원인·다음 조치·자동 대기 여부와 `기존 서버 결과 받기`, `연결 상태 확인`, `보관 자막 다시 저장`, `한국어 자막만 복구`, `분석 설정 확인`, `기술 진단 보기`를 상황에 맞춰 표시한다. 원인 불명·거절을 자동 전체 재분석으로 바꾸지 않는다.

`GET /api/analysis/results/:id/recovery`는 현재 계획을 조회한다. `POST /api/analysis/results/:id/recovery/check`는 서버가 다시 계산한 허용 조치만 수행하며, 클라이언트가 보낸 임의 조치를 믿지 않는다. 연결·공간 확인과 기존 접수 결과 읽기는 음성 모델·장면 추출 설정 검증 때문에 차단되지 않는다. 사용자가 중지한 대기열은 명시적 결과 읽기를 실행해도 그대로 유지한다.

SRT 진단은 경로·스택·대사·원시 응답을 새로 기록하지 않는다. `saveStage` 12개, `pathClass` 5개와 정수 `attemptedNames` 0~10만 저장·전송·화면 경계를 통과한다.
