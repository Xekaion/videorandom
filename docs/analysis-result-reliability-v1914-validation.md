# 1.9.14 · 완료 결과와 실제 복구 대상 구분

2026-10-20. 구현 검사는 합성 자료·별도 저장소·직접 복사한 시험 EXE만 사용했다. 실제 영상·음성·대사·이미지·모델·번역 제공자를 사용하지 않았다. 운영 서버와 다른 PC의 결과·설정·작업은 변경하지 않았다.

## 확인한 문제

- 이전 UI는 정상 완료된 결과에도 복구·다시 분석 버튼을 표시했다. 버튼 존재만으로 실패 여부를 판단할 수 없었다.
- 운영 서버를 읽기 전용으로 확인한 실행 버전은 **1.9.10**이다. 진단 기록의 과거 클라이언트 버전은 다른 PC의 현재 실행 버전을 증명하지 않는다.
- 보관된 진단에서 원문 기준 번역 **129/129, 121/121**이면서 파일 저장만 실패한 사례를 확인했다. 한 사례는 실제 파일 시스템 오류 **EISDIR**가 남아 있다. 나머지의 기록되지 않은 원인은 추측하지 않는다. 번역 수는 전체 음성의 누락 없는 인식을 증명하지 않는다.
- 오류 38건·경고 5건은 보고·가져오기·단계별 중복 이벤트를 포함한다. 현재 다른 PC의 16개 결과가 모두 실패했다는 근거가 아니다. 과거 번역 중단에는 시간 초과·거절·길이 및 구간 개수 검증 실패도 기록되어 있다.

## 변경과 보존 조건

- 완료 결과의 다시 분석·재번역은 닫힌 **추가 작업** 안에 둔다. 실제 미번역, 줄거리·분석 실패, SRT 저장 실패에는 해당 단계의 기본 복구 버튼을 표시한다. 상세 화면도 같은 판정을 사용한다.
- SRT 저장 실패의 **자막 파일 다시 저장**은 기존 저장 API만 호출한다. 목록의 요약 응답에서도 저장 개수 증거를 사용하고, 이중 클릭·진행 중 작업과의 충돌을 막는다. 다른 상세 화면의 전사를 덮어쓰지 않는다.
- SRT 후보 이름을 폴더·링크·기타 비정규 파일이 사용하고 있으면 그대로 보존하고 기존의 제한된 대체 이름을 사용한다. EISDIR만 보고 성공으로 처리하지 않고 해당 이름의 실제 파일 상태를 확인한다. 권한·공간 부족·일반 입출력 오류는 실패를 유지한다. 기존 완성 SRT·다른 파일·폴더를 덮어쓰거나 제거하지 않는다.
- 새 번역 시도만 실패했을 때 이전 완성 상태를 유지하려면 양쪽 V1 완료 증거, 전체 원문 SHA-256, cue ID·시각·본문, 한국어 전체 번역, 원어 품질 증거가 모두 일치해야 한다. 원어 확인이 남거나 증거가 바뀐 결과는 이 보존 예외에 들어가지 않는다. 기존 SRT 저장 정보도 렌더링 바이트의 SHA-256이 일치할 때만 유지하며 새 파일 쓰기는 하지 않는다.
- 최신 요청의 실패·오류·진단과 자동 대기열의 중지 조건은 보존한다. 서비스 거절·인증·사용량·시간 초과·연결 오류를 자동 재요청하지 않는다. 성공한 번역에서만 정확한 프로그램 생성 실패 문구 두 종류를 정리하며, 사용자 메모와 원어 품질 경고는 유지한다.
- `N/N`이어도 최종 번역 검수나 원어 확인이 남았다면 별도로 표시한다. 기존 완성 번역을 보존한 최근 재번역 실패를 미번역으로 다시 계산하지 않는다. SRT 저장 실패를 녹색 완료 배지로 표시하지 않는다.

## 검사

- 전체 Node 검사 **1,238개 통과**, 실패·취소·생략 0개, 63.70초. `artifacts/test-v1914-full.log`.
- 최종 상태 배지·복구 가능 여부 변경 후 관련 UI **209개 통과**, 1.09초. `artifacts/test-v1914-ui-final.log`.
- 신규 UI 15개, 파일 충돌 21개, 완성 결과 보존 22개를 추가했다. 기존 저장 관련 검사와 함께 104개, 보존·서비스·복구·자동 대기열 회귀도 통과했다.
- 합성 완료 16개 결과에서 기본 복구 버튼이 없고 추가 작업이 닫혀 있는지 검사했다. 실제 미번역, 요약 누락, 원어 확인 필요, 요약·전체 응답의 저장 오류, 최종 검수 미완료, 진행 중 작업, 보존된 완성 번역의 최신 실패도 구분했다.
- 브라우저 합성 예시의 **2,000/2,000 완료**, **200/2,000 미완료**, **129/129 번역 완료·파일 저장 실패**를 확인했다. 1280px에서 목록 가로 넘침이 없으며 완료 결과의 기본 복구 버튼이 보이지 않는다. 화면: `artifacts/completed-actions-v1914.png`. 시험 탭과 서버를 정리했다.

## 실행 파일

- Windows EXE 빌드 성공. **99,490,798바이트**, SHA-256 `1cd90151b2e8d7cad8488cc118bc2c4fa087beace55118e1045a4268a8c44f3b`. 업데이트 manifest와 일치한다. 기존 `open/xdg-open` 경고는 Windows에서 사용하지 않는 Linux 보조 파일에 관한 것이다.
- 별도 EXE에서 최신 HTML·JS·CSS 해시와 목록 개수·상세 응답을 확인했다. 실제 폴더 이름 충돌을 보존한 부분 SRT 저장, 번역 전용 복구, 원래 시각·기존 완성 자막·분석 메타데이터·기록·대기열·진단·거절 중지 조건을 검증했다. `artifacts/package-v1914.log`.
- 별도 EXE·PowerShell 도우미로 **1.9.13→1.9.14 업데이트 인계**와 의도적으로 새 프로세스를 실패시킨 **1.9.13 복원**을 모두 통과했다(전체 92.22초). 각 시나리오에서 연결 설정·결과·SRT·대기열 등 8개 파일의 바이트를 보존하고 직접 생성한 시험 프로세스를 정리했다. `artifacts/update-handoff-v1914.log`.

이 검사는 실제 사용자 영상의 자막 복구 완료나 16개 결과 전체의 품질 확인을 의미하지 않는다. 서버 중지·재실행이나 운영 업데이트를 수행하지 않았다. 새 코드는 새 버전으로 실행한 뒤 적용된다.
