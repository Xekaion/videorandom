# 일본어 자막 누락 보완 검증 · 1.6.1

2026-10-16. 영상 플레이어에서 일본어가 들리는데 한국어 자막이 비는 현상을 대상으로, 음성 인식·번역·LAN 전송·플레이어용 파일 갱신을 각각 점검했습니다. 사용자 영상이나 저장된 실제 분석 내용은 검증에 사용하지 않았습니다.

## 코드와 모형으로 확인한 누락 경로

| 경로 | 재현 | 변경 |
| --- | --- | --- |
| 재인식 후보 선택 | 재인식 문장 중점은 검사 구간 밖이지만 마지막 실제 단어는 검사 구간 안에 있음 | 문장 중점 대신 실제 단어 시간과 검사 구간의 교집합으로 선택 |
| 기존 자막과 겹친 재인식 | 기존 문맥과 새 단어가 같은 재인식 문장에 들어가면 문장 전체를 버림 | 기존 단어를 보존하면서 중복되지 않는 새 단어를 반영. 시간 정렬이 없는 원문을 추정 분할하지 않음 |
| 단어 시간 역전 | 문장 자막은 4초에 끝나는데 잘못 정렬된 단어가 8초까지 덮어 누락 검사와 모순 | 실제 문장 구간 시간으로 보존하고 단어 정렬 제한 안내 |
| 부분 한국어 번역 | 원어 한 구간이 미해결이면 이미 인식된 모든 대사의 한국어 번역까지 막힘 | 인식된 유효 대사는 검수 후 부분 번역으로 표시·수동 저장. 미해결 구간은 그대로 안내 |
| 감지 언어 불일치 | 감지 메타데이터가 한국어이면 일본어 본문도 한국어로 복사 | 본문도 한국어 자막 기준을 통과해야 복사. 불일치하면 실제 본문을 번역 |
| 긴 영상 전송 | 2시간·2,400구간·단어진단 포함 약 4.57MB에서 원문 뒤 9분 42초가 잘리고 한국어 배열이 전부 제외됨 | 같은 시간별 원문·한국어 핵심 내용은 약 0.49MB. 단어별 진단을 먼저 줄여 전체 대사와 시간 보존 |
| 플레이어의 이전 SRT | 재분석 SRT가 별도 이름으로 생기고 플레이어는 이전 `.ko.srt`를 계속 읽음 | 저장 이력의 경로·SHA256과 현재 파일이 일치하는 프로그램 생성물만 `.bak` 보존 후 같은 이름 갱신 |

부분 자막은 원문 전체의 SHA256, 구간 수, 대사 ID, 시작·종료 시각과 대조합니다. 검수에 실패한 현재 번역 초안은 노출하지 않고 검수된 앞부분만 보존합니다. 부분 SRT/VTT는 명시적으로 선택한 수동 저장만 허용하며, 완성된 플레이어용 자막을 자동 교체하지 않습니다. 단어 진단을 줄인 사실은 경고로 남기며, 순수 원문과 한국어 내용 자체가 응답의 4MiB 제한을 넘으면 부분 결과와 오류를 표시합니다. 50,000구간 초과 자료를 업로드 전에 잘라서 전체 인식 완료로 인정하지 않습니다.

## 적용과 재검증

음성 인식 결과의 `recognitionRevision: 2`와 서버 기능 `subtitle-quality-v2`로 이번 변경 적용 여부를 구분합니다. 예전 결과는 계속 열 수 있지만 정확도 우선 복구에서는 이전 원어 인식 기록을 그대로 재사용하지 않습니다. 양쪽 PC에서 1.6.1 이상 실행 파일을 실행해야 하며, 새 실행 파일을 내려받아도 이미 실행 중인 구버전 서버가 바뀌지는 않습니다. 연결 주소·연결 코드는 기존 사용자 데이터에서 유지됩니다.

이전에 생성한 기본 SRT는 새 완성본 저장 때 이전 바이트를 `.bak`으로 보존합니다. 수동 작성·수정한 파일은 해시가 일치하지 않으므로 덮지 않습니다. 동시 변경·쓰기 실패·취소 때도 기존 자막과 백업을 보존하는 회귀를 포함합니다. 플레이어가 자막을 메모리에 읽어 둔 경우에는 자막을 다시 불러오거나 영상을 다시 열어야 합니다. 별도 파일명으로 저장한 자막은 상세 화면에 표시된 경로를 플레이어에서 직접 선택해야 합니다.

이 문서는 작은 공개 음성 회귀와 모형으로 확인한 결함을 구분합니다. 이전 버전의 [10사례 CER 비교](subtitle-quality-validation.md)는 1.5.1과 1.6.0의 비교이며 이번 변경의 추가 개선 수치로 재사용하지 않습니다. 원본 녹음의 단어별 정답 시각은 없으므로 새 신경망 정렬 시각을 정답 시간으로 간주하지 않습니다. 조용한 말·다중 화자·음악·방언·긴 영화의 모든 대사가 정확하다는 보증은 제공하지 않습니다.

## 실음성 시험의 해석

공개 Google FLEURS 일본어 원문과, 큰 발화 뒤 진폭 3%·1%·0.3%의 발화를 이어 붙인 사례를 1.6.0과 대조했습니다. 같은 원문을 동일하게 인식한 경우가 있어 이를 이번 수정의 추가 정확도 향상 수치로 제시하지 않습니다. 중간 논리 수정판의 탐색 결과와 최종 소스의 고정 회귀는 소스 해시로 구분합니다.

약 0.4초짜리 단어 조각의 반복·조용한 삽입도 시험했습니다. 이 자료는 신경망의 단어 경계를 기준으로 잘라 만든 스트레스 조각이므로 완전한 자연 단답의 정답 자료로 취급하지 않습니다. 단독 조각을 짧은 문맥으로 다시 인식하자 낮은 신뢰도의 다른 말이나 긴 잘못된 문장이 나오기도 했습니다. 해당 결과를 자동으로 채택하는 추가 재인식은 도입하지 않았습니다. 모르는 대사를 채워 넣어 누락이 해결된 것처럼 보이지 않게 합니다.

이를 보완하기 위해 같은 공개 일본어 test split 650행에서 자르지 않은 전체 길이가 가장 짧고 서로 다른 문장 3개(row 118 / id 1731 / 6.36초, row 50 / id 1978 / 6.42초, row 605 / id 1679 / 6.48초)를 추출했습니다. 2~6초 원본은 없었습니다. 원본 WAV 바이트·행 번호·정답 원문·출처·라이선스·SHA256을 fixture manifest에 기록합니다. 사용자 영상이나 파일 경로는 포함하지 않습니다.

새 `scripts/benchmark_subtitle_coverage.py`는 명시적으로 지정한 로컬 manifest의 전후 소스를 고정 복사하고 실제 CLI를 실행합니다. 모델 객체만 재사용하며 원문, 모델·소스·음원 해시, JSONL, 문자 삭제·삽입·치환, 블록별 단어 시간, 정렬이 없는 구간의 시간 불확실성, 캡션 중첩을 별도로 기록합니다. 블록 정답 시각이 없는 원본 문장은 시간 정확도 수치로 평가하지 않습니다.

최종 소스 `0f7e19233912bf29f899b7dab9ed6b17111cbad2f34b297856bb5efcf6d5b9f4`를 고정해 10사례를 전후 각 1회, 총 20회 실제 추론했습니다. 자연 전체 문장 3개·자연 문장 음량 혼합 1개·단어 조각 문맥 시험 1개·비발화 대조 1개·기존 일본어/중국어 작은 소리·창 경계 4개입니다. 전후 각 사례의 삭제·삽입·치환 수는 동일했으며, 캡션 중첩과 캡션 밖 단어 시간은 0건입니다. 자연 문장 세 개와 혼합한 73자는 누락·삽입이 없었고, 자연 원본 한 문장의 동음 한자 1치환은 양쪽에 남았습니다. 일본어 두 기존 스트레스 사례는 각각 91자 중 삭제 1·치환 2, 중국어 두 사례는 각각 치환 1이 남았습니다. 이 자료로 이번 변경이 신경망 자체의 실인식률을 높였다고 주장하지 않습니다.

이 검증 과정에서 새 필터가 발화 검출 시작보다 앞에 있는 첫 단어를 잘라내는 회귀를 찾아 수정했습니다. 원래 문장 중점 기준으로 보존하던 실제 문장은 계속 보존하고, 중점 밖에 있는 새 단어만 추가로 구제하도록 고쳤습니다. 최종 고정 소스의 동일 10사례 재실행에서 해당 회귀가 해소됐습니다. 실행 도중 소스가 바뀌지 않았음을 메타데이터로 확인했습니다.

짧게 자른 단어 조각은 최종판에서도 발화 검출과 인식이 함께 놓칠 수 있었으며, 누락 점검이 완료된 결과에서도 발생했습니다. 완료 표시는 전체 음성을 처리하고 검출된 발화와 대조했다는 뜻이며 모든 실제 발화를 찾았다는 증명은 아닙니다. 자연 전체 문장에서도 일부 신경망 단어 시간과 검출 경계에 차이가 남아 미해결로 표시됐습니다. 이 시간 차이를 임의로 늘려 없애지 않았습니다.

Node 회귀 271개와 Python 회귀 64개를 통과했습니다. 이번 릴리스에서 검증한 처리 개선은 위의 재현 가능한 누락·전송·파일 갱신 오류 수정이며, 모형 시험과 실제 음성 비교의 근거를 구분합니다.
