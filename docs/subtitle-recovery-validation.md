# 부분 자막 저장과 긴 영상 재검수 검증 · 1.6.6

2026-10-16. 검수된 한국어 자막이 있어도 원문 인식의 불확실성이 남으면 영상 폴더에 SRT가 생기지 않던 문제를 수정했습니다. 사용자 영상·저장된 실제 대사·이미지는 열지 않았습니다. 아래에서 코드로 재현한 결함과 공개 음성의 실제 인식 결과를 구분합니다.

## 확인한 원인과 변경

| 원인 | 변경과 확인 |
| --- | --- |
| 자동 저장이 완성본만 허용 | 검수된 한국어 부분 자막도 `<영상명>.ko.partial.srt`로 저장. 완성본은 기존 `<영상명>.ko.srt` 사용 |
| 전체 음성을 처음 인식한 뒤 추가로 불확실 구간을 다시 듣는 작업에 고정 600초 총량 제한 | 영상 뒤쪽까지 모든 재검수 대상을 고려. 실제 재생한 샘플 수로 추가 작업을 계산하고 영상 길이의 1.2배 이내로 제한 |
| 기존 단어 확률이 0.95이면 새 단어 확률에 0.1 향상을 요구하는 비교로는 정상 복구를 인정할 수 없음 | 원문이 같고 실제 단어 시간이 유효하며 기존 저신뢰 판정을 통과한 재인식으로 확인. 원래 저신뢰 기준은 유지 |
| 기존 6초 문장이 정상적인 3초 문장 두 개로 나뉘면 각 문장의 겹침만 비교해 둘 다 거절 | 실제 단어와 합산한 겹침으로 같은 대사의 분할 복구를 확인. 주변의 확정된 대사에 침범하는 후보는 거절 |
| 재검수 창 경계의 단어를 자를 수 있음 | 30초 검사 창 내부 경계에 앞뒤 3초 문맥을 포함하고 실제 단어의 중점으로 담당 창을 결정. 중복 제거 후 한 번 반영 |
| 원문 전체 처리, 불확실성 검사, 한국어 번역 검수가 같은 실패 안내에 섞임 | 세 상태를 별도로 전송·표시. 원문에 불확실성이 남아도 인식한 대사의 번역 검수가 끝났으면 번역 실패라고 표시하지 않음 |
| 미해결 진단을 200개 예시로 제한해 실제 총계와 달라짐 | `unresolvedCount`, `unresolvedByReason`, `unresolvedTruncated`를 추가해 실제 총계와 예시 수 구분 |

600초는 첫 전체 음성 인식의 길이 제한이 아니라 **추가 재검수의 총량 제한**이었습니다. 진단 예시 200개 제한 자체가 분석 실패 원인은 아니었습니다. 발화 양끝의 짧은 시간 차이나 단어별 정렬을 얻지 못해 유효한 문장 시간을 유지한 대사는 별도 진단이며, 이것만으로 자막 완료를 막지 않습니다.

## 저장과 기존 기록

한국어 부분 자막은 원문 전체의 SHA256, 대사 ID·개수·시작·종료 시각과 대조한 검수 결과만 사용합니다. 임의의 대사나 시간을 만들지 않습니다. 검수된 대사가 없거나 검증에 실패하면 빈 SRT를 만들지 않습니다.

분석을 실행한 클라이언트 PC가 원본 영상 폴더에 저장합니다. LAN 분석 서버는 업로드 임시 폴더에 원본용 자막을 쓰지 않습니다. 기존 완성본과 수동 수정 파일은 보존합니다. 프로그램 생성 이력의 경로와 SHA256이 현재 파일과 일치할 때만 이전 바이트를 `.bak`으로 보존하고 같은 종류의 기본 파일을 갱신합니다. 부분 자막은 완성 자막을 대체하지 않습니다. 재생 중인 플레이어에서는 새 파일을 직접 불러오거나 영상을 다시 열어야 할 수 있습니다.

기존 결과는 상세 화면의 **영상 폴더에 저장**으로 새 음성 인식·요약·번역 요청 없이 내보낼 수 있습니다. 새 `POST /api/analysis/results/:id/subtitles/save`는 저장된 기록의 원본 경로만 사용하고 요청에서 임의 경로를 받지 않습니다. 같은 영상이 분석 중이면 저장을 거절하며 쓰기 실패 사유를 화면과 기록에 남깁니다. 화면은 파일 저장 성공·기존 동일 파일·쓰기 실패를 구분합니다.

분석 중지 전 이미 검수된 대사는 최종 기록 보관 단계에서 저장합니다. 이때 새 음성 인식이나 번역을 실행하지 않습니다. 저장 도중 새 취소 신호를 받으면 파일 쓰기의 기존 취소 처리를 유지합니다.

## 완료 판정과 이전 결과 보존

`processingComplete`는 정확 모드에서 전체 샘플의 첫 인식을 마쳤음을 나타냅니다. 불확실성 검사의 `audit.complete`와 한국어 검수의 `translationComplete`는 별개입니다. 실제로 미해결 구간이 있으면 전체 자막을 완성본으로 표시하지 않습니다. 부분 자막 저장을 위해 이 기준을 낮추지 않았습니다.

새 인식이 중간 실패한 경우, 이전에 전체 음성을 처리했던 원문·시간·감지 언어를 짧은 실패 결과로 덮지 않습니다. 정확도 우선 복구에서 이전 인식 기록을 그대로 재사용할지는 더 엄격한 전체 검수 완료 증거와 최신 인식 버전으로 판단합니다. 전체 처리 사실만으로 재검수를 건너뛰지 않습니다.

음성 처리 버전은 `recognitionRevision: 3`, LAN 기능은 `subtitle-quality-v3`입니다. 새 재검수는 양쪽 PC에서 1.6.6 이상을 실행해야 적용됩니다. 파일을 내려받거나 교체해도 실행 중인 이전 서버는 자동 교체되지 않습니다. 사용자 데이터에 있는 연결 주소·연결 코드는 유지합니다.

## 자동 회귀와 화면·실행 파일 확인

최종 소스로 Node 회귀 313개와 Python 회귀 77개를 통과했습니다. Node 전체 회귀에는 Python 시험을 실행하는 래퍼도 포함됩니다.

* 54분 길이와 324개 재검수 대상을 모형으로 재현해 3,235초 이후까지 검사하는 것을 확인했습니다. 정상 재인식이 반환되는 모형에서 기존 저신뢰 표시가 해소됩니다.
* 0.25초부터 2시간까지 검사 범위·실제 추가 샘플 예산을 확인했습니다. 60초 입력의 29.8–30.2초 경계 단어는 0–33초와 27–60초를 실제로 재생하는 총 66초 추가 작업으로 한 번만 복구합니다.
* 실제로 불확실한 303개 모형 구간은 미완료로 남습니다. 총계 303개와 진단 예시 200개를 구분합니다.
* 부분 파일명, 원래 시간, 원문 지문, 기존 완성본·수동 수정 보존, 백업, 중지·쓰기 실패·재실행, LAN 결과의 클라이언트 저장을 확인했습니다.
* 합성한 일반 안내 대사로 화면의 **영상 폴더에 저장**을 실제 호출해 `.ko.partial.srt`가 생성되고 두 대사의 원래 시간이 유지되는 것을 확인했습니다. 완성본 파일은 생성하지 않았습니다.
* 빌드한 1.6.6 EXE를 별도 테스트 데이터로 실행해 버전과 HTML·JS·CSS 바이트가 최종 소스와 일치함을 확인했습니다. 이 시험에서 운영 분석 서버를 변경하지 않았습니다.

모형 결과는 실제 54분 영상의 인식률 개선 수치가 아닙니다. 사용자가 보고한 특정 영상의 미해결 303개가 모두 해소됐다고 판정하지 않았습니다.

## 공개 음성으로 실제 인식 비교

캐시에 있는 Google FLEURS의 일반 일본어·중국어 음성 4사례를 사용했습니다. 출처는 [Google FLEURS](https://huggingface.co/datasets/google/fleurs), 라이선스는 CC BY 4.0이며 원본 행·데이터셋 revision·음원 SHA256·가공 방법은 로컬 fixture manifest에 기록돼 있습니다. 자연 일본어 문장은 자르지 않은 전체 원본이며 작은 소리·창 경계 사례는 같은 공개 음성으로 만든 스트레스 자료입니다. 이전 [누락 검증](subtitle-omission-validation.md)과 같은 fixture를 사용했습니다.

`large-v3`, CPU, `int8`, CPU 스레드 4개로 실행했습니다. 모델 객체만 재사용하고 각 소스의 실제 CLI 인식·재검수 경로를 실행합니다. 1.6.5 기준 소스의 비교 전 결과와 최종 소스의 비교 후 결과를 사례별로 연결해 음원 SHA256, 모델·장치·연산 형식이 일치하는 것을 확인했습니다.

| 사례 | 정답 문자 수 | 전: 삭제 / 삽입 / 치환 | 후: 삭제 / 삽입 / 치환 | 전·후 불확실성 검사 |
| --- | ---: | --- | --- | --- |
| 일본어 자연 전체 문장 row 118 | 21 | 0 / 0 / 1 | 0 / 0 / 1 | 미해결 1구간 유지 |
| 일본어 자연 문장 음량 혼합 | 73 | 0 / 0 / 0 | 0 / 0 / 0 | 미해결 1구간 유지 |
| 중국어 큰 말 뒤 작은 말 | 44 | 0 / 0 / 1 | 0 / 0 / 1 | 완료 |
| 중국어 창 경계 | 44 | 0 / 0 / 1 | 0 / 0 / 1 | 완료 |

최종판의 캡션 중첩과 캡션 밖 단어 시각은 모두 0건입니다. 전체 샘플 처리는 네 사례 모두 완료했습니다. 일본어 원본의 1.05초 VAD 꼬리와 혼합 자료의 약 0.906초 미해결 영역은 남았으며, 자막 시간을 임의로 늘려 완료로 만들지 않았습니다. 이 비교에서는 문자 인식률의 추가 개선이 관측되지 않았습니다. 이번에 확인한 개선은 재현 가능한 재검수 결함과 파일 보관·상태 표시의 수정입니다.

### 소스 고정과 재현

* 비교 전 Python SHA256: `0f7e19233912bf29f899b7dab9ed6b17111cbad2f34b297856bb5efcf6d5b9f4`
* 최종 Python SHA256: `10073c0a32aa7670cc7ef77b36f702dbb121d0cb64a8b7e4b8801f109aaa65dc`
* manifest SHA256: `caf692213d9bc3b59e8b0c15011f55cfbdab107078a5fe8ec8f79d337850fd65`
* 최종 비교기 SHA256: `dd05d424ec0b4a99a910d62a5499c77561bcb5feefbd720fcba059356e2ec735`

최종 비교 후 실행 중 소스가 바뀌지 않았음을 메타데이터로 확인했습니다. 개발 중간판 결과는 최종 비교 후 수치로 사용하지 않았습니다. 비교 전 소스와 음원이 같으므로 이미 완료된 비교 전 실행을 다시 반복하지 않았습니다. 이전 비교기 메타데이터에 장치 옵션이 없어서 해당 실행의 최종 quality에 기록된 CPU·int8·모델을 대조했습니다.

fixture 음원과 로컬 결과는 저장소에 포함하지 않습니다. 출처와 해시가 같은 manifest·음원을 준비한 뒤 다음 명령으로 전후를 실행할 수 있습니다. `--variant after`를 추가하면 동일 기준선의 재실행 없이 비교 후만 실행합니다.

```powershell
python scripts/benchmark_subtitle_coverage.py `
  --baseline baseline-transcribe_local.py `
  --source scripts/transcribe_local.py `
  --manifest final-manifest.json `
  --case ja-natural-full-row-118 --case ja-natural-mixed-volume `
  --case zh-quiet-after-loud --case zh-window-boundary `
  --cache MODEL_CACHE --device cpu --compute-type int8 --cpu-threads 4 `
  --output benchmark-results
```

이 검증은 실제 사용자 영상, 다른 PC의 실행 상태, 모든 실제 발화의 검출·번역 정확도를 확인한 결과는 아닙니다. 불확실성이 남으면 그 사실을 알리고 검수된 자막을 보관합니다.
