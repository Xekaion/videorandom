# 1.9.36 · 자막 요청 시간 초과 복구와 부분 SRT 저장

2026-11-08. v1.9.35 양쪽 환경에서 NHDTB-275의 자막 복구가 같은 초안 81–160구간에서 두 차례 끝났다. 최신 실패(18:08 KST)는 요청 시작 이후 후속 활동이 관측되지 않은 앱 자체 제한(180.041초)이다. 프로세스 종료를 확인했고 1,321구간 중 기존 80구간은 유지했다. 기술 로그에는 서버 측 지연의 세부 원인이 없었다. 별도로 클라이언트의 부분 SRT가 첫 후보의 `publish-link`에서 `EISDIR`로 저장되지 않았다. 사용자 미디어나 응답 본문은 검사하지 않았다.

## 동작

- 앱 타이머가 만든 정확한 오류 객체만 후보가 된다. 도구 종료, 제한 범위, 시간, 최종 분류를 확인한 뒤 다른 실패 증거가 없는 경우에만 구간을 나눌 수 있다. 도구 종료 미확인, 제공자 오류, 혼잡 재시도 이후 오류, 인증·사용량·거절·저장 오류와 취소는 기존대로 처리한다.
- 해당 초안·검수의 최초 묶음은 최대 20구간이고 원래보다 작은 단위로, 기존 보완에서 실패한 묶음은 한 번만 반으로 나눈다. 한 구간이 만료되면 같은 요청을 재전송하지 않는다. 추가 요청은 영상당 최대 8회(기존 64회 보완 한도에도 포함), 최대 60초이며, 같은 단계에서 작은 요청 두 개가 만료되면 추가 소분을 멈춘다.
- 앞서 검증된 원래 자막 시간과 번호를 유지하고 뒤쪽 구간을 방문한다. 정확 모드의 초안을 최종 자막으로 승격하지 않는다. 응답이 없던 구간은 가짜 자막으로 채우지 않고, 끝까지 처리했다면 미완료 번호를 표시하며 다음 복구에서는 그 번호만 요청한다. 연속 두 독립 묶음 모두 시간 초과가 발생하고 새 확정 자막이 없으면, 반복 대기 대신 해당 영상의 진행을 보존하고 다른 대기 영상으로 넘어갈 수 있다.
- 먼저 시작한 다음 초안의 타임아웃은 현재 검수를 취소하지 않는다. 시간 초과 뒤 새 요청을 보내기 전에 진행 중인 형제 요청의 결과를 확인해 진짜 서비스 오류를 숨기지 않는다.
- 부분 SRT는 `publish-link`의 `EISDIR`에서 원본과 임시 파일을 다시 확인한 뒤 제한된 후보의 독점 생성으로 대체 저장한다. 기존 폴더나 자막은 덮어쓰지 않으며, 복사 실패나 저장 장치 오류는 숨기지 않는다.

## 검증

- 실제 서비스 대신 소유한 모의 프로세스로 초안·검수·누락 보완의 시간 초과, 작은 요청과 뒤쪽 구간 처리, 정확한 자막 ID·시간과 다음 실행의 미완료 복구, 요청 한도, 늦게 드러난 인증 실패 우선 처리를 검증한다.
- 임시 테스트 폴더에서 첫 후보 `publish-link`의 `EISDIR`, 대체 이름 저장, 경쟁 중 생성된 사용자 파일과 폴더 보존, 실제 복사·용량·권한 오류를 검증한다. 실제 영상 분석, 번역 서비스 호출, 운영 프로그램 재실행은 하지 않는다.
