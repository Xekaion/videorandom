# 1.9.29 · 원문부터 다시 분석과 최신 원문 선택

2026-10-27. 기존 ‘다시 분석’은 저장된 원문·장면을 재사용하는 복구 경로였으며, 전체 음성 재인식을 보장하지 않았다. 원문 자체가 부족한 영상에서 같은 버튼을 눌러도 구간 수가 그대로일 수 있었다. 새 원문을 확보한 결과가 일부 완료 상태이면 예전 완료 결과의 표시 순위에 가려지는 별도 문제도 있었다.

이 검증은 코드와 중립 합성 자료만 사용한다. 실제 영상·음성·대사·요약·제공자 원시 응답을 열거나 실제 ASR·GPU·번역·운영 작업을 실행하지 않는다. 사용자가 지목한 영상의 실제 새 원문 개수를 확인하거나 재분석을 완료했다는 뜻은 아니다.

## 버튼의 계약

- **원문부터 다시 분석**: 비로컬 분석의 직접 복구, 대기 복구, 프로그램 재시작 후 복구와 중단 작업 재개에서 `transcribeAudio:true`를 강제한다. 기존 체크박스가 꺼져 있어도 전체 음성을 새로 인식한다. 설정한 언어·빠름/정확/초고속 모드와 모델은 유지한다.
- **한국어 자막 다시 번역**: 보관된 원문·시간·구간 수로 한국어 번역만 처리한다. `transcribeAudio:false`이며 음성 인식·장면 추출을 다시 실행하지 않는다.
- **로컬 추출**: 음성 인식 서비스가 아닌 기존 장면·외부/내장 자막 추출 방식으로 유지한다. 전체 원어 음성 인식에는 이 PC 분석 또는 분석 서버 방식을 사용한다.

‘한국어 100/1,200구간’은 원문 1,200개 가운데 번역 100개를 보관했다는 뜻이다. 이 경우 번역 복구를 선택할 수 있다. 원문 전체가 100구간으로 인식돼 부족한 경우에는 원문부터 다시 분석해야 한다. 영상 길이만으로 원문이 반드시 1,000구간 이상이라고 정하거나 대사를 임의로 나누어 늘리지 않는다.

## 변경한 경계

1. 분석 서비스의 작업 생성 경계에서 전체 재인식 의도를 강제한다. 새 대기 기록은 이를 저장하며, 예전 버전의 `transcribeAudio:false` 복구 대기 기록도 실제 실행·재개 시 전체 재인식으로 올린다. 번역 전용과 접수 결과 읽기는 재인식 대상이 아니다.
2. 전체 재인식은 추출 캐시를 우회하고 추출기에 내부 `skipExistingSubtitles:true`를 전달한다. 외부·내장 자막을 읽어 이전의 짧은 원문이나 한국어 자막으로 새 원문을 시작하지 않는다. 엔진은 이전 원문·언어·음성 품질·캐시 연결도 정리한 뒤 새 음성 인식으로 넘긴다.
3. 이 PC 분석은 원본 영상에서 음성을 새로 준비하고, 원격 분석은 전체 음성 파일을 서버에 보낸다. 기존 LAN 전체 음성 인식 설정을 사용하므로 새로운 서버 전송 명령이나 API 키가 필요하지 않다. 실제 새 인식이 실패하면 옛 100구간을 새 인식의 성공 결과처럼 반환하지 않는다. 이전 결과 파일은 그대로 보존한다.
4. `sourceReanalysis:true`는 서비스가 만든 전체 재인식 **작업 의도** 메타데이터다. 음성 인식 완료나 구간의 정확도를 인증하는 값이 아니다. 원격 접수 기록에도 엄격한 boolean만 보관하며, 재실행 뒤 같은 서버 결과만 읽어도 원래 복구 관계와 표시 의도를 유지한다. 제공자 응답이 임의로 이 표시를 승인할 수 없다.
5. 목록은 이 표시·같은 영상의 복구 관계·유효한 새 원문·최신 시각을 확인해 최신 원문을 선택한다. 예전 요약이 완료 상태라는 이유만으로 새 1,200구간 원문 대신 옛 100구간을 계속 보여주지 않는다. 원문 0인 실패는 이전의 사용 가능한 결과를 가리지 않는다. 번역 후속 작업, 역순 응답, 목록의 압축 응답과 상세 로딩에서도 같은 선택을 유지한다.
6. 화면의 두 버튼·설명을 구분한다. 번역 버튼은 현재 보관 원문 N구간을 그대로 쓴다고 알린다. 기존 결과·자막·주소·연결 코드는 보존한다.

Python의 모델 캐시는 모델 파일 저장소다. 현재 원문 음성 체크포인트는 기록용이며 이전 구간을 읽어 이어 쓰는 경로는 없다. 이번 변경은 모델 다운로드 캐시나 호환되는 한국어 번역 체크포인트를 삭제하지 않는다. 번역 체크포인트는 원문 ID·시간·텍스트 지문과 개수가 일치해야 재사용된다.

## 검증

신규 서비스 19개, 엔진·추출 15개와 UI 27개는 다음을 검증한다.

- 완료된 옛 100구간 입력이 있어도 Codex·LAN 재분석에 전체 재인식 설정을 전달하고 새 합성 1,200구간을 목록·상세·파일에 보존한다.
- 직접 실행·대기·예전 대기 기록·재실행·중단 복구에서도 계약이 유지되며 번역 전용의 원문 100구간과 원래 시각은 그대로다.
- 외부/내장 자막은 강제 재인식에서 읽지 않고 보통의 로컬 추출에서는 기존 방식대로 읽는다. 빠름·정확·초고속 경로 모두 기존 원문을 새 인식의 대체물로 쓰지 않는다.
- 이전 결과 바이트를 보존한다. 원격 접수 후 재시작은 새 분석·음성 인식·번역 요청 없이 기존 작업 결과만 읽으며 원래 복구 관계와 새 구간 수를 유지한다.
- 최신 원문과 번역 후속 결과의 여섯 로딩 순서, 별도 진행 조회, 압축 목록·상세 전환, 잘못된 복구 관계와 원문 0인 실패를 확인한다.

- 최종 전체 Node 검사 **2,665개 중 2,664개 통과**, 실패·취소 0개, **103.71초**. Windows 심볼릭 링크 생성 권한이 필요한 기존 검사 1개만 생략했다. `artifacts/test-v1929-final.log`.
- 신규 61개 검사를 전체 검사에 포함했다. 실제 영상의 구간 수·인식 품질·번역 완료 여부나 처리 속도를 이 합성 검사로 인증하지 않는다.
- Windows EXE 빌드와 업데이트 manifest 검증 통과. **99,701,459바이트**, SHA-256 `e47686f308f84711f0a58320e992464139d54a93e7b985c743d88275739c08fb`. 기존 Windows 미사용 `open/xdg-open` 경고만 남았다. `artifacts/build-v1929.log`.
- 최종 EXE를 별도 저장소와 소유한 시험 포트에서 실행해 새 버튼 자산, 목록·상세의 전체 재인식 메타데이터, 정확한 구간 수, 한국어 자막 전용 복구·원래 시간·부분 SRT 자동 저장·기존 자막과 사용자 일시 중지를 검증했다. 실제 ASR·제공자 호출 없이 통과했다. `artifacts/package-v1929.log`.
- 실제 Windows EXE·PowerShell 도우미로 **1.9.28→1.9.29 업데이트**와 의도적 새 실행 실패 시 **1.9.28 복원**을 모두 통과했다(전체 **99.92초**). 설정·결과·자막·대기열·진단·접수 기록 등 **11개 시험 파일의 바이트를 보존**했으며 소유한 시험 프로세스만 사용했다. `artifacts/update-handoff-v1929.log`.

목록과 대기열을 사용하는 PC를 1.9.29로 실행해야 새 요청과 표시가 적용된다. 서버에는 기존 전체 음성 인식 요청을 사용한다. 이미 실행 중인 구버전이 파일 교체만으로 새 코드로 바뀌는 것은 아니다.
