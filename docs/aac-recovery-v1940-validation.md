# 1.9.40 · AAC 채널 손상 복구와 대기열

2026-11-15. ATID-099의 2026-11-15 00:21:34(KST) 클라이언트 로그는 음성 준비 단계, 원문 0개, `DIAGNOSTIC_UNKNOWN`이었다. 영상 PC의 실행 버전은 1.9.38이었다. 사용자가 제공한 화면에서 AAC 디코더의 `Reserved bit set`, `invalid band type`, `Prediction is not allowed in AAC-LC`와 `Rematrix is needed between 32 channels and mono`, 필터 재초기화 실패를 확인했다. 서버에 업로드해 음성을 인식하기 전의 로컬 음성 추출 실패다. 원본 파일의 바이트·오디오 또는 손상의 시작 시점은 직접 확인하지 않았다.

기존 코드는 FFmpeg 종료 실패를 코드 없는 Error로 만들었고, 공유 진단에서는 원문을 제거해 원인을 잃었다. 전체 stderr를 붙인 오류 문구는 대기열의 기존 단일 행 `Invalid data found when processing input`과 일치하지 않아 공유 환경 문제로 멈췄다.

## 수정

- FFmpeg 실패를 고정된 기술 코드로 보관한다. 원시 stderr는 로컬 오류·경고에만 남기며 공유 진단에는 고정 문구를 쓴다. 저장 공간과 권한은 기존 시스템 코드로 구분한다.
- 실제 관측된 AAC + 비정상 채널 모노 변환 + 필터 중단 조합에만 재시도한다. 건강한 첫 시도는 그대로다. 재시도는 최대 한 번이며 첫 시도의 남은 시간만 사용한다. 저장·권한·사용자 취소·다른 형식 오류는 이 경로로 반복하지 않는다.
- 번들 FFmpeg 6.1.1에서 지원하는 입력 디코더 옵션 `-flags:a +drop_changed`를 사용한다. 출력은 `aresample=async=1:first_pts=0,apad=whole_dur=<원본 길이>`와 `-t <원본 길이>`로 시각 공백과 꼬리 길이를 유지한다. 건강한 PCM 입력·첫 시도 옵션·모델은 바꾸지 않는다. 비정상 프레임의 실제 대사를 복원하는 기능이 아니다.
- 복구 성공 시 경고를 보관하고 원문 완전성 및 누락 검사 완료를 false로 유지하며 `source_audio_damaged` 확인 항목을 남긴다. 번역을 완성본으로 인증하지 않는다. 동시 이미지·음성 준비에서도 경고를 최종 결과로 전달한다.
- 복구 실패 또는 트랙 누락은 저장된 해당 영상에만 한정한다. 다른 저장·서비스 오류가 있으면 그것이 우선하며 저장 확인 전에는 다음 작업을 진행하지 않는다. 이전 `UNKNOWN` 음성 단계 기록은 같은 결과에 정확한 FFmpeg 손상 문구가 함께 남은 경우에만 이 범위를 적용한다. 사용자 일시 중지를 자동 해제하지 않는다.

[FFmpeg 문서](https://ffmpeg.org/ffmpeg.html#Advanced-options)는 채널 정보 변경에 따른 필터 재초기화와 변경 프레임 제외를 설명한다. 새 CLI 옵션 `-drop_changed`를 구형 바이너리에 넣지 않고 번들 도구 도움말에서 확인한 디코더 flag를 사용했다. 해당 flag와 필터를 실제 번들 FFmpeg의 중립 sine 입력에서 실행해 옵션 호환을 확인했다.

검증에는 중립 가짜 도구·모델·소유한 임시 폴더와 프로세스를 사용한다. 실제 ATID-099의 복구 성공과 누락량은 아직 실측하지 않았다. 손상이 심하거나 처음부터 유효한 채널 정보가 없으면 복구할 수 없으며 정상 원본으로 교체해야 한다.
