# 1.9.23 · 자막 응답의 번호·대사 오류를 행별로 분리

2026-10-23. 문제 확인에는 기술 진단의 실행 버전·개수·단계·오류 코드만 사용했다. 사용자 영상·음성·대사·줄거리·번역 제공자 원시 응답을 읽거나 재처리하지 않았다. 검증에는 중립 합성 원문·가짜 제공자·별도 저장소를 사용하며 운영 서버·작업·설정은 변경하지 않는다.

## 원인

최근 한 분석은 요청 PC와 서버 모두 1.9.22였다. 원문 2,007구간 중 880구간을 저장한 뒤 881–960번 묶음의 번역 초안 검사에서 `SUBTITLE_BATCH_INVALID`로 중단됐다. 화면의 고정 오류 문구는 응답 한 행의 번호나 대사 형식 검사에 대응한다. 원시 응답을 열지 않았으므로 번호 누락·중복·빈 대사 등 어느 행 조건이었는지는 확정하지 않는다.

외부 응답의 번호·대사 검사와 정확 모드의 압축 검수 변환기가 한 행의 오류에도 예외를 발생시켜 묶음 전체와 이후 번역을 중단했다. 기존 응답 누락·외국어 분리 처리에는 이 예외가 도달하지 않았다.

## 수정

- 외부 번역·검수 응답은 요청 범위 안의 안전한 정수 번호를 명시한 행만 원문에 대응한다. 문자열·누락·소수·범위 밖 번호는 위치로 추정하거나 변환하지 않는다. 요청한 번호의 응답이 없으면 해당 원문만 기존 보완 대상으로 둔다.
- 같은 원문 번호가 두 번 이상 등장하면 내용이 같아도 해당 번호의 모든 후보를 제외한다. 정확 모드의 승인·수정 배열 사이 중복도 동일하다. 먼저 또는 마지막에 도착한 행을 임의로 선택하지 않는다.
- 알려진 번호의 빈 대사·문자열이 아닌 대사·길이 초과·금지된 대사 형식은 해당 행만 제외한다. 정상 이웃 대사는 보존하며 수정 요청에는 원래 원문과 번호를 사용한다. 위험한 응답 텍스트를 저장 자막으로 바꾸거나 원문 내용을 만들어 채우지 않는다.
- 분리한 문제는 `SUBTITLE_ROWS_INVALID` 경고로 남긴다. 최대 20구간씩 보완하고, 다시 빠진 번호는 기존 단일 구간 보완을 사용할 수 있다. 영상 전체가 공유하는 64회 요청 한도는 유지한다. 해결되지 않는 행이 있어도 다음 원문 묶음과 마지막 구간까지 처리한다.
- 정확 모드 초안은 독립 원문 대조 검수 없이 승인하지 않는다. 내부 최종 저장·체크포인트 검사는 엄격하게 유지한다. 전체 응답의 잘못된 JSON·최상위 구조·용어 오류, 실제 실행·인증·거절·사용량·연결·시간 초과 오류는 행 누락으로 바꾸거나 자동 재시도하지 않는다. 필터링 전에 모든 원시 대사 행의 거절 표시를 검사한다.
- 외부 응답의 절대 상한은 50,000행이다. 번역 체크포인트 계약은 버전 9이며 버전 3–8의 기존 결과는 원문 지문·프로필·검수 횟수·번호·시각을 확인해 재사용한다. 단순 버전 변경으로 기존 검수 대사를 버리지 않는다.
- 처리 완료와 자막 완성을 구분한다. 해결되지 않은 구간은 `N/M`·부분 SRT로 보관하고 뒤쪽 정상 자막을 유지한다. 해당 영상의 미완료만으로 다음 대기 영상을 중지하지 않는 기존 정책을 유지한다.

## 검증

- 최종 전체 Node 검사 **1,743개 통과**, 실패·취소·생략 0개, **68.29초**. `artifacts/test-v1923-final.log`.
- 새 행 오류 회귀 **90개**는 정확 모드 초안·전체/압축 검수·빠름·초고속에서 번호 누락·문자형·소수·범위 밖·중복·빈 대사·문자열이 아닌 대사·길이 초과·금지된 대사 형식을 검증한다. 합성 2,007구간에서 881번째 행에 지속 오류가 있어도 마지막 구간까지 검수·저장하고 다음 복구가 빈 원래 번호만 요청하는 것을 확인했다. 부분 SRT와 원래 ID·시각, 선행 처리 취소·재개, 빈 초안의 공통 보완 한도도 확인했다.
- 압축 검수 어댑터의 별도 회귀는 중복 승인·수정 충돌, 알려지지 않은 번호, 응답 상한, 내부 초안 오류, 신뢰된 메타데이터 위조 방지를 검사한다. 기존 회귀는 버전 8의 전체·부분 검수 캐시 재사용과 원문·번호·ID·시간·프로필·검수 횟수 불일치 거부를 확인했다. 거절 필드와 거절 대사가 동시에 있어도 기존 필드 출처를 우선한다.
- 독립 코드 검토에서 행별 분리가 원문 번호·시간 추정이나 검수 생략으로 이어지지 않는 것을 확인했다. 실제 실행·서비스 거절·인증·사용량·연결·시간 초과·최상위 구조·용어·내부 저장 검증의 중단 조건은 유지했다. 실제 제공자 호출이나 사용자 영상의 번역 완료를 뜻하지 않는다.
- Windows EXE 빌드와 manifest 확인 통과. **99,544,010바이트**, SHA-256 `24f4fe70e961d74990e615c020f5ce882647bcb2b17d86d519ff3fbf8dd37d33`. 기존 Windows 미사용 `open/xdg-open` 경고만 남았다. `artifacts/build-v1923.log`.
- 최종 EXE를 별도 저장소와 소유한 시험 포트에서 실행해 저장 결과·부분/완성 SRT·원래 시각·진단·실패 기록·대기열을 검증했다. 일반 구버전 미완료 응답 뒤에도 다음 독립 복구가 한 번만 실행되고 완성 SRT가 영상 옆에 저장됐다. 기존 완성 자막·사용자 중지·저장 파일·원래 분석 버전과 시간 기록도 유지했다. 실제 미디어 디코딩·ASR·번역 제공자 호출은 없었다. `artifacts/package-v1923.log`.

이 변경은 분석을 처리하는 PC의 코드이므로 분석 서버 방식에서는 서버도 1.9.23으로 실행해야 적용된다. 기존 결과가 자동 재번역되지는 않으며 업데이트 후 남은 자막 번역 복구에서 저장된 원문·기존 검수 대사를 이어 사용할 수 있다. 연결 주소·코드·저장 결과는 유지한다.
