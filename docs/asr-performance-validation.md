# 음성 인식 처리 개선 · 1.7.1

## 변경한 작업

기존 정확 모드는 같은 GPU에서 음성 구간을 한 개씩 처리했습니다. 이번 버전은 일반 `WhisperModel.transcribe()`를 그대로 사용하며 최대 두 구간을 동시에 실행합니다. 처음 인식의 90초 구간과 앞뒤 2초 문맥, 재검수의 30초 구간과 앞뒤 3초 문맥, 전체 음성 범위, 모델, beam 5, 온도 재시도, 단어별 시간 정렬, 누락 검수를 유지했습니다. 두 결과는 원본 순서대로 반영하며 대기 작업도 최대 두 개입니다.

일괄 처리용 `BatchedInferencePipeline`은 이번 기본 경로에 사용하지 않았습니다. 설치된 faster-whisper 1.2.1에서는 이 경로의 일부 신뢰도·무음·환각 처리 인수가 사용되지 않아 기존 정확 모드의 검수 정책을 그대로 보존할 수 없었습니다. 일반 모델의 동시 호출과 같은 GPU의 모델 가중치 공유는 [faster-whisper](https://github.com/SYSTRAN/faster-whisper)와 [CTranslate2 병렬 실행 문서](https://opennmt.net/CTranslate2/parallel.html)를 참고합니다. 병렬 호출의 실제 처리량 증가는 GPU와 입력에 따라 다릅니다.

자동 병렬 처리는 CUDA 장치 0을 확인할 수 있고, 로딩 전 전체 메모리 8GiB 이상·여유 메모리 6GiB 이상, 로딩·준비 실행 후 여유 메모리 2GiB 이상일 때 선택합니다. CPU, 장치 매핑이 불명확한 환경, GPU 메모리를 조회할 수 없는 환경은 순차 처리합니다. 추론 중 메모리가 부족하면 실행 중인 두 작업이 정리된 뒤 성공한 결과를 유지하고 실패한 구간만 같은 모델로 한 번 순차 재시도합니다. 재시도 실패를 무시하거나 처리 완료로 세지 않습니다.

`VIDEORANDOM_ASR_WORKERS=1`은 순차 처리 비교용이며 `2`는 명시적 병렬 요청입니다. 사용자 화면의 정확도 기본값과 한국어 번역·검수 정책을 변경하지 않았습니다. 병렬 처리 중에도 온도 재시도의 확률적 결과가 항상 같은 문자열로 나오는 것은 아닙니다. 인식 방식 변경으로 기존 결과를 강제로 다시 만들지 않으며 현재 검수 revision 3을 유지합니다.

## 진행률과 예상 시간

이전에는 대사 끝 시각으로 계산한 진행률과 구간 처리 완료율이 서로 다른 배율로 같은 값을 덮어썼습니다. 현재 워커는 구간 처리 이벤트만 진행률에 사용합니다. 구형 워커의 대사 이벤트 경로는 호환을 위해 유지합니다.

인식·재검수에는 완료한 음성 길이와 해당 단계 전체 작업량을 별도로 전송합니다. 재검수는 원본 영상 길이를 재사용하지 않고 실제로 다시 읽을 음성 길이를 사용합니다. 세 번 이상의 전진 관측과 15초 이상의 관측 시간이 쌓인 후 최근 처리 속도로 **현재 단계만** 추정합니다. 원본 음성을 읽었다는 사실을 전체 분석 완료로 표시하지 않습니다. 단계가 바뀌면 이전 예상치를 지우며 마지막 처리 관측이 120초 넘게 갱신되지 않으면 예상치를 숨깁니다. LAN 상태 재조회도 오래된 예상치를 새 관측으로 바꾸지 않습니다.

병렬 구간을 기다리는 동안 워커는 경과 관측을 보냅니다. 처리하지 않은 구간을 진행한 것으로 세지 않습니다. 서버·클라이언트 경계를 통과하는 진행 정보는 단계 식별자와 유한한 숫자만 허용하며 음성 내용·파일 경로·연결 코드를 포함하지 않습니다.

## 검증 범위

모형 인식기로 병렬 수 제한, 완료 순서가 뒤바뀐 두 구간의 원본 순서 반영, 전체 인식·재검수의 순차 결과와 같은 시간·대사·검수 값, 기존 인식 인수 보존, 메모리 사전 조건, OOM 후 성공 결과 보존, 한 번의 순차 재시도, 대기 제한 시간과 완료가 겹치는 경합을 검증했습니다. 모델을 내려받거나 실제 GPU 추론을 실행하는 시험은 아닙니다.

진행 정보는 provider → LAN 호스트 → 클라이언트 → 화면 경로에서 카운터를 다시 배율 계산하지 않고 전달하는지 검사했습니다. 잘못된 수치·임의 필드 제외, 다음 단계의 예상치 제거, LAN 재조회 중 오래된 예상치 만료와 구형 워커 호환도 확인했습니다.

이번 구현 중 운영 분석이 GPU를 사용하고 있어 실제 음성의 순차·병렬 비교를 겹쳐 실행하지 않았습니다. 따라서 이 문서는 **실제 영상의 몇 배 가속이나 1~2분 완료를 보증하는 측정 보고서가 아닙니다.** 현재 분석 서버를 중지·재시작하거나 처리 중인 원격 요청을 새 워커로 교체하지 않았습니다.

최종 Node 회귀 **389개 통과**(실패·취소·생략 0)이며 그 안에서 Python 워커 회귀 87개와 벤치마크 단위 검사 6개도 실행했습니다. 빌드한 Windows 실행 파일 1.7.1을 별도 저장 폴더와 포트로 열어 새 진행 정보 스크립트를 포함한 HTML·JS·CSS 바이트 일치, 저장 결과 읽기·편집, 중단 작업 제외, 원래 시간의 부분 SRT 저장과 기존 완성 자막 보존, 잘못된 요청 후 정상 응답을 확인했습니다. 이 실행 파일 시험도 실제 음성 인식이나 provider 호출을 하지 않았습니다.

## 실제 처리량 비교 도구

`scripts/benchmark_subtitles.py`는 같은 현재 정확 모드의 `--workers 1`과 `--workers 2`를 비교할 수 있습니다. 공개·사용 허가된 음성과 정확한 원문을 명시적으로 준비한 manifest를 사용합니다. 각 항목에는 `file`, `reference`, `language`, `case`, 자료 출처와 라이선스를 기록합니다. 두 구간 병렬을 시험하려면 최소 3분 이상이며 여러 인식 구간을 포함하는 자료를 사용해야 합니다. 짧은 단일 구간으로 측정한 실행 시간을 긴 영상의 병렬 처리 성능으로 해석하지 않습니다.

운영 분석을 마친 뒤 같은 PC와 같은 공개 manifest·모델·장치로 실행하고 출력 폴더를 구분합니다. 다음 경로는 비교용으로 준비한 공개 자료의 예시입니다.

```powershell
$taskPython = Join-Path $env:LOCALAPPDATA 'VideoRandom\catalog\runtime\Scripts\python.exe'
$taskModels = Join-Path $env:LOCALAPPDATA 'VideoRandom\catalog\models'
& $taskPython scripts/benchmark_subtitles.py --manifest .test-data/asr-public-long/manifest.json --profiles accurate --workers 1 --device cuda --cache $taskModels --output artifacts/asr-serial
& $taskPython scripts/benchmark_subtitles.py --manifest .test-data/asr-public-long/manifest.json --profiles accurate --workers 2 --device cuda --cache $taskModels --output artifacts/asr-parallel
```

결과에는 요청한 병렬 수와 실제 병렬 수, 메모리 부족 시 순차 전환 여부, 경과 시간, 음성 길이 대비 처리 시간, 원문 문자 오류율과 누락 검수 결과를 함께 보관합니다. 모델을 재사용한 실행의 시작 비용은 새 프로세스 실행과 다르므로 병렬 속도 비교와 섞지 않습니다. 같은 장치에서 다른 GPU 작업을 함께 실행한 수치도 별도로 구분해야 합니다. 속도만 개선되고 누락·원문 오류가 늘면 정확 모드의 개선으로 판단하지 않습니다.

## 업데이트 적용

음성 인식 병렬 처리는 분석 서버 PC가 새 버전으로 실행될 때 적용됩니다. 처리 중인 요청은 기존 워커로 계속 실행되며 진행 중에 새 방식으로 바뀌지 않습니다. 클라이언트 PC도 새 버전으로 실행해야 새 처리량·예상 시간 표시를 볼 수 있습니다. 주소·연결 코드·저장 결과는 유지합니다.
