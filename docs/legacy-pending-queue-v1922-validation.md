# 1.9.22 · 미완료 응답의 구버전 호환과 다음 영상 진행

2026-10-21. 실제 문제 확인은 기술 진단의 코드·개수·단계·실행 버전만 읽었다. 사용자 영상·음성·대사·줄거리·번역 제공자 원시 응답은 읽거나 재처리하지 않았다. 구현 검증에는 중립 합성 전사·가짜 엔진·별도 저장소만 사용한다. 운영 서버·작업·설정은 변경하지 않는다.

## 원인

최근 한 번역 복구는 전체 390구간 중 346구간을 보관하고 마지막 321–390번 묶음도 처리했다. 241–320번 검수 응답의 누락·일부 길이 판정·작업당 보완 한도 때문에 44구간이 미완료로 남았다. 최종 진단은 `SUBTITLE_CUES_PENDING`, 실행 버전은 요청 PC 1.9.20·서버 1.9.16이었다.

1.9.20 대기열 판정은 해당 코드 자체를 영상별 문제로 취급하지만, 먼저 확인하는 일반 `subtitleError` 문자열에는 코드가 없었다. 구버전의 정확한 미완료 안내 문장이 `DIAGNOSTIC_UNKNOWN`으로 분류돼, 함께 전달된 `SUBTITLE_CUES_PENDING`을 읽기 전에 공통 오류로 판정됐다. 이로 인해 다음 영상 중지·건너뜀 기록 누락·저장 결과를 이용한 기존 자동 중지 복구 실패가 발생했다. 합성 응답으로 수정 전 같은 대기 중지를 재현했다.

## 수정

- 표준 영상별 진단 문장은 선언된 진단의 고정 문구와 정확히 일치하는 경우에만 매핑한다. 구버전 및 현재 버전 미완료 안내도 전체 문장과 `1..50000` 범위의 구간 수를 검증한다. 현재 버전 문장은 미완료 수가 전체 수를 넘을 수 없다.
- 명시된 인증·서비스 거절·사용량·시간 초과·연결·저장 오류 코드·HTTP 상태·즉시 원인 정보는 계속 우선한다. 정확한 미완료 문장의 구간 수 401·403·429·500·502·503·504는 HTTP 오류로 오인하지 않는다. 문장에 추가된 서비스 오류나 알 수 없는 실행 내용은 정확 일치에 포함되지 않는다.
- 영상 한 건의 `SUBTITLE_REPAIR_LIMIT`는 계정·서비스의 사용량 제한과 구분해 결과를 보관하고 다음 파일을 처리한다. 실제 서비스 사용량 오류를 이 코드로 바꾸거나 중단한 요청을 재제출하지 않는다.
- 최종 결과와 작업 기록을 저장한 뒤 다음 영상으로 진행한다. 결과를 완성 자막으로 새로 승인하지 않는다. 기존 자동 일시 중지는 동일 저장 결과·경로를 확인하는 기존 마이그레이션이 새 분류를 사용하며, 사용자 중지·취소·미저장 중단·다른 공통 오류는 보존한다.
- 원어 인식·번역 모델·검수 횟수·보완 한도·저장 형식·연결 설정을 변경하지 않는다. 번역 자체의 길이 거부 및 외국어 처리 개선은 1.9.21 이하의 변경을 그대로 포함한다.

## 검증

- 최종 전체 Node 검사 **1,619개 통과**, 실패·취소·생략 0개, **41.59초**. `artifacts/test-v1922-final.log`.
- 새 회귀 검사 **23개**는 구버전·현재·표준 미완료 문장, HTTP 상태처럼 보이는 구간 수, 잘못된 범위·추가 오류 문장, 명시적 공통 오류 우선, 영상별 보완 한도를 검증한다. 실제 HTTP 서비스와 별도 저장소에서 미완료 결과 뒤 다음 파일 실행, 부분 SRT·실패 기록 보관, 시작 시 기존 자동 중지 복구, 같은 파일 자동 재실행 방지도 확인했다.
- 기존 대기열·결과 이력 회귀 **104개**를 통과했다. 독립 코드 검토에서는 별도 합성 87개 조합에서 인증·거절·503·사용량·연결·저장·취소·미확인 오류가 잘못 통과하지 않는 것도 확인했다. 실제 제공자 호출이나 사용자 영상의 번역 완료를 뜻하지 않는다.
- Windows EXE 빌드와 manifest 확인을 통과했다. **99,537,649바이트**, SHA-256 `9a43d0d319f39454035f9f084e560c5dd486b17545fe492b5f5ddaa11af9dc54`. 이전과 같은 Windows 미사용 `open/xdg-open` 경고만 남았다. `artifacts/build-v1922.log`.
- 최종 EXE를 별도 저장소와 소유한 시험 포트에서 실행했다. 가짜 LAN 서버가 현대 처리 완료 증거 없이 구버전의 실제 형식과 같은 일반 오류·부분 결과를 반환한 뒤, 먼저 등록된 다른 번역 복구가 완성 SRT까지 정상 처리되는 것을 확인했다. 앞 결과의 원래 ID·시각·부분 SRT·건너뜀 이력 `2/3`을 보존했고, 두 독립 원본을 각각 한 번만 처리했다. 기존 자막·진단·거절 회귀도 통과했다. 실제 영상 디코딩·ASR·번역 제공자 호출은 없었다. `artifacts/package-v1922.log`.
- 실제 PowerShell 도우미와 최종 EXE의 **1.9.21→1.9.22 인계** 및 의도적 새 실행 실패 시 **1.9.21 복원**을 모두 통과했다(전체 **92.87초**). 연결 설정·결과·자막·대기열 등 시험 파일 **8개의 바이트를 각 시나리오에서 보존**했고 소유한 시험 프로세스만 정리했다. `artifacts/update-handoff-v1922.log`.

이 대기열 호환 수정은 화면을 사용하는 PC가 1.9.22로 실행된 뒤 적용되며 해당 구버전 서버 응답도 지원한다. 운영 프로그램을 검증 과정에서 중지하거나 재시작하지 않는다.
