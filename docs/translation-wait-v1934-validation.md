# 1.9.34 · 번역 대기 관측과 요청 제한

2026-10-27. ‘초안 번역 응답 지연’은 논리 요청 전체의 경과 시간이며 실제 제공자의 생성·연결 상태를 나타내지 않던 문제를 수정했다. 사용자 영상·음성·전사·요약·원시 응답은 열지 않았다. 제공자·ASR·모델·GPU 작업을 실행하지 않았으며 검증에는 중립 합성 자막, 가짜 도구·LAN 서버, 소유한 비활성 Node 자식과 별도 저장소만 사용했다. 운영 프로그램의 종료·교체·재시작은 수행하지 않는다.

## 대기 상태의 의미

- 요청 전체 경과와 실제 CLI 시도의 경과·남은 제한 시간을 구분한다. 첫 요청 또는 이전 동일 단계의 요청 속도를 기준으로 ‘지연’을 표시하되, 시간 경과만으로 실제 생성 중이라고 말하지 않는다.
- `thread.started`는 번역 도구 준비, `turn.started`는 요청 시작 신호로 표시한다. 실제 assistant 메시지 이벤트를 관측했을 때만 응답 이벤트 수신으로 표시한다. `turn.completed`만으로 대사 출력을 받았다고 표시하지 않는다.
- 인식한 재연결·기술 오류만 관측한다. 임의 stderr, 원문이나 응답 본문의 문구는 활동 신호로 사용하지 않는다. 연결 재시도·모델 혼잡 대기와 요청 전체 타이머를 구분한다.
- 1초 상태 갱신은 기존 신호의 나이를 계산하며 신호 시각이나 완료 구간을 갱신하지 않는다. 한 번 읽은 미종결 stderr 행을 다시 확인해도 활동 시각이 새로 바뀌지 않는다. 이전 시도의 늦은 이벤트와 다음 초안의 상태가 현재 검수 상태를 덮지 않게 한다.
- 진단에는 고정 활동 종류, 시도 번호, 요청 모델·추론 설정, 경과·제한·마지막 신호의 상대 시간, 재연결 횟수·HTTP 상태만 남긴다. 원시 텍스트·요청 ID·프롬프트·파일 경로는 추가하지 않는다. 과거 진단의 신호 간격은 ‘기록 시점’이라고 표시한다.

구버전 서버가 이 정보를 제공하지 않으면 ‘세부 연결 상태 미지원’으로 표시한다. 서비스 혼잡·실제 생성·응답 없는 연결 중 어느 것인지 관측하지 못한 경우 원인을 추측하지 않는다. 이전 기록에 없던 원인은 이 업데이트로 복원되지 않는다.

## 번역 요청의 최대 대기

초안·원문 대조 검수·누락 보완의 **각 논리 번역 요청에 최대 180초**를 적용한다. 혼잡 재시도의 대기·이전 시도·도구 준비도 같은 예산을 사용하며 시도마다 180초를 다시 시작하지 않는다. 도구 준비 후 남은 시간을 다시 계산하고, 예산이 끝났으면 새 자식을 실행하지 않는다. 서버의 Retry-After를 짧게 줄여 재요청하지 않는다. 일반 요약의 기존 15분 제한과 ASR 제한은 그대로다.

종료 요청 후 첫 정리 유예는 기본 2초이고, 종료하지 않았으면 같은 소유 자식에 강제 종료 신호를 보내 최대 2초를 더 확인한다. 종료 이벤트는 받았으나 파이프 닫힘이 없는 경우에도 출력 꼬리를 확인하고 파이프를 정리한다. 종료 사실을 확인하지 못하면 유한 시간 안에 그 사실을 반환하고, 해당 프로세스의 실제 종료를 확인할 때까지 같은 제공자 인스턴스의 새 도구 실행을 차단한다. 정상 생성이 길어지는 경우도 이 예산을 넘으면 미완료로 남으며, 완료를 보장하거나 실제 서비스 자체의 응답 속도를 높였다는 뜻은 아니다.

타이머·취소·도구 오류 경합에서 최초 실패를 보존한다. 종료 중에 늦게 관측한 인증·사용량·거절·통신·서비스 또는 미분류 오류를 앱의 자체 제한으로 숨기지 않는다. 신호 전송 중 발생한 `ChildProcess.error`만으로 도구가 종료됐다고 판정하지 않는다. 소유한 자식만 처리하며 실행 중인 다른 프로그램을 검색하거나 종료하지 않는다.

## 보관과 다음 대기 영상

앱 자체 번역 예산, `local-deadline`, 정확한 번역 요청 범위, 제한 시간·경과, **프로세스 종료 확인**과 충돌하는 다른 오류가 없다는 증거가 모두 있어야 `PROVIDER_REQUEST_DEADLINE`으로 분류한다. 코드나 문구만 받은 결과는 이 권한을 얻지 못한다. 일반 제공자 시간 초과·종료 미확인·사용자 중지·실제 인증·사용량·거절·통신·저장·알 수 없는 오류의 기존 처리는 유지한다.

확인된 자체 제한은 검수된 자막·원문·체크포인트를 보존하고, 자막이 있으면 부분 SRT를 저장한 뒤 다음 **독립 영상**을 진행한다. 같은 실패 요청을 자동으로 반복하지 않으며 결과는 미완료와 실제 `완료/전체` 개수로 남긴다. 한국어 자막 복구는 저장한 원문·시각과 검증된 앞부분을 재사용하는 별도 사용자 동작이다. 실제 제공자 거절을 다른 요청·모델·분할로 우회하지 않는다.

## 실행 버전 확인

이 PC의 실제 실행 버전과 최신 버전의 다운로드·적용 상태를 구분한다. 내려받았지만 아직 교체되지 않았으면 ‘다운로드 완료 · 적용 전’으로 표시한다. 다른 PC 연결을 확인하면 서버가 반환한 실행 버전과 ‘연결 확인 시점’을 함께 표시한다. 주소·연결 코드가 바뀌면 과거 확인 표시를 지우며, 과거 연결의 늦은 응답이 새 연결에 버전이나 연결 성공을 표시하지 못한다.

새 실행 파일만 내려받아도 현재 실행 중인 구버전 코드가 도중에 바뀌지는 않는다. 실행 중인 서버와 화면·대기열 PC를 새 버전으로 적용해야 전체 변경을 사용할 수 있다. 기존 주소·연결 코드·원문·결과·SRT·사용자 중지는 같은 저장소에 보존한다.

## 검증

- 관측기·진행 표시·진단 UI: 허용 목록·분할 UTF-8·미종결 행·빈 신호·구버전 자료·시도 변경·늦은 과거 시도·앞선 검수 우선·혼잡 대기·카운트다운·기록 시각·원시 내용 미노출을 검증한다.
- 실제 provider runner를 가짜 도구로 실행해 기본 180초 예산 전달, 한 묶음만 저장 후 다음 초안 제한, 소유한 부분 체크포인트 보존, 종료·파이프 정리·실패한 신호 전송·미확인 종료의 새 실행 차단과 후속 실제 종료 후 해제를 검증한다. 비활성 Node 자식 시험에서는 실제 운영 도구 없이 PID 종료 사실을 확인한다.
- 실제 대기열 서비스의 HTTP 경로를 별도 임시 저장소·중립 메타데이터로 실행해, 첫 영상 `1/3` 부분 결과와 부분 SRT·원문을 보관하고 다음 두 복구를 한 번씩 순서대로 실행하는 것을 확인한다. 재실행 후 보관 자료·확인 필요 기록을 유지하고 실패 요청을 재실행하지 않는다. 일반 시간 초과·미확인 종료·다른 오류와 사용자 중지는 다음 작업을 임의로 재개하지 않는다.
- 실행 버전·다운로드 후 적용 전·연결 시점 서버 버전과 연결 수정 경합을 DOM 모형으로 검증한다.
