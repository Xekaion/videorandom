# 1.9.39 · 짧은 발화 재검사의 문맥과 처리량

2026-11-13. RCTD-614의 서버에 보관된 결과에서 수치·처리 범위·검수 메타데이터를 확인했다. 영상·음성·대사 본문을 재생하거나 새 ASR·번역을 실행하지 않았다. 기존 작업·설정·결과는 수정하지 않았다.

## 저장 결과에서 확인한 사실

- 영상 길이 6,722.327초(1시간 52분 2.327초), 디코딩 음성 길이와 처리 범위는 6,722.3253125초다. 마지막 대사 끝은 6,722.28초다. 앞부분만 처리돼 624개가 된 경우는 아니다.
- large-v3, 정확 모드, CUDA int8_float16, 작업자 2개, recognition revision 3으로 원문 624개를 보관했다. 한국어 번역은 607/624개다.
- 누락 검사 완료는 false다. 확인 필요 203개는 누락 의심 78개, 낮은 신뢰도 115개, 정렬 충돌 10개다. 시간 목록은 200개 표본이지만 전체 개수는 별도로 저장됐다.
- 발화 검출 합계 345.312초, 대사와 대응하지 않는 검출 발화 45.762초, 발화 경계 차이 9.74초다. 발화 검출 합계는 실제 대사 전체의 정답 길이가 아니며 검출 누락 가능성이 있다. 구간 수와 이 수치만으로 필요한 대사 개수를 정하지 않는다.
- 1,693.616초를 재검사했어도 위 문제가 남았다. 현재 자료로 624개가 정확한 전체 대사인지, 개선 뒤 몇 개로 바뀔지는 확정할 수 없다.

## 변경과 적용 범위

기존 recovery_plan은 의심 범위를 1.5초 확장한 span 안에서만 추가 문맥을 허용했다. 고립된 0.5초 목표는 3.5초 입력이 되어 앞뒤 3초 문맥을 실제로 전달하지 못했다. 새 계획은 span 바깥에서도 원본 음성 범위 안의 문맥을 전달한다. 같은 목표는 9.5초 입력이 된다. 내부 코어는 최대 30초, 문맥 포함 입력은 최대 36초다.

패딩된 span 사이 간격이 문맥 양쪽 합계(기본 6초) 이하면 함께 계획한다. Whisper의 짧은 입력 패딩 때문에 되풀이하던 encoder 작업과 호출을 줄인다. 연결된 사이의 음성과 외부 문맥도 디코딩하지만, 병합 후보는 기존 RecoveryTargetIndex로 원래 의심 범위에 해당하는 대사만 선택한다. 연결 구간에 새 대사를 임의로 넣지 않는다.

정확 모드의 large-v3, beam 5, best-of 5, 온도 fallback, VAD 없이 전체 음성 처리, 단어 정렬, 재검사 옵션, 보수적 병합과 미해결 판정은 유지한다. 바뀐 것은 재검사 입력 계획이다. 최대 두 작업자·기존 OOM fallback·실제 디코딩 길이 합계에 따른 진행률과 예산 집계를 그대로 사용한다. 기존 유효한 결과를 무효화하지 않으며 recognition revision은 3을 유지한다. 기존 결과에 새 계획을 적용하려면 원문부터 다시 분석해야 한다.

상세 화면에는 저장된 발화 검출 합계와 미해결 발화 합계를 보여 주고, 구간 수만으로 전체 대사 인식 여부를 판단할 수 없음을 표시한다. 해당 수치가 없는 기록에는 값을 추정하지 않는다.

## 검증

새 중립 모델 검사 10개: 외부 문맥, 가까운 목표 병합, 먼 목표 분리, 영상 양끝, 빈 목표, 잘못된 인수, 무작위 500개 계획의 모든 목표 보존·최대 입력·전체 길이 1.2배 이내 처리량, 짧은 입력 반복 비용, 실제 시각을 보존하는 문맥 의존 인식, 연결 문맥의 대사 배제. 기존 Python ASR 검사 99개도 통과했다. 변경된 입력 시작 시각과 묶음 수에 맞춰 가짜 응답의 상대 시각 및 호출 수 3개를 조정했다.

중립 목표 200개(5초 간격, 각 0.5초, 전체 1,100초)의 계획 비교: 호출 200→34개, 30초 단위 패딩 합계 6,000→2,010초, 새 실제 입력 합계 1,202.5초. 패딩 합계는 인코더 입력량의 단순 지표이며 음성 추론 시간이나 전체 영상 속도 실측이 아니다. 새 입력은 문맥을 더 전달하므로 실제 디코딩 샘플은 늘어날 수 있다. 대상 분포와 장치에 따라 속도 효과가 다르다.

전체 Node 검사는 3,275개 중 3,274개 통과, 실패·취소 0개, 기존 Windows 심볼릭 링크 권한 검사 1개 생략, 87.68초다. 새 Python 검사 10개와 기존 ASR 검사 99개도 이 실행에 포함됐다. 기록은 `artifacts/test-v1939-final.log`다.

Windows EXE 빌드와 manifest 대조를 통과했다. 크기 99,792,586바이트, SHA-256 `a5656758c85375a6b587ecd72d86c34687f47f024bef0a1cafa1ada79c8fbbe8`다. 기존 Windows 미사용 `open/xdg-open` 경고만 있었다. 기록은 `artifacts/build-v1939.log`다.

새 EXE를 별도 데이터 폴더·임의의 로컬 포트에서 실행해 준비 완료, 실제 버전 1.9.39, 새 UI 자산을 확인하고 이 시험 프로세스만 종료했다. manifest는 실제 EXE의 크기·해시와 다시 대조했다. 기록과 재현 스크립트는 `artifacts/package-v1939.log`, `artifacts/smoke-v1939.cjs`다. 공개 배포·운영 프로그램 재시작·실제 사용자 영상 재분석은 실행하지 않았다.
