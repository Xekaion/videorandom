# 1.9.37 · 시간 초과로 남은 자막의 보완

11월 8일 KST의 NHDTB-275(20:03, 1,193/1,321)와 BBAN-339(19:16, 1,687/1,782) 기술 진단을 확인했다. 두 작업 모두 마지막 보완에서 8묶음을 처리해 각각 40구간을 추가한 뒤 미완료가 됐다. NHDTB-275의 끝 1315–1321, BBAN-339의 끝 1761–1782도 시간 초과 이후 정상인 원래 묶음이 없다는 이유로 보완 대상에서 제외됐다. 두 작업 뒤 다른 대기 작업의 시작이 확인됐다. 최신 기록에서 SRT 저장 실패는 관측되지 않았으나, 저장 성공은 기술 진단만으로 확인할 수 없다.

- 긴 원문(960구간 이상)의 기본 요청은 최대 32구간과 4,800개 UTF-16 코드 단위로 제한한다. 큰 단일 대사는 자르거나 버리지 않는다. 기존 정확 모드의 검수, 저장 자막과 원문의 번호·시간, 형식 보완과 기존 요청 제한은 유지한다.
- 확인된 앱 시간 초과의 미완료 번호만 보완한다. 뒤쪽 원래 묶음이 정상으로 끝나면 이전 빈 구간을 먼저 확인하고, 이 보완에서 새 자막이 검증되면 영상 끝의 시간 초과 구간까지 확인한다. 8묶음으로 총량을 자르지 않는다.
- 한 묶음은 최대 8구간이다. 시간 초과하면 다음 묶음을 줄이고, 두 묶음 연속으로 새 자막이 저장되면 크기를 다시 늘릴 수 있다. 확인하지 않은 번호를 먼저 처리한 뒤, 다른 묶음에서 정상 결과를 확인했을 때만 실패한 여러 구간을 더 작은 묶음으로 한 차례 추가 확인한다. 구간별 보완은 최대 두 번이다. 4개 보완 묶음에서 연속으로 새 자막이 검증되지 않으면 같은 영상에서 추가로 기다리지 않는다.
- 실제 서비스 거절·인증·저장 실패 등을 시간 초과로 바꾸지 않는다. 미검수 자막을 완성으로 표시하지 않으며, 다음 복구에서 이미 검증된 자막을 다시 요청하지 않는다.

회귀 검사에서는 소유한 모의 프로세스만 사용한다. 64구간을 넘는 빈 자막, 영상 끝부분, 새 번호 우선 처리, 8→4→2→1 축소, 연속 무진전, 인증 오류, 번호·시간 및 정확 모드 검수 보존을 검증한다. 실제 영상이나 제공자 요청으로 완료를 확인한 것은 아니다.

1,819구간 모의 복구에서는 검수 자막을 보존하고 빠진 19구간만 보완한 뒤 디스크에 저장된 전체 SRT를 원래 시간과 대조했다. 별도 루프백 저장소·포트에서 Windows EXE의 모의 LAN 통합 검사가 통과했다. EXE 99,782,094바이트, SHA-256 `f1ba5dd6a7199d6b0696fd037075ca9f42fe4cb7bec4b9c29e2cf7268f356f97`.
