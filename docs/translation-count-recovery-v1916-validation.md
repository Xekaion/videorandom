# 1.9.16 · 빈 검수 응답과 반복 누락 보완

2026-10-21. 실제 진단 확인은 허용된 기술 메타데이터만 읽었다. 구현·회귀 검사는 중립 합성 전사·가짜 제공자·별도 저장소와 시험 실행 파일만 사용한다. 실제 사용자 영상·음성·대사·요약·제공자 원시 응답은 읽지 않았고 실제 모델·번역 제공자를 호출하지 않았다. 운영 서버·작업·저장 결과·연결 설정을 변경하지 않았다.

## 확인한 원인

기술 기록에서 번역 전용 복구의 `translation_review` 실패를 확인했다. 확보한 원문은 1,819구간, 저장한 번역은 240구간이었다. 다음 241–320번 초안은 **80개 요청 / 80개 검증 성공**, 이어진 검수는 **80개 요청 / 0개 반환**으로 실패했다. 관련 진단에는 거절·인증·한도·시간 초과·연결 오류 표시는 없었다. 빈 응답의 내부 이유를 추측하지 않는다. 개인 파일명·경로·작업 식별자·발생 시각은 이 문서에 포함하지 않는다.

기존 코드는 빈 검수 배열을 누락 보완 전에 거부했다. 비어 있지 않은 응답에도 번호가 빠지면 한 차례 보완했지만 보완 응답에서 다시 번호가 빠지면 뒤쪽까지 중단했다. 1.9.12의 반복 누락 격리는 지나치게 짧은 대사를 대상으로 했으며 이 경로를 해결하지 않았다.

## 변경과 유지한 조건

- 알려진 필드와 `terms` 배열을 가진 정상 구조의 빈 검수는 미승인 상태로 받아 누락 보완한다. 검수 승인이 없다고 기존 초안을 자동 승인하지 않는다. 빈 초안·누락 배열·과도한 개수·잘못된 형식은 실패로 유지한다.
- 먼저 20구간 이하로 보완하고, 그 응답에서 빠진 번호만 한 차례 더 단일 구간으로 보완한다. 모든 보완은 작업 전체의 기존 **64회** 한도를 공유한다. 반복해서 짧은 최종 대사를 재귀적으로 다시 요청하지 않는다.
- 유효한 구간은 원문의 명시적인 번호로 대응하며, ID·시작·종료 시각을 원문에서 복사한다. 빠진 번호 앞뒤의 검수된 구간도 체크포인트로 보관한다. 배열 위치로 맞추거나 없는 대사를 생성하지 않는다.
- 정확 모드의 검수 대상은 실제로 확보한 초안의 번호만 사용한다. 모든 승인·수정은 원문 대조를 거치며 고유명사·한국어 본문·길이 검증을 유지한다. 고유명사 확인 누락과 충돌은 무시하지 않는다.
- 끝내 없는 구간이나 보완 한도로 남은 구간은 미완료로 보관하고 뒤쪽 일반 번역·검수를 계속한다. 원문 전체를 끝낸 뒤 실제 남은 번호와 `SUBTITLE_CUES_PENDING`을 표시한다. 전체 번호가 검증되고 원어 처리 증거도 충족할 때만 완성으로 표시한다.
- 거절 필드·거절 대사 문구는 누락 처리보다 먼저 검사한다. 도구 실패·인증·사용량·503·시간 초과·네트워크·잘못된 JSON·취소는 자동 보완·재요청으로 바꾸지 않는다. 시작한 선행 작업도 종료를 기다린다.
- 검증된 구간의 승인·체크포인트 계약이 같으므로 번역 프롬프트 버전 7을 유지한다. 원문 지문·구간 ID·시간·품질·검수 횟수를 확인해 기존 240구간을 포함한 유효한 체크포인트를 이어 사용한다.
- 실제 개수 오류 문구에는 번역/검수·요청 수·응답 수 또는 배열 누락을 표시한다. 메시지만 남은 진단도 기존 `SUBTITLE_CUE_COUNT_MISMATCH`로 분류하고, 원문·번역·원시 오류 본문을 진단에 복사하지 않는다.

## 합성 검증

- 신규 처리 검사 **37개**와 오류 분류 검사 **3개**를 추가했다.
- 1,819구간에서 처음 240구간 후 80개 검수가 비는 상황을 compact 승인 형식과 기존 전체 번역 형식으로 각각 재현했다. 각각 네 번의 20구간 보완 후 **1,819/1,819**까지 원래 ID·시각으로 검수·저장했다.
- 2,000구간의 정확·빠름·초고속 모드에서 일부가 빠진 보완 응답을 단일 구간으로 해결한다. 정확 모드의 미승인 한 구간을 남기고 2,000번째 구간까지 저장한 뒤 다음 복구에서 그 한 번호만 처리하는 것도 확인한다.
- 64회 보완 한도, 빈 검수의 끝없는 반복 방지, 정확 모드의 초안 누락, 최종 구간 보존, 기존 완료 체크포인트 재사용을 검사한다. 거절·401·한도·503·시간 초과·네트워크·잘못된 JSON의 즉시 중단, 중복/범위 밖 번호·외국어·고유명사 문제도 유지한다.
- 기존 테스트는 앞부분만 보존해야 한다는 기대를 정확한 승인 번호 집합으로 바꿨다. 확인되지 않은 번호는 여전히 저장하지 않으며 검수된 뒤쪽의 원문 ID·시간·본문과 미완료 표시를 구체적으로 대조한다.
