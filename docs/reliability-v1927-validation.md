# 1.9.27 · 접수 결과 복구와 저장 안정성

2026-10-27. 실제 영상·음성·대사·요약·제공자 원시 응답을 열지 않고, 기술 진단을 대조하고 중립 합성 데이터로 수정 사항을 검사한다. 실제 ASR·번역·제공자 요청이나 운영 프로그램 재시작은 수행하지 않는다.

## 확인한 결함과 변경

- 서버 접수 뒤 클라이언트가 결과 수신을 포기하면 서버에서 나중에 완료한 결과를 놓칠 수 있었다. 이제 접수 직후 작업 ID·서버 원점·작업 종류·원본 지문과 정확한 전송 원본을 `remote-receipts`에 원자적으로 기록한다. 재수신은 같은 작업에 대한 GET만 사용하며 업로드·ASR·번역을 다시 요청하지 않는다. 원본 파일 크기·수정 시각·전송 지문·결과 ID를 확인한다.
- 수신 중 통신 오류만 자동 재연결 대상으로 삼는다. 삭제된 작업·다른 결과·인증·사용량·실제 서버 작업 실패·사용자 취소는 자동 재접수하지 않는다. 대기·확인 필요 상태와 영상명을 표시하며, 접수된 영상에 새 분석 요청을 보내는 경로도 차단한다. 접수 기록을 쓸 수 없는 동안에는 메모리에 접수 정보를 유지하고 새 원격 전송을 보류한다.
- 작업 전 저장 공간 검사를 추가한다. 클라이언트는 알려진 영상 길이에 맞는 임시 음성·이미지 공간과 512MiB 보존 공간을 확인하고, 서버는 업로드 크기와 동시 업로드 예약량을 확인한다. 알려진 공간 부족은 `STORAGE_SPACE_LOW`/HTTP 507로 구분한다. 공간 부족으로 중지된 대기열만 자동 재개하며 서버 공간은 서버의 인증된 상태 조회로 확인한다. 조회 불가를 충분한 공간으로 간주해 대기 상태를 해제하지 않는다.
- 여러 파일을 선택한 작업에서 공간 부족을 만나면 현재 파일 이후를 보관하고 더 진행하지 않는다. 기존 사용자 일시 중지·취소를 공간 회복으로 해제하지 않는다. 공간 추정은 사전 검사이며 실행 중 다른 프로그램이 공간을 소모하는 모든 상황을 보장하지 않는다.
- 일반 분석 catch·서버 종료 결과·제공자 결과 반환 경계에서 오류 코드·HTTP 상태·시스템 코드·실행 제한 근거가 사라지던 경로를 보완했다. 미분류 제공자 실행 오류는 정확한 하위 원인을 추측하지 않고 `PROVIDER_UNKNOWN`으로 보존한다.
- 진단 저장의 공통 경고를 append·전송 대기 저장·수신 확인·시작 읽기 등 연산별 상태로 분리했다. 최초/최근 실패 시각·횟수·시스템 코드·복구 시각을 최대 32개 이력으로 보존하며 다른 연산의 성공으로 누락된 이벤트 저장 실패를 지우지 않는다. 원시 응답·대사·경로·연결 코드를 기술 상태에 추가하지 않는다.

## 검증과 적용 범위

새 합성 검사는 동일 작업 결과 재수신, 재시작, 원본 변경, 인증 서버 일치, 잘못된 결과, 저장 실패, 취소·일시 중지, 공간 부족과 회복, 다중 파일 보관, 진단 연산별 복구, UI 표시를 포함한다. 모델·프롬프트·번역 재시도 정책은 변경하지 않는다. 실제 거절을 우회하거나 실패를 숨겨 완료로 표시하지 않는다.

- 최종 전체 Node 검사 **2,299개 중 2,298개 통과**, 실패·취소 0개, **64.36초**. Windows 심볼릭 링크 생성 권한이 필요한 기존 검사 1개만 생략했다. `artifacts/test-v1927-final.log`.
