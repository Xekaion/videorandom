# 1.9.26 · 넘긴 영상 표시 기록 정리와 영상별 실패 분류

2026-10-24. 중립 합성 데이터·가짜 분석 엔진·독립 시험 저장소로 검증한다. 실제 사용자 영상·음성·대사·원시 제공자 응답은 검사하지 않고 실제 제공자 추론·번역·ASR을 호출하지 않는다. 운영 프로그램·분석 작업·설정은 변경하거나 재시작하지 않는다.

## 표시 기록 삭제

`다음 분석으로 넘긴 영상 · 저장 기록`을 기본으로 접고, 펼친 목록에도 높이 제한을 둔다. 항목마다 `목록에서 삭제`, 전체에는 `기록 비우기`를 제공한다. 같은 영상의 실제 분석 결과·진단·원문·번역·SRT·현재/대기 작업을 삭제하는 기능은 아니다.

`DELETE /api/analysis/queue/issues`에 `{recordId, recordedAt, code}`를 보내 해당 표시 항목을 정리하거나 `{clearAll:true}`로 현재 저장된 전체 표시 기록을 정리한다. 최근 20개 화면 밖의 이전 항목도 포함하되 이후 발생하는 새로운 시도는 표시한다. 별도 `queue-issue-dismissals.json`에 항목의 ID·코드·기록 시각을 조합한 SHA-256 식별값만 저장한다. 분석 결과 파일과 원래 `queueOutcome`·진단은 변경하지 않는다.

목록 정리는 분석 진행 중에도 사용할 수 있다. 진행·대기열 제어와 별도의 사용 중 상태를 사용하며 삭제 전 요청이 늦게 도착해 목록을 다시 표시하지 않도록 응답 순서를 확인한다. 목록 저장 실패 시 성공으로 숨기지 않고 원래 목록을 유지한다. 표시 기록 저장 오류 때문에 분석 대기열을 일시 중지하지 않는다. 기존 사용자 중지·취소·다음 대기 영상은 보존한다.

## 영상별 오류 뒤 다음 영상 진행

다음 내부 검증 문장이 `DIAGNOSTIC_UNKNOWN`으로 보관되어 다음 영상까지 멈추던 문제를 수정한다.

- 요약 응답의 필수 항목·형식 오류, 장면 번호 중복, 요약 JSON·구간 요약 형식 오류.
- 큰 대사의 단계별 요약이 정해진 분량에 도달하지 못한 경우.
- 시간 정보가 있는 대사를 확보하지 못해 한국어 자막을 만들 수 없는 경우.

정확히 대응하는 프로그램 내부 검증 문장만 요약 형식·요약 분량·원어 확인 진단으로 분류한다. 원래 오류·부분 결과·미완료 개수는 유지하고, 결과와 종료 기록이 저장된 후 다음 독립 영상을 진행한다. 같은 실패 영상을 자동 재요청하거나 요약 실패 후 현재 영상의 번역을 강제로 계속하지 않는다.

이전 버전의 알 수 없는 진단도 원래 문장·단계·진단 대응이 확인되는 경우에만 영상별로 판정한다. 다른 오류가 덧붙은 문장·공유 오류 코드·원인·HTTP·실행 진단은 우선한다. 실제 서비스 실행 거절·인증·사용량·통신·시간 초과·공통 저장 오류·취소·사용자 일시 중지는 계속 보존한다. 실제 서비스 오류를 숨기거나 모든 분석 완료를 보장하는 변경은 아니다.
