# 1.9.30 · 정확 모드의 GPU 대기와 CPU 반복 계산 감소

2026-10-27. large-v3, beam 5·best-of 5, 원래 온도 재시도, 전체 입력 음성, 단어별 시각, 독립 발화 누락 검사·재확인 및 한국어 번역의 독립 검수를 유지한다. 실제 사용자 영상·음성·대사·요약·제공자 원시 응답을 열지 않았으며 실제 ASR·GPU 추론·번역이나 운영 작업·설정·프로세스를 변경하지 않는다. 검증에는 수치 배열·합성 구간·가짜 디코더·지연 게이트·별도 시험 저장소를 사용한다.

## 병목과 변경

이미 정확 모드에는 메모리가 확인된 CUDA 작업자 최대 2개, 한국어 초안과 검수의 최대 2요청 중첩, 80구간·12,000자 분할과 압축 검수 응답이 적용돼 있었다. 이를 처음 추가한 것처럼 주장하지 않는다. 배치 API는 일반 디코더의 fallback·무발화 옵션과 다를 수 있으므로 정확 모드에 대신 적용하지 않는다. 모델·검수 축소와 번역 묶음 확대도 하지 않는다.

기존 Python 스케줄러는 두 구간 중 원래 순서가 앞선 작업을 기다리는 동안, 뒤 작업이 먼저 끝나면 그 GPU 슬롯을 다시 채우지 못했다. 새 스케줄러는 완료된 작업부터 확인해 빈 슬롯을 채운다. 활성 디코더는 여전히 최대 2개이며, 앞 구간을 기다리는 완료 후속 구간은 최대 4개다. 제출했으나 아직 소비하지 않은 구간은 최대 5개로 제한한다. 입력 음성·옵션·소유 구간은 그대로이며 결과 공개와 CPU 검수·체크포인트는 원래 순서대로 수행한다. 소비자가 멈춰도 무제한으로 디코딩하지 않는다.

어느 순서에서든 오류를 관측한 뒤에는 새 작업을 제출하지 않는다. GPU 메모리 오류가 원래 처리 순서에 도달하면 이미 시작한 작업을 모두 정리하고 성공한 결과를 보존한다. 실패한 창만 같은 모델·옵션으로 직렬 1회 재처리하며, 재차 메모리 오류 또는 별도의 일반 오류는 숨기지 않는다. 이미 관측한 일반 오류를 메모리 재시도로 바꾸지 않는다. 취소·소비자 종료 시 이미 시작한 최대 2개의 정리 경계는 기존과 같다.

다음 두 CPU 함수는 후보 검색만 변경한다.

- `reconcile_window_boundaries`: 이전 창의 모든 단어를 매번 공백 제거·비교하는 대신 같은 텍스트 키를 가진 단어만 인덱스에서 찾는다. 실제 중복 관측 판정과 시각 허용 범위, 입력 순서, 누락 창 번호와 명시적 0의 차이를 유지한다.
- `prune_non_speech_artifacts`: 낮은 신뢰도의 구간마다 발화 전체를 순회하지 않고, 정렬 시작점과 누적 최대 끝점으로 기존의 엄격한 교집합 후보를 찾는다. NaN·무한대·bool·비정상 구간·일회성 iterator 등은 필요한 경우 기존 판정을 사용한다. 높은 신뢰도의 대사에는 발화 자료를 읽지 않는 기존 동작을 유지한다.

임시 FLAC은 이 PC 분석과 서버 전송 준비 모두 압축 수준 0을 사용한다. 빠른 모드의 기존 MP3는 유지한다. FLAC 수준은 무손실 인코딩의 압축 작업량이며 음성 인식 모델·샘플 범위·PCM을 줄이지 않는다. 파일은 커질 수 있어 LAN 전송이 항상 더 빨라진다고 보장하지 않는다.

GPU 메모리 자동 검사와 단일 작업자 조건은 유지한다. GPU 작업자가 1개인 환경에는 두 작업자 스케줄링의 효과가 없다. 기존 모델 다운로드 캐시와 검증된 번역 체크포인트도 유지하며 원문 인식 revision을 임의로 올려 전체 재인식을 유발하지 않는다.

## 업데이트 확인

이전 프로그램은 고정된 `main/update.json`을 캐시 우회 없이 읽었고, 배포 검증 도우미는 별도의 `?verified=` 주소를 읽었다. 따라서 실제 프로그램이 사용하는 CDN 캐시에 이전 버전이 남는 상황을 배포 검사만으로 놓칠 수 있었다. 공개 응답에서 `Cache-Control: max-age=300`을 확인했다. 다른 PC의 당시 응답 본문을 직접 확인한 것은 아니므로 해당 PC에서 캐시가 유일한 원인이었다고 단정하지 않는다.

새 구현은 기존 정규 URL을 먼저 엄격히 검증한 뒤 **내부 전송에만** 무작위 16바이트 `check` 키와 `Cache-Control: no-cache, no-store, max-age=0`, `Pragma: no-cache`를 붙인다. 외부 입력 URL·리다이렉트에 임의 쿼리를 허용하지 않는다. 버전 고정 EXE 주소·크기·해시·Windows 형식 검증도 그대로다. 공개 배포 검사에는 별도 우회 fetch만 쓰지 않고 실제 `fetchUpdateManifest()` 경로를 사용한다.

이 수정은 기존 1.9.28 실행 코드에 소급 적용되지 않는다. 그 버전이 계속 오래된 정보를 읽는다면 캐시 만료 뒤 다시 확인하거나 새 태그 EXE를 직접 내려받아야 한다. 요청 키와 헤더는 캐시 우회 조치이며 외부 CDN의 모든 동작을 보증하는 것은 아니다.
