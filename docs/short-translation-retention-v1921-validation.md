# 1.9.21 · 문자 수 차이로 검수 대사를 버리던 문제 수정

2026-10-21. 실제 실패는 기술 진단의 코드·개수·단계·실행 버전만 확인했다. 사용자 영상·음성·대사·줄거리·번역 서비스 원시 응답은 읽거나 재처리하지 않았다. 구현은 중립 합성 환승 안내·가짜 제공자·별도 저장소에서 검증한다. 운영 서버·설정·작업은 변경하지 않는다.

## 확인한 원인

최근 번역 복구는 마지막 원문 묶음까지 순회한 뒤 전체 2,215구간 중 2,206구간을 저장했다. 최종 9개 미승인은 `SUBTITLE_REVIEW_TOO_SHORT`로 1+6+1+1개씩 기록됐고, 종료 시 `SUBTITLE_CUES_PENDING`을 반환했다. 실행 버전은 서버 1.9.16·요청 PC 1.9.18이었다. 실제 영상 내용이 아니라 기술 코드와 개수만으로 확인한 사실이다.

`possibleSubtitleOmission`은 원문이 40자 이상이고 번역이 원문 문자 수의 15%보다 짧으면 의미 누락을 의심한다. 그러나 이 수치는 언어 간 압축·반복·숫자 표현 등을 고려한 의미 검증이 아니다. 기존 코드는 독립 검수가 명시적으로 승인한 대사도 이 비율에 걸리면 추가 요청하고, 여전히 짧으면 버렸다. 체크포인트 전체 재사용과 기존 부분 결과 보존도 같은 비율로 거부하는 경로가 있었다.

## 변경과 한계

- 문자 수 추정은 안내로만 남긴다. 정확 모드 초안의 `omissionCheckIndexes`는 기존 독립 원문 대조 검수로 전달하며, 검수에서 명시적으로 승인·수정한 유효한 한국어 대사는 원래 ID·시각으로 보관한다. 빠름·초고속도 유효한 번역을 보존하되 기존 1회 처리와 검수 표기를 유지한다.
- 길이만을 이유로 추가 요청·대사 삭제·격리된 빈 구간·복구 실패가 생기지 않는다. 실제 응답 누락과 외국어 분리·보완, 64회 공용 보완 한도 및 거절·인증·사용량·연결·시간 초과·구조·저장 오류 처리는 유지한다. 중단한 서비스 요청을 다시 호출하거나 우회하지 않는다.
- `SUBTITLE_LENGTH_REVIEW`는 고정 문구의 경고 이벤트다. 성공 결과의 오류 진단으로 저장하지 않는다. 경고 개수는 최종 보관된 완성/부분 자막으로 집계하며, 실패 시 이전 완성본 또는 기존·신규 대사의 합집합을 보존해도 실제 표시 내용과 일치한다. 경고에는 대사 내용이나 원시 응답을 넣지 않는다.
- 짧은 대사 하나 때문에 호환 체크포인트나 기존 부분 결과 전체를 거부하지 않는다. 번역 검증 버전은 8이며, 버전 7을 포함한 기존 검수 결과는 원문 지문·번호·ID·시각·프로필·검수 횟수·한국어·거절 검사를 유지한 채 재사용한다. 미승인 초안을 새로 승인한 것으로 바꾸지 않는다.
- 기존 원어 인식의 미확인 구간은 그대로다. 이 변경은 실제 사용자 영상의 9개 대사를 재번역하거나 의미 정확성을 측정한 결과가 아니다. 전체 번역 개수와 실제 의미의 정확성을 구분한다.
