# 1.9.9 · 번역 보완·보존과 요청별 예상 시간

2026-10-19. 검증 가능한 누락 응답과 짧은 번역에 대한 보완 범위를 늘리고, 실제 요청의 대기를 측정한다. 인식 모델·음성 범위·단어 시각·검수 횟수·최종 번역 검증 기준은 유지한다. 실제 사용자 영상·대사·이미지·외부 AI·GPU 추론은 검증에 사용하지 않는다.

## 중단 경로와 수정

기존 코드는 유효한 부분 응답에 누락 구간과 짧은 대사가 함께 있으면 보완 전에 중단했다. 정확 모드의 짧은 최종 검수는 작업 전체에서 한 번만 큰 묶음을 20개씩 다시 초안·검수했으며, 이미 작은 마지막 묶음이나 다음 묶음에서 같은 문제가 생기면 보완하지 못했다.

새 경로는 정상 cue를 보존하고 누락·짧은 cue만 최대 20개씩 한 번 요청한다. 원문의 index·ID·시각을 바꾸거나 구간을 합치지 않는다. 원문을 근거로 한 같은 검수 요청을 사용하며, 초안·검수·용어·한국어 본문·생략 의심 기준을 통과해야 저장한다. 정확 모드의 짧은 초안은 기존처럼 최종 검수를 반드시 거친다. 최종 검수에서 짧거나 누락된 구간만 다시 대조한다.

보완은 재귀 호출하지 않는다. 정상 형식의 검증 가능한 부분 응답만 대상이며, 잘못된 index·중복·외국어·용어 충돌·거절은 보완 대상으로 바꾸지 않는다. 누락·길이 보완을 합쳐 작업당 추가 요청은 최대 64회다. 제공자 거절·인증·사용량·503·시간 초과·연결 오류가 발생하면 추가 요청을 시작하지 않는다.

필수 인명·호칭을 모두 확인한 최종 응답의 **연속된 정상 앞부분**은 먼저 체크포인트로 보관한다. 미검수 초안·짧은 cue·빈 구간·뒤쪽만 있는 자막은 완료된 앞부분에 넣지 않는다. 부분 보관 뒤 최종 묶음을 저장할 때 중복을 제거한다. 보완 중 오류·취소·저장 실패가 발생하면 이전에 내구 저장한 앞부분을 유지한다. 재개는 원문 지문·index·ID·시각·품질·검수 횟수가 같은 체크포인트만 사용한다. 최종 수락·저장 계약이 같으므로 번역 검증 버전 6을 유지한다.

## 남은 시간

이미 저장한 번역 앞부분을 이번 실행의 처리 속도로 계산하지 않는다. 최근 표본이 8개를 넘겨도 실행 시작 기준을 유지해 모델 준비·검수·보완 시간이 추정에서 사라지지 않게 한다. 정상으로 끝난 초안·검수·보완 요청의 cue당 시간을 따로 측정해 묶음 크기가 다른 요청을 비교한다. 다음 초안이 미리 실행 중이어도 현재 저장을 막고 있는 검수·보완의 대기를 우선 표시한다.

새로 내구 저장한 두 번 이상의 진척과 15초 이상의 관측이 있어야 숫자를 계산한다. 실제 진척의 전체·최근 속도와 관측된 변동으로 현재 단계의 잔여 범위를 표시한다. 진행 중 요청이 평소보다 늦어지면 해당 요청의 초과 대기만 반영하며, 한 번의 지연을 모든 이후 구간에 그대로 곱하지 않는다.

같은 단계에서 관측된 요청 시간의 3배 이상이면서 최소 60초를 넘으면 응답 지연으로 표시한다. 아직 비교 자료가 없는 요청은 120초 기준을 사용한다. 마지막 진척이 120초 넘게 오래됐거나 응답 지연 상태면 숫자 예측을 제거한다. LAN·브라우저에서 흘러간 시간을 실제 대기에 더하고, 범위를 갱신하되 대기 시간을 초기화하지 않는다. 음성 인식·재검수의 단계 경계와 이후 단계 별도 안내를 유지한다.

범위는 관측에 근거한 추정이며 통계적 완료 보장 구간이 아니다. 전체 영상의 모든 단계나 다른 PC 대기까지 포함하지 않으며, 외부 서비스가 언제 응답할지는 예측하지 않는다.

## 실패 진단

기존에는 로컬 15분 제한이 먼저 발생하면 메모리의 stderr 기술 단서가 최종 기록에서 빠졌다. 이제 요청 실행의 종료 출처·경과시간·제한시간을 분리하고, 정형화된 도구 오류 줄과 오류 이벤트에서 확인한 재연결 횟수·HTTP 상태·네트워크 코드만 보관한다. 종료 직전의 기술 신호도 자식 프로세스를 정리한 뒤 반영한다.

관측한 HTTP 503이 로컬 제한 초과를 서비스 오류로 덮어쓰거나, 과거 거절의 판정 근거를 새로 추측하게 하지 않는다. 재연결은 도구 출력에서 관측한 횟수이며 프로그램이 새 번역을 요청하는 기능이 아니다. 원문·번역·프롬프트·전체 stderr·응답 본문·경로·인증 정보는 새 진단 필드에 저장하지 않는다. 임의 JSON·프롬프트 속 오류 문구, 범위를 벗어난 수치와 잘못된 횟수 조합은 버린다.

상세 화면·자막 안내·연결 PC 작업 로그에서 도구의 대기 제한 초과와 서비스 오류 응답을 구분한다. 체크포인트·LAN 결과·완료 저널·목록·진단 조회와 내보내기에도 허용한 기술 필드만 전달한다. 이전 버전이 저장하지 않은 기술 신호는 복원하지 않는다.

## 검증과 한계

합성 자료로 여러 묶음의 짧은 검수, 마지막 17개·1개, 누락과 짧은 번역 혼합, 올바른 앞부분 저장·중단·재개·ID·시각·인명 충돌, 64회 상한을 검사한다. 80개 전체가 길이 보완 대상인 합성 사례는 기존 초안·검수 재실행 10회에서 원래 초안·검수와 표적 검수 6회로 줄었다. 일부 한 cue만 문제인 경우 해당 cue만 추가 검수한다. 요청 수 비교이며 실제 제공자의 속도나 번역 정확도 측정은 아니다.

합성 시계로 저장분 제외, 최근 표본 제거 이후의 전체 기준, 불균등 묶음, 병렬 초안·현재 검수·보완, 실패·취소 요청 제외, 지연·오래된 진척·비정상 시간 수치와 LAN·브라우저 전달을 검사한다. 합성 자식 프로세스로 로컬 제한·서비스 오류·부모 취소·늦게 도착한 기술 stderr·무재시도·자식 정리를 검사한다.

브라우저 합성 화면에서 정상 처리의 잔여 범위와 검수 응답 지연·실제 대기시간을 확인했고 오류·경고 로그는 없었다. 운영 서버는 중지·교체하지 않았으며 기존 사용자 영상의 번역을 다시 요청하지 않았다. 서비스 무응답·거절 또는 반복되는 잘못된 응답까지 포함한 무조건 완료를 보장하지 않는다. 변경은 새 버전으로 시작한 작업부터 사용한다.

최종 검증:

- `node --test --test-concurrency=4 --test-timeout=60000 test/*.test.js`: **943개 통과**, 실패·취소·건너뛰기 0개, 약 57.2초.
- Windows EXE 빌드: **99,445,738바이트**, SHA-256 `ae38715b74458f5b47ac4a23c3a56af9ee6dba5a777021ea528806b0ca6773f7`. 버전 고정 업데이트 주소·실제 크기·해시·MZ 헤더를 대조했다.
- 최종 EXE의 독립 저장소·포트에서 웹 자산, 번역만 복구, 원래 ID·시각·이전 분석 버전, 영상 옆 SRT 저장, 기존 완성 자막·중지 대기열·진단 보존을 검사했다. 새 로컬 대기 제한 출처·경과시간·HTTP·재연결 수가 LAN→실제 EXE→목록·상세·진단에 보존됐다. 실행 중 단계의 ETA 전달과 완료 시 제거도 확인했다. 합성 요청만 사용했고 실제 음성 인식·제공자 호출은 없었다.
- 복사한 실제 **1.9.8→1.9.9 EXE** 업데이트가 같은 테스트 포트·저장소로 활성화됐으며, 결과·자막·대기열·암호화된 연결 설정·진단 등 **8개 파일이 바이트 단위로 유지**됐다. 이 검사가 만든 프로세스와 저장소만 사용하고 정리했다.
