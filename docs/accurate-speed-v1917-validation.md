# 1.9.17 · 정확 모드의 처리 겹침 복원과 음성 후처리 최적화

2026-10-21. 진단 확인은 허용된 기술 메타데이터만 읽었다. 사용자 영상·음성·전사·요약·제공자 원시 응답은 읽지 않았다. 구현 검증에는 중립 합성 전사와 수치 배열, 가짜 제공자, 별도 저장소와 시험 실행 파일을 사용한다. 실제 모델·번역 제공자를 호출하지 않고 운영 서버·작업·결과·설정을 변경하지 않는다.

## 확인한 병목과 측정의 한계

최근 74분 길이 영상의 전체 분석은 1,370.4초(22분 50초)였다. 초기 음성 인식 828.9초와 누락 재확인 307.8초를 합치면 전체의 약 82.9%다. 번역은 74.1초, 검수는 112.3초였다. 번역·검수만 두 배 빨라져도 나머지가 같다면 전체 단축은 약 1.07배에 그친다. 최근 정확 모드 작업 다섯 건은 이미 large-v3, CUDA int8_float16, GPU 작업자 2개를 사용했고 메모리 부족에 따른 대체 처리는 기록되지 않았다.

진행 중인 별도 번역 작업의 정상 6묶음에서는 변경 전에도 초안과 검수가 겹쳤다. 초안 단계 시간 합계 144.504초, 검수 단계 합계 99.215초, 교집합 67.633초, 전체 구간 벽시계 시간 176.378초였다. 단계 시간 합계를 순차 처리 시간이라고 설명하지 않는다. 문제는 누락 이력이 생긴 뒤 정상 묶음으로 돌아와도 선행 처리를 영구적으로 막는 조건이었다.

이 수치는 기술 기록의 관측값이며 같은 영상의 변경 전후 비교가 아니다. 개인 파일명·경로·작업 식별자·발생 시각은 공개 문서에 포함하지 않는다. 실제 전체 분석 또는 음성 인식에서 추가 2배 가속을 입증한 결과는 없다.

## 변경과 유지한 조건

- 번역 선행 처리의 조건에서 과거 누락을 나타내는 `gapSeen`만 제거했다. 누락 결과의 저장과 미완료 판정에는 이 변수를 그대로 사용한다. 현재 묶음 복구 시 선행 초안을 폐기하고 정상 묶음의 저장 후 재개한다. 선행 초안은 최대 하나, 검수는 순차 처리하며 고유명사와 이전 번역 문맥을 검증한다.
- 정확 모드의 묶음 크기 80구간·12,000자, 동일 모델·프롬프트 버전 7·검수 횟수 2회, 보완 한도 64회, 원문 번호·ID·시간 대응, 체크포인트 호환성은 유지한다. 미승인 구간을 자동 승인하지 않는다. 거절·인증·사용량·503·시간 초과·연결 오류·취소를 재시도로 바꾸지 않는다.
- `very_quiet_stationary_noise`는 기존 peak 계산 직후 같은 최종 임계값을 넘으면 즉시 False를 반환한다. peak는 이후 감소하지 않으므로 남은 샘플을 계산해도 이 분류를 바꿀 수 없다. 임계값과 합산 순서, 실제 음성 인식·누락 확인·정렬 경로는 바꾸지 않는다.
- large-v3, 탐색 설정, 전체 입력 음성, 독립 누락 재확인, 단어 시각, 번역 독립 검수와 완료 조건을 줄이지 않는다. 실제 제공자 또는 GPU 작업의 처리 속도는 이번 합성 검사로 보장하지 않는다.

## 합성 검사

- 신규 번역 검사 12개: 저장한 V2 부분 자막, 이전 미승인 번호 유지, 현재 묶음 복구 시 선행 작업 종료, 정상 저장 이후 겹침 재개, 고유명사 변경, 원문 번호·ID·시간, 취소와 각 서비스 오류의 즉시 중단을 확인한다. 실제로 시작한 초안과 검수의 겹침은 명시적 게이트로 확인한다.
- 같은 합성 1,120구간·29개 요청·검수 2회와 요청당 짧은 지연을 사용한 세 번의 측정은 순차 처리 대비 1.26–1.44배였다. 파일 입출력과 가짜 요청 지연이 포함된 검사이며 실제 번역·ASR·전체 영상의 속도 향상 비율이 아니다. 배속 수치를 통과 조건으로 쓰지 않고 요청 수·결과·동시 처리 제한을 검증한다.
- 신규 Python 차등 검사 10개를 Node 래퍼로 실행한다. 무작위 수치 배열 400개, 임계값 경계, 음수·비유한 수·패딩·짧은 입력 등에서 이전 구현과 분류가 같은지 확인하고 실제 읽기 횟수로 조기 종료를 검사한다.
- 수치 배열만 사용한 CPU 측정에서 첫 샘플로 판정 가능한 30초 상당 배열은 약 0.213초에서 7µs, 90초는 약 0.767초에서 2µs였다. 마지막에 판정되는 배열과 무음 배열은 기존과 비슷했다. 이는 한 후처리 함수의 특수 입력 측정이며 전체 ASR 가속 비율로 사용할 수 없다.
