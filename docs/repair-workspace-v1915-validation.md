# 1.9.15 · 실패 영상 확인과 복구 대기열

2026-10-21. 모든 구현 검증은 중립 합성 결과·별도 저장소·직접 복사한 시험 프로세스에서 수행한다. 실제 사용자 영상·음성·대사·이미지·모델·번역 제공자를 사용하지 않는다. 운영 서버·작업·결과·연결 설정은 변경하지 않는다.

## 변경

- 작업 화면은 실패·미완료한 각 영상의 이름·경로·실패 단계·이유·검증된 한국어 자막 N/M을 표시한다. 진행 중인 배치의 앞선 실패도 현재 영상·단계·진행률과 분리한다. 처음 4개 이후는 펼칠 수 있다. 저장된 결과가 있으면 명시적 상세 보기만 제공한다.
- 완성 자막을 보존한 최신 재번역 실패, 번역 완료·파일 저장 실패, 원어 인식 확인 안내를 구분한다. 알려지지 않은 자막 수나 과거에 저장되지 않은 실패 영상명을 추측하지 않는다. 오류 본문의 후속 줄·자격 정보는 축약·정리하며 DOM의 텍스트로 표시한다.
- 결과 파일 저장 실패로 해당 결과가 없더라도 새 작업은 종료 전 `failedFile`, `failedFilePath`, `failedStage`를 보존한다. 바뀌지 않은 실패 목록의 폴링은 DOM과 키보드 포커스·펼침 상태를 유지한다.
- `POST /api/analysis/queue/repair`는 신뢰한 저장 결과 ID와 `analysis` / `translation-only` 작업 종류를 받는다. 진행 중 작업이 있거나 기존 대기가 있으면 UI는 직접 복구 대신 이 경로로 대기를 추가한다. 현재 작업은 대기 등록 응답으로 교체하지 않는다. 비어 있는 유휴 상태의 기존 직접 복구는 유지한다.
- 대기 목록은 전체 복구·번역 전용 복구를 구분한다. 같은 파일 경로의 진행·대기는 결과 ID와 작업 종류가 달라도 중복 추가하거나 작업 종류를 바꾸지 않는다. 기존 순서 이동·제거·대기 비우기와 현재 작업 보호를 유지한다.
- 대기열에는 허용된 설정·작업 종류·원본 결과 ID·파일 크기/수정 시각·시도 ID만 보관한다. 연결 코드·전사·원본 결과 객체를 복사하지 않는다. 실행 시 신뢰한 저장 결과를 다시 읽고 파일 동일성을 확인한다. 번역 전용 복구는 FFmpeg·음성 인식 도구를 요구하거나 전체 분석으로 바꾸지 않는다.
- 오류·중지·저장 실패는 후속 복구 대기를 일시 중지한다. 추가만으로 기존 일시 중지를 해제하지 않으며 제공자 거절·인증·사용량·시간 초과·연결 오류를 자동 재요청하지 않는다. 재시작 시 정확히 저장된 완료 결과만 소비하고 처리 중이던 시도를 몰래 반복하지 않는다.
- 재시작 후 중단된 대기 복구의 이전 작업 기록을 새 시도와 연결한다. 이전 기록은 새 대기 커서를 바꾸기 전에 내구성 있게 정리하므로 중단 기록이 누적되지 않는다. 기존 방식의 대기 비우기도 현재 복구의 재시작 정보를 제거하지 않는다. 저장 도중 장애는 작업 호출 전에 멈춘다.
