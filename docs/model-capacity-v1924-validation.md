# 1.9.24 · 저사용량 모델 지정과 명확한 혼잡 응답 복구

2026-10-23. 사용자 영상·음성·대사·원시 번역 응답을 읽거나 실제 Codex 추론·ASR·번역을 호출하지 않았다. 중립 합성 원문·가짜 CLI·별도 저장소로 검증했다. 운영 프로그램·작업·연결 설정을 중지·교체·재시작하지 않는다.

## 모델과 사용량

기존 프로그램은 `--ignore-user-config`를 사용하면서 모델을 지정하지 않아 Codex의 기본 추천 모델에 의존했다. 사용자 설정의 모델을 그대로 사용한다는 보장도, 과거 요청의 모델 기록도 없었다. 이제 모든 요약·번역·독립 검수 요청에 `--model gpt-6-luna`, `model_reasoning_effort="low"`, `service_tier="default"`, `--disable fast_mode`를 전달한다. 명시적인 `VIDEORANDOM_CODEX_MODEL` 및 유효한 추론 환경변수 재정의는 유지하며 모델을 자동으로 상향하거나 혼잡 후 다른 모델로 전환하지 않는다.

현재 [공식 Codex 가격표](https://learn.chatgpt.com/docs/pricing)의 Standard 크레딧 단가는 다음과 같다. API 달러 가격으로 구독 사용량을 추산하지 않았다.

| 모델 | 입력 100만 토큰 | 출력 100만 토큰 |
| --- | ---: | ---: |
| GPT-6 Luna | 2.5크레딧 | 12.5크레딧 |
| GPT-5.6 Luna | 5크레딧 | 30크레딧 |
| GPT-6.1 Sol | 50크레딧 | 250크레딧 |

같은 토큰 수 기준으로 GPT-6 Luna는 Sol의 입력·출력 단가 각각 1/20이며 5.6 Luna보다 저렴하다. Light/Low가 실제로 생성할 추론 토큰 수나 번역 품질·총사용량을 고정하지는 않는다. 실제 번역은 토큰을 사용하며 구독의 포함 사용량 한도는 이 단가 비율만으로 정해지지 않는다. [공식 모델 안내](https://learn.chatgpt.com/docs/models)는 Luna를 명확하고 반복적인 변환·추출·구조화 작업에 권장한다. 실제 사용자 영상의 번역 품질 비교 측정은 수행하지 않았다.

## 혼잡 처리

- 신뢰된 CLI 오류 이벤트·오류 출력의 시작 부분에 나타난 정확한 `Selected model is at capacity` 또는 오류 필드의 문서화된 `server_is_overloaded`만 모델 혼잡으로 식별한다. 원문·대사·임의 JSON·일반 출력의 단어를 혼잡 증거로 검색하지 않는다.
- 혼잡 전용 진단 `PROVIDER_CAPACITY`와 안전한 요청 모델·추론·Standard 설정을 기록한다. 기존의 모든 CLI 오류가 `Codex 요약 실패`로 감싸지더라도 단계·혼잡 원인·모델 설정을 확인할 수 있다. 기록은 요청 설정이며 원격 서버가 실제 처리한 내부 모델을 별도로 검증했다는 뜻은 아니다.
- 같은 구간을 30초·60초에 최대 5초의 양의 무작위 지연을 더해 재요청한다. 신뢰된 오류 헤더에서 읽은 초·HTTP 날짜 형태 `Retry-After`는 최소 대기로 존중한다. 지나치게 긴 값·잘못된 값은 짧게 잘라 재시도하지 않는다. [공식 오류 복구 안내](https://developers.openai.com/api/docs/guides/error-codes)에 따른 제한된 대기이며 API키 방식으로 바꾸지 않는다.
- 요청당 2회·한 영상 작업 전체 4회·첫 혼잡부터 10분의 한도를 병렬 초안·검수·요약이 공유한다. 회복 가능한 혼잡은 즉시 형제 작업을 취소하지 않는다. 실제 하드 오류나 한도 소진 시 기존 오류 전파·취소·저장 정책을 유지한다. 장시간 서비스 장애가 계속되면 결과·체크포인트를 보관하고 대기를 유지한다. 무제한 반복하거나 서비스를 우회하지 않는다.
- 인증·사용량 한도·거절·일반 503·시간 초과·연결·내부 형식·저장 오류를 재시도하지 않는다. 명시된 다른 실패 증거는 혼잡보다 우선한다. 사용자 취소는 대기 타이머를 즉시 해제하고 새 요청을 시작하지 않는다.
- 낮은 추론 모델로 바꾸어도 정확 모드의 독립 원문 대조 검수·원래 번호·ID·시간·부분 SRT·저장 검증은 유지한다. 기존 승인된 체크포인트의 동일 원문·프로필·검수 증거를 그대로 확인해 재사용한다. 모델 변경만으로 과거 검수 결과를 버리거나 원어 인식 모델을 바꾸지 않는다.
- 요청 모델은 설정·결과 상세·진단 화면에 표시한다. LAN 전송과 목록 요약은 허용된 필드만 전달하며 번역 복구는 과거 요약의 모델 정보를 보존한다. 이전에 기록되지 않은 모델은 추정하지 않는다.

## 검증

- 새 합성 회귀 **58개**는 명시 모델·Low·Standard 인수, 환경변수 검증, 안전한 모델 기록, 정확한 혼잡 이벤트·기계 코드·표준 오류 출력, 인증·한도·거절·시간 초과·연결 증거 우선, 요청/작업별 공유 한도, 30초·60초 대기와 서버 대기 지시, 취소 및 타이머 정리를 확인한다.
- 합성 161구간에서 초안·독립 검수 각각의 일시적 혼잡을 재현했다. 저장된 80구간을 유지하고 같은 묶음만 다시 요청해 마지막 구간까지 원래 ID·시각으로 완료했다. 혼잡이 지속되는 경우 기존 체크포인트를 보관하고 새 명시적 복구가 남은 번호만 요청했다. 401구간의 선행 초안 혼잡에서도 현재 검수를 불필요하게 취소하지 않았다. 요약의 혼잡도 같은 정책으로 회복했다.
- 모델 기록의 UI 회귀는 요청 모델만 표시하며 검증하지 않은 실제 모델명·임의 필드는 노출하지 않는 것을 확인한다. 기존 개인 내용 비노출 검사도 요청 모델·추론·Standard라는 기술 필드만 추가 허용하고 원문·번역·프롬프트·경로·임의 제공자 출력을 계속 거부한다.
