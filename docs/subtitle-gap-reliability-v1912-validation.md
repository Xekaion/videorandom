# 1.9.12 · 개별 자막 오류 격리와 완료 상태 구분

2026-10-19. 기술 메타데이터와 합성 자료로 반복되는 일부 완료를 조사했다. 실제 영상·음성·이미지·대사 본문·제공자 응답 본문은 검증에 사용하지 않는다. 운영 분석 서버를 중지하거나 교체하지 않는다.

## 확인한 원인

운영 서버의 BBAN-521 작업은 1.9.10 정확 모드로 원문 1,856구간을 확보했고 전체 음성 처리 증거가 있었다. 1,488구간을 번역·검수한 뒤 1,489–1,490번의 한 번 보완에서도 `SUBTITLE_REVIEW_TOO_SHORT`가 발생해 작업 전체가 종료됐다. 번역 368구간은 완료되지 않았고 마지막 보관 번역은 약 85분, 원문은 약 140분이었다. 이는 해당 두 구간의 실제 의미를 확인한 결과가 아니라 기록된 길이 검사와 구간 수·시각의 대조다.

다른 최근 작업은 확보한 원문 대사 129/129·121/121구간의 번역을 끝냈지만 원문 완전성 확인이 남았고, 요청 PC가 별도로 `SIDECAR_SAVE_FAILED`를 보고했다. 과거 저장 오류 기록에는 파일 시스템 원인 코드가 없어 권한·경로·파일 충돌 중 무엇인지는 확정하지 않는다. 번역 완료, 원어 확인, 영상 폴더 저장 실패는 별도 상태다.

## 처리 변경

정상으로 반환되어 본문·번호·용어 검증을 통과한 응답의 짧은 대사는 최대 20개씩 한 번 보완한다. 정확 모드의 초안은 계속 전체 원문 대조 검수를 거친다. 빠름·초고속의 최종 1회 번역에도 같은 한 번 보완을 적용한다. 작업당 추가 요청 64회 상한과 최종 본문 수락 기준은 유지한다.

그 뒤에도 길이 검사를 통과하지 못한 대사는 승인하지 않고 확인 대상으로 남긴다. 나머지 정상 대사와 다음 묶음은 계속 번역한다. 모든 나머지 구간을 처리한 뒤 `SUBTITLE_CUES_PENDING`으로 미완료 개수와 보관 개수를 알린다. 서비스 거절·인증·사용량·503·시간 초과·연결 오류·잘못된 형식이나 인명 충돌은 이 경로로 바꾸지 않으며 추가 요청을 시작하지 않는다.

앞부분만 보관할 수 있던 V1은 유지한다. 중간에 미완료 구간이 있는 결과는 V2 진행 기록의 `cueIndexes`로 보관한 각 대사를 원문의 정확한 번호·ID·시작·종료 시각과 대응시킨다. 원문 지문과 품질·검수 횟수도 확인한다. 중복·정렬 오류·범위 밖 번호·ID/시간 불일치·틀린 완료 선언은 거절한다. 확인 대상에 대사를 만들어 넣거나 뒤쪽 번역을 앞쪽으로 이동하지 않는다.

체크포인트 재개는 이미 승인한 구간을 제외한 번호만 요청한다. 같은 원문·품질의 기록은 공유 번호의 본문과 용어가 충돌하지 않을 때만 합친다. 충돌하는 후보는 전체를 합치지 않고 이전 증거를 보존한다. 200개 용어를 넘겨 임의 삭제하지 않는다. 외부 응답당 용어 100개 제한과 내부 조립의 200개 상한을 분리해, 정상 보완 결과의 용어가 합계 101개라는 이유로 중단되던 오류도 수정했다.

번역 복구에서 실패하더라도 기존 뒤쪽 구간과 새로 검증한 앞쪽 구간을 함께 보존한다. 이 보관 때문에 캐시의 검수 횟수를 올리거나 작업 전체를 완료로 표시하지 않는다. 선행 초안은 구멍을 확인한 뒤 사용하지 않으며 이미 시작한 자식은 정리한다.

## 저장·화면·진단

부분 SRT/VTT는 V2 대응을 검증한 뒤 실제 구간만 원래 시각으로 내보낸다. 영상 옆 `.ko.partial.srt` 자동 저장과 기존 완성 자막 보호를 유지한다. LAN은 `sparse-subtitles-v1`을 광고하며 새 클라이언트는 이를 확인한다. V2 표시와 복구에는 양쪽 PC의 1.9.12 이상 실행이 필요하다.

목록·상세·작업 상태는 번역 N/N 완료와 원어 확인 필요를 구분한다. N/N은 확보한 원문 대사의 번역 수이며 영상의 모든 발화가 인식됐다는 보증이 아니다. 자막 파일 저장 실패는 번역 실패와 따로 표시한다. 정확한 원문과 대응하는 저장 자막으로 개수를 계산하고, 명시적인 번역 미완료 표시는 완료로 올리지 않는다.

저장 오류의 `systemCode`와 허용된 `causeCode`만 기술 기록으로 전달한다. 예외 본문·스택·프롬프트·자막·비밀번호·임의 경로를 새 진단 필드에 넣지 않는다. 이전 기록에서 사라진 원인 코드는 복원하지 않는다.

## 검증 범위

신규 합성 회귀는 1,856구간 중 두 구간을 남긴 1,854구간의 끝까지 보관, 두 구간만 재개, 뒤쪽 서비스 오류 후 정상 구간 보존, 빠름·초고속의 제한 보완, V1 호환·V2 대응·잘못된 기록 거절·용어 상한·호환 체크포인트 병합과 충돌·취소·선행 요청 정리를 확인한다. 실제 제공자나 사용자 자료는 호출하지 않는다.

UI 합성 검사는 중간 구멍 뒤의 번역이 원래 대사에 표시되는지, 잘못된 대응을 숨기는지, 부분 다운로드 요청과 번역 완료/원어 확인/저장 실패의 구분을 확인한다. LAN과 실제 EXE의 별도 저장소·포트에서 부분 SRT의 뒤쪽 시각과 기존 자막 보존을 검증한다. 최종 전체 검사와 EXE 확인 결과는 아래에 기록한다.

## 검사 결과

- 전체 Node 검사 1,130개 통과, 실패·생략 0개(64.98초). 로그: `artifacts/test-v1912-full-final.log`.
- 마지막 저장 상태 갱신 수정 후 전체 UI 검사 165개 재검사 통과(1.05초). 로그: `artifacts/test-v1912-all-ui-final.log`. 목록·상세·종료 작업 대시보드가 저장 성공↔실패 전환을 함께 반영하고 기존 원문·번역·지문·번호 매핑은 교체하지 않는다.
- 핵심 번역 합성 회귀 30개, 부분 자막·LAN·파일 보존 회귀 38개, 상태·안전 진단 회귀를 포함한다. 실제 사용자 영상의 번역 완료율이나 처리 속도를 측정한 결과는 아니다.
- Windows EXE 빌드 성공. 크기 99,480,938바이트, SHA-256 `ab8151211afac825dc80692b89a369444c70ffc208250591c06272b1f3aae219`. 업데이트 manifest와 정확히 일치한다. 빌드의 `open/xdg-open` 경고는 Windows 대상에서 사용하지 않는 Linux 실행 파일에 관한 기존 경고다.

EXE 검사는 미사용 포트 3264·3266·3286, 별도 임시 저장소와 직접 복사한 실행 파일에 한정했다. 경로·PID·저장소 ID를 확인한 시험 프로세스만 정리했다. 실제 음성 모델·외부 번역 요청·운영 결과 변경·운영 서버 재실행은 하지 않았다. 확인 당시 운영 서버는 계속 1.9.10이었다. 이 결과로 기존 BBAN-521의 미완료 구간이 실제로 복구됐다고 주장하지 않는다.
