# 1.9.31 · 업데이트 조회 원본과 실패 표시

2026-10-27. 1.9.30의 정확 모드 성능 개선은 그대로 포함한다. 이번 추가 변경은 실제 배포 확인에서 재현한 CDN 캐시와 조회 실패 시 최신성 표시를 보완한다.

## 실제 관측과 변경

1.9.30의 main·태그가 `46942211ad101e279bc0ae79e8d60ce56219cdb9`로 게시된 뒤, 실제 `fetchUpdateManifest()`가 요청 키와 캐시 무효화 헤더를 사용했음에도 raw CDN에서 1.9.29를 받았다. 같은 시점 GitHub Contents API는 1.9.30 manifest를 반환했다. `artifacts/public-v1930.log`에 불일치 근거를 보관했다. 기존 v1.9.30 태그를 덮어쓰지 않고 추가 버전으로 수정한다.

GitHub의 [공식 Contents API 문서](https://docs.github.com/en/rest/repos/contents?apiVersion=2022-11-28#get-repository-content)는 공개 저장소의 파일을 인증 없이 읽고 `application/vnd.github.raw+json`으로 원문을 받을 수 있다고 설명한다. 새 구현은 이 원문 모드에서 고정된 `Xekaion/videorandom` 저장소·`update.json` 경로·`main` 참조만 읽는다. 인증 정보나 API 키를 추가하지 않는다.

공개 함수의 허용 입력 URL은 여전히 기존 canonical raw main 주소 하나다. 이를 검증한 뒤 내부 전송만 고정 API URL로 바꾸고 무작위 32자리 16진수 요청 키, no-cache/no-store 헤더와 고정 API 버전을 붙인다. API 응답의 `download_url`이나 외부 URL을 따라가지 않는다. API 주소 자체·임의 쿼리·다른 저장소도 외부 입력·리다이렉트로 허용하지 않는다.

본문 16KiB·30초·인코딩 제한, manifest의 정확한 구조, 버전 고정 EXE URL·크기·SHA-256·Windows 형식 검증을 유지한다. 403·429·304·5xx·인증/사용량 오류 봉투·잘못된 JSON은 확인 실패로 처리하며 오래된 raw CDN으로 조용히 대체하지 않는다. 실패는 기존 확인 시각을 갱신하거나 다운로드를 시작하지 않는다.

실패 후 이전에 확인한 버전 값이 남아 있어도 화면은 이를 ‘최신’ 대신 ‘마지막 확인’으로 표시한다. 정상 확인이 다시 성공하면 일반 최신 버전 표시로 돌아간다. 자동 확인 주기·중복 잠금·작업 종료 후 업데이트 정책은 바꾸지 않는다.

구버전의 코드는 이 변경을 아직 포함하지 않는다. 계속 1.9.28 등을 최신이라고 표시한다면 캐시 만료 후 재확인하거나 새 태그 EXE를 한 번 직접 받아 실행해야 한다. 외부 API에도 캐시·사용량 제한·장애가 있을 수 있으며, 실패 시 최신성을 확인한 것으로 표시하지 않는다.

## 검증

- 신규 전송·실패 회귀 28개는 고정 API 원문, 임의 URL·쿼리·리다이렉트·오류 봉투 거절, 자산 주소 불변, 이전 정상 상태 뒤 403/429/304에서 확인 시각·다운로드가 그대로임을 검사한다.
- 기존 캐시·updater 검사와 함께 73개를 통과했다. 실제 사용자 미디어·ASR·번역·운영 서버·설정·업데이트 실행은 건드리지 않는다.
- 신규 UI 회귀 12개와 기존 UI 검사 20개를 통과했다. 이전 정상 조회 뒤 403·429·503, 서버 오류 snapshot, 첫 확인 실패, 실패 뒤 정상 재확인에서 ‘마지막 확인’·오류 안내·재확인 버튼과 정상 복원을 검사한다.
- 새 함수로 공개 manifest를 읽어 1.9.30을 확인한 뒤 배포를 준비했다. 최종 공개 배포도 별도 우회 fetch 대신 실제 `fetchUpdateManifest()` 경로와 고정 태그 파일을 검사한다.

- 최종 전체 Node 검사 **2,739개 중 2,738개 통과**, 실패·취소 0개, **57.20초**. Windows 심볼릭 링크 권한이 필요한 기존 검사 1개만 생략했다. 정확 모드의 스케줄링·후처리·무손실 오디오 검사도 포함한다. `artifacts/test-v1931-final.log`.
- Windows EXE 빌드·manifest 검증 통과. **99,703,736바이트**, SHA-256 `057feddfcae15859a32bb6a6d5546f641c24a666830b9845e2be50f7c054e18e`. 기존 Windows 미사용 `open/xdg-open` 경고만 남았다. `artifacts/build-v1931.log`.
- 최종 EXE를 소유한 별도 포트·저장소에서 실행해 UI 자산, 원문 재인식 표시, 자막 전용 복구, 원래 시각·부분 SRT 저장·기존 자막, 원격 접수·공간·진단·대기열과 사용자 중지 보존을 확인했다. 실제 미디어 처리·ASR·제공자 요청 없이 통과했다. `artifacts/package-v1931.log`.
- 실제 Windows EXE와 PowerShell 도우미로 **1.9.30→1.9.31 인계**와 의도적 새 실행 실패 시 **1.9.30 복원**을 통과했다(전체 **100.53초**). 연결 설정·결과·SRT·대기열·진단·접수 기록 등 **11개 시험 파일의 바이트를 보존**했다. 소유한 별도 시험 프로세스·저장소만 사용했다. `artifacts/update-handoff-v1931.log`.

공개 배포 확인 도우미는 실제 `fetchUpdateManifest()`·`validateManifest()` 결과를 로컬 manifest와 비교하고 v1.9.31 태그의 manifest·EXE 크기를 별도로 검사한다. 출력은 `artifacts/public-v1931.log`에 보관한다. 운영 중 프로그램을 자동으로 교체하거나 다시 실행하는 검사는 아니다.

정확 모드 개선의 변경·측정 한계는 [1.9.30 보고서](accurate-speed-v1930-validation.md)에 있다. 실제 영상 전체가 몇 배 빨라졌다는 실측은 없으며 운영 중인 구버전 작업은 기존 코드로 처리한다. 기존 설정·결과·자막·사용자 중지는 보존한다.
