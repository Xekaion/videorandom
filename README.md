## 🌌 Project Overview (프로젝트 소개)

> **"방대한 외장하드 속 영상들을 0.1초 만에 훑고, 미래지향적인 사이버 룰렛으로 오늘의 감상 영상을 골라보세요!"**

**Video Roulette**는 개인용 대용량 외장하드디스크 및 로컬 스토리지에 보관된 수많은 영상 파일들을 **비동기식 너비 우선 탐색(BFS)** 알고리즘으로 빠르게 스캔하여, 화려한 SF 영화 감성의 인터페이스를 통해 랜덤으로 영상을 추출해 주는 **오프라인 윈도우 단독 실행 프로그램**입니다.

## ✨ Premium Features (핵심 기능)

### 📚 전체 뽑기 · 재생 기록

프로그램을 실행하면 **전체 영상 기록**에 이 PC에서 저장한 뽑기와 기본 플레이어 재생 실행 기록이 표시됩니다. 스캔하기 전에도 볼 수 있으며, 파일명·경로 검색과 기록 종류 필터, 페이지 이동을 지원합니다. 같은 영상을 여러 번 뽑거나 재생한 기록도 날짜와 함께 각각 남습니다. 표시할 때만 50개씩 나누며 저장 개수 제한은 없습니다. 재생 기록은 플레이어를 실행한 기록으로, 영상을 끝까지 시청했는지는 나타내지 않습니다.

* **CSV 전체 내보내기**: 화면의 검색·종류 필터·페이지에 관계없이 모든 기록을 내보냅니다. Excel에서 파일명, 전체 경로, 기록 종류, 날짜와 시각을 확인할 수 있습니다.
* **JSON 백업·가져오기**: 기록을 백업하고 다른 설치에서 다시 가져올 수 있습니다. 같은 백업을 다시 가져와도 기록을 중복해서 추가하지 않습니다.
* **기존 기록 이관**: 예전 버전은 브라우저의 `pick_history`에 최근 5개만 저장하고 그 이전 기록을 지웠습니다. 같은 브라우저 프로필에서 같은 주소(`http://localhost:3000`)로 새 버전을 열면 남아 있는 기록을 자동으로 가져옵니다. 예전 기록에는 날짜가 없으므로 **날짜 미상**으로 표시합니다. 이미 잘린 기록을 프로그램 데이터만으로 복원할 수는 없습니다.
* **Windows 최근 영상 확인**: 버튼을 누르면 Windows 최근 항목 폴더에 남아 있는 영상 바로가기를 참고 기록으로 가져옵니다. 다른 프로그램에서 연 영상도 섞일 수 있으며, 표시된 시각은 바로가기의 수정 시각입니다. VideoRandom에서 뽑거나 재생했다는 증거 또는 전체 과거 기록이 아닙니다.

기록 파일은 기본적으로 `%LOCALAPPDATA%\VideoRandom\catalog\history\events.jsonl`에 보관됩니다. 브라우저 기록을 지우거나 실행 파일을 업데이트해도 이 파일은 유지됩니다. Windows 사용자 계정이 바뀌면 저장 폴더도 달라집니다.

### 🔄 새 버전 실행과 기존 프로그램

화면 상단의 버전 표시로 현재 실행 중인 버전을 확인할 수 있습니다. **직접 내려받은 실행 파일로 교체할 때는 기존 VideoRandom을 종료한 뒤 새 파일을 실행하세요.** 1.7.0부터 같은 저장 폴더를 사용하는 프로그램의 중복 실행을 막습니다. 이미 실행 중인 같은 버전은 기존 화면을 열고, 발견한 구버전은 종료 후 새 버전을 다시 실행하도록 안내합니다. 다른 프로그램이 3000번 포트를 사용하면 가능한 다른 로컬 주소를 사용합니다. 이 화면 주소가 바뀌어도 다른 PC의 분석 서버 주소를 바꿀 필요는 없습니다. 이전 브라우저의 5개 기록을 이관하려면 새 실행 파일을 이전과 같은 브라우저의 `http://localhost:3000`에서 여세요. 화면이 오래된 상태로 남아 있으면 `Ctrl+F5`로 새로고침하세요.

### 📝 1.9.3 · 번역 응답에서 빠진 자막 구간 보완

* **묶음의 개수와 번호를 명확히 요청**: 번역 서비스에 이번 묶음의 정확한 자막 개수와 허용 번호를 전달하고, 응답 순서가 달라도 원문 번호에 맞춰 정리합니다. 원문 대사와 자막 시작·종료 시각은 유지합니다.
* **정상 응답의 빠진 번호만 보완**: 비어 있지 않고 나머지 검증을 통과한 응답에서 일부 번호만 빠졌다면, 누락된 번호만 최대 20개씩 한 차례 요청합니다. 초안에서 빠진 대사는 초안을 보완한 뒤 정확 모드에서는 기존 방식으로 전체 묶음을 검수하고, 검수 응답에서 빠진 대사는 해당 번호만 검수합니다. 중복·범위 밖 번호, 잘못된 번역·용어, 빈 응답, 요청 거절·서비스 오류는 완료로 처리하지 않습니다.
* **검증된 앞부분 이어 사용**: 이전 번역 체크포인트의 원문·번호·시각·품질 설정·용어를 다시 확인하고, 유효한 검수 구간은 새 번역 버전에서도 이어 사용합니다. 기본 80구간 묶음과 기존 검수 횟수, 원어 음성 인식 방식은 유지합니다. 누락 보완 요청은 묶음의 각 단계에서 최대 4회, 한 번의 번역 작업에서 총 64회로 제한하며 재귀적으로 반복하지 않습니다.

**Windows EXE 1.9.0 이상은 매번 GitHub에서 다시 내려받을 필요가 없습니다.** 상단 **업데이트 → 새 버전 확인**에서 다운로드·적용할 수 있고, 자동 업데이트를 켜 두면 새 버전을 확인해 작업이 끝난 뒤 적용합니다. 이 버튼은 현재 PC의 프로그램에 적용됩니다. `분석서버_시작.bat`으로 실행한 Node 서버에는 자동 소스 교체가 없으므로 새 코드를 받아 다시 실행해야 합니다. 서버 주소·연결 코드·저장된 결과는 기존 데이터 폴더를 그대로 사용하면 유지됩니다.

번역 처리를 맡는 PC에서 새 버전을 실행한 뒤 새 분석 또는 **남은 한국어 자막 번역 계속**을 요청해야 변경이 적용됩니다. 이미 저장된 미번역 구간을 자동으로 완료 처리하지 않으며, 기존 사용자 영상의 번역이 끝났다는 의미도 아닙니다. [번역 묶음 누락 보완 검증](docs/subtitle-batch-recovery-validation.md)에 적용 조건과 검증 범위를 정리합니다.

### 🧾 1.9.2 · 연결 PC의 작업·오류를 분석 서버에서 확인

**영상 목록 → 연결 PC · 작업 로그**에서 파일명·PC 이름·작업 ID·오류 코드로 검색하고 오류·주의·진행 기록을 나눠 볼 수 있습니다. 패널을 열어 둔 동안 5초마다 갱신하며, 이전 기록 더 보기와 전체 JSONL 내보내기를 지원합니다. 기록은 이 PC의 데이터 폴더에 저장하므로 프로그램 종료·업데이트 뒤에도 유지됩니다.

* **실패 원인과 구간 수**: 번역 초안/검수 중 어느 단계인지, 요청한 자막 수와 실제 반환된 수, 처리한 구간 범위와 마지막 저장 진척을 남깁니다. 작업 처리가 끝났어도 번역이 일부만 생성됐으면 일부 완료·오류로 표시합니다.
* **다른 PC의 오류도 모으기**: 업로드 전 실패, 연결 오류, 영상 폴더의 SRT 저장 실패, 결과 저장 실패를 원본 PC가 보고합니다. 연결이 끊기면 원본 PC에 전송 대기를 저장하고 같은 서버에 다시 연결될 때 보냅니다. 수신 확인은 별도로 보관해 재실행 후 같은 기록을 계속 보내지 않습니다. 이 과정에서 분석·번역 요청을 다시 실행하지 않습니다.
* **남아 있는 과거 실패 가져오기**: 클라이언트의 기존 원격 분석 실패 결과와 서버의 저장된 완료 작업에서 기술 정보만 가져옵니다. 당시 버전·실패 단계·반환 개수가 없으면 미상으로 남깁니다. 이전 버전이 저장하지 않은 오류는 복원할 수 없습니다.

분석 서버와 원본 PC 모두 1.9.2를 실행해야 클라이언트에서만 발생한 오류까지 보고됩니다. Windows EXE의 내장 업데이트를 사용할 수 있으며, `분석서버_시작.bat`으로 켠 Node 서버는 새 소스로 다시 실행해야 합니다. 기존 주소·연결 코드·분석 결과·자막은 유지합니다. 로그에는 대사·이미지·프롬프트·연결 코드·인증 정보·원본 전체 경로를 넣지 않습니다. [진단 기록 검증](docs/diagnostics-validation.md)에 저장·전송·검증 범위를 정리했습니다.

### ⚡ 1.9.1 · 음성 인식 처리 대기와 저장 낭비 줄이기

* **GPU의 다음 구간을 먼저 준비**: 두 구간 병렬 처리에서 현재 구간의 대사 정리·저장을 기다리지 않고 다음 GPU 작업을 제출합니다. 결과는 원래 영상 순서대로 반영하며 실행·대기 작업 수를 제한합니다. NVIDIA 메모리 확인 도구가 PATH에 없으면 Windows의 정상 설치 경로에서도 찾습니다.
* **GPU 여유에 맞춘 병렬 시도**: CUDA 장치와 전체 메모리 8GiB 이상을 확인하고, 모델 준비 전 여유 4GiB·준비 후 여유 2GiB 조건을 충족하면 두 구간 처리를 시도합니다. 조건을 확인할 수 없거나 메모리가 부족하면 한 구간씩 처리합니다. 메모리 부족 시 완료 결과를 보관하고 실패한 구간만 제한적으로 재시도합니다.
* **긴 대사의 반복 복사·저장 줄이기**: 대사마다 전체 배열을 복사하지 않고, 주기적인 원문 저장이 밀리면 최신 대기로 합칩니다. 분석 전·실패 시·최종 원문 저장은 순서를 지켜 마무리합니다. 한국어 번역 저장에서도 같은 원문 지문과 JSON의 중복 계산을 줄입니다.
* **실제 사용 설정 표시**: 진행 화면과 저장 결과에 확인된 모델, 정확/빠름, GPU/CPU, 연산 형식과 병렬 수를 표시합니다. 이 PC의 품질 선택은 이 PC에서 요청하는 분석에 적용되고, 다른 PC가 보낸 분석은 그 PC의 선택으로 처리합니다. 속도 우선 설정의 저장 완료 안내도 실제 저장 성공 뒤에 표시합니다.

정확 모드의 `large-v3`, 전체 음성 범위, 단어별 시간 정렬, 누락 재검수와 한국어 번역 검수 기준은 유지합니다. 기존에 저장한 정확도 우선 선택도 바꾸지 않습니다. 실제 사용자 영상에서 몇 배 빨라지는지는 아직 측정하지 않았으며, [처리 개선 검증](docs/analysis-speed-validation.md)에 합성 검사 결과와 측정 범위를 구분합니다. 변경은 새 버전으로 시작한 분석부터 적용됩니다.

### 🔄 1.9.0 · 프로그램 안에서 자동 업데이트

* **직접 다시 내려받는 절차 줄이기**: Windows 실행 파일이 시작 후 새 버전을 확인하고, 이후 약 5분마다 확인합니다. 새 파일의 크기·SHA-256·실행 파일 형식을 확인한 뒤 별도 폴더에 보관합니다. 화면 위 **업데이트**에서 수동 확인·다운로드·적용과 자동 적용 설정을 사용할 수 있습니다.
* **분석이 끝난 뒤 적용**: 진행 중인 분석·번역·업로드·저장이 끝날 때까지 기다립니다. 기존 작업을 강제로 종료하지 않습니다. 유휴 상태에서 잠시 새 작업 입장을 닫고 앱이 스스로 교체·재실행하며, 브라우저도 같은 저장소의 새 버전을 확인한 뒤 새로고침합니다.
* **주소와 기록 유지**: 기존 로컬 포트, 분석 서버 포트·연결 코드·분석 결과·자막·사용자가 중지한 자동 분석 상태를 유지합니다. 서버 재시작 뒤에도 원격 PC가 이미 끝난 결과를 받아갈 수 있도록 완료 작업을 보관합니다. 새 버전을 활성화하기 전 준비 확인에 실패하면 이전 실행 파일로 복구합니다. 활성화를 시작한 뒤 확인이 실패하면 새 버전을 유지하고 화면에서 시작 확인을 다시 시도할 수 있습니다.

**처음 한 번은 양쪽 PC의 기존 프로그램을 종료하고 1.9.0 이상 실행 파일을 실행하세요.** 이전 버전에는 내장 업데이트 기능과 재시작 연결 복구가 없습니다. 이후에는 이 PC에서 수정하여 GitHub에 게시한 버전을 각 PC가 확인·적용하므로 매번 ZIP을 다시 받아 교체할 필요가 없습니다. 자동 적용을 끄면 새 버전 확인만 하고 직접 적용할 수 있습니다. 분석 서버 내부 로직 변경은 서버만 업데이트해도 계속 사용할 수 있고, 다른 PC의 화면·파일 저장 기능 변경은 그 PC에도 적용해야 합니다.

업데이트는 Windows EXE에서 지원합니다. Node 소스 실행과 테스트 환경에서는 자동 파일 교체를 하지 않습니다. [업데이트 보존·복구 검증](docs/managed-update-validation.md)에 적용 경계와 검증 범위를 정리합니다.

### 📝 1.8.2 · 중간에 멈춘 한국어 번역 복구

* **번역 길이 검사 보완**: 숫자를 한자로 길게 읽은 원문을 아라비아 숫자로 번역한 경우처럼 글자 수만으로 생략을 의심하던 검사를 보완합니다. 정확 모드에서는 짧은 초안도 원문 대조 검수를 거치며, 최종 검증을 통과한 자막만 보관합니다.
* **새로 번역한 부분도 보존**: 원격 복구 도중 뒤쪽 묶음이 실패하더라도 이번에 새로 검증된 번역이 기존보다 길면 결과와 부분 SRT에 반영합니다. 기존 완성 자막과 더 긴 번역은 보존합니다. 남은 구간은 **남은 한국어 자막 번역 계속**으로 이어 처리할 수 있습니다.
* **중단과 진행을 구분**: 종료된 작업의 미번역 구간을 ‘번역 대기’로 표시하지 않습니다. 번역된 구간 수·전체 원문 구간 수·마지막 번역 시각·실제 오류를 함께 표시합니다. 번역이 전부 끝났고 원어 검수만 남은 경우는 별도로 안내합니다.

원격 복구에는 영상을 선택한 PC와 분석 서버 PC 모두 새 버전을 실행하세요. 기존 원문과 번역 진행 기록을 재사용하므로 자막만 복구할 때 음성 인식과 줄거리를 다시 만들지 않습니다. 제공자가 요청을 거절하거나 사용량·인증·연결 오류가 있으면 원인과 보관된 구간을 표시합니다. [번역 중단 복구 검증](docs/subtitle-continuation-validation.md)에 변경과 확인 범위를 정리합니다.

### ▶️ 1.8.1 · 자막 복구와 자동 분석 대기 연결

* **품질 경고가 있어도 다음 영상 진행**: 전체 음성을 처리하고 요약과 요청한 한국어 번역을 마친 결과는 원문 검수 경고 때문에 ‘일부 완료’여도 다음 대기 영상을 분석합니다. 해당 영상의 미확인 구간과 부분 자막 표시는 그대로 유지합니다. 실행 오류·번역 실패·사용자 중지는 계속 구분해 안내합니다.
* **실패했던 영상의 복구 후 자동 연결**: 자동 분석이 특정 영상의 오류로 중지된 경우, 같은 결과를 복구하여 오류가 해결되면 그 오류로 생긴 중지를 풀고 다음 영상을 진행합니다. 사용자가 직접 중지한 작업, 다른 영상의 오류, 원인을 확인할 수 없는 예전 중지 상태는 자동 해제하지 않습니다.
* **뽑기 화면에서 바로 재개**: ‘자동 분석 대기 · 일시 중지됨’ 옆에 실제 이유와 **자동 분석 재개** 버튼을 표시합니다. 복구가 진행 중일 때 재개해도 해당 복구를 마친 뒤 대기 영상을 순서대로 시작합니다. 기존 **설정 적용 · 대기 분석 계속** 버튼도 사용할 수 있습니다.

1.8.0까지의 버전에서 이미 중지된 대기는 **자동 분석 재개**를 한 번 눌러 주세요. 실행 파일을 업데이트해도 대기 목록과 분석 결과·서버 연결은 유지합니다. 적용·검증 범위는 [자동 분석 대기 복구 검증](docs/auto-queue-recovery-validation.md)을 참고하세요.

### ⚡ 1.8.0 · 한국어 번역만 복구와 속도 우선 설정

* **한국어 자막 번역만 복구**: 목록이나 상세 화면에서 저장된 원문 대사와 시작·종료 시각을 그대로 사용해 한국어 번역만 다시 만들 수 있습니다. 음성 인식·대표 이미지 추출·줄거리 요약은 재실행하지 않습니다. 검증된 번역 앞부분이 있으면 이어서 처리하며, 완성된 번역을 다시 요청하면 새로 번역합니다. 원래 분석과 이미지는 보관하고 복구 결과를 새 기록으로 저장합니다. 저장된 원문이 없거나 원본 영상이 변경된 것으로 확인되면 전체 분석을 먼저 해야 합니다.
* **부분 자막도 저장**: 번역한 한국어 자막은 원본 영상이 있는 PC의 폴더에 자동 저장합니다. 원문 인식에 미확인 구간이 있으면 번역을 마쳐도 그 상태를 유지하며 `.ko.partial.srt`로 저장합니다. 번역 복구는 원어 인식의 누락·오인식을 해결하지 않습니다. 상세 화면에서 번역 복구 결과와 원문 검수 상태를 구분해 확인할 수 있습니다.
* **새 설정의 기본값은 속도 우선**: 기존 자막을 먼저 사용하고, 자막이 없거나 전체 음성 인식을 선택했으면 `small` 모델로 인식합니다. 호환되는 GPU가 있으면 사용합니다. 문장 구간의 실제 시각을 사용하며 단어별 시간 정렬과 발화 누락 재검수를 생략합니다. 처리량을 줄이는 대신 조용한 대사·어려운 발음의 인식과 세밀한 자막 경계는 정확도 우선보다 부정확할 수 있습니다. 기존에 저장한 **정확도 우선** 선택은 업데이트 후에도 유지하므로 바꾸려면 **속도 우선으로 설정**을 누르세요. 이 변경은 다음 분석부터 적용합니다.
* **분석·번역 버전 기록**: 새 분석 결과에는 실행한 앱과 응답한 분석 서버의 버전, 확인된 음성 인식 설정을 기록합니다. 번역만 복구하면 원래 분석 버전을 유지하고 이번 번역 복구 버전을 따로 기록합니다. 과거 결과에 버전이 기록되지 않았다면 **기록 없음**으로 안내하며 저장 시각이나 인식 방식만으로 당시 버전을 추정하지 않습니다.

새 기능은 **분석 서버 PC와 영상을 선택하는 PC 모두 1.8.0으로 실행**해야 적용됩니다. 진행 중인 작업이 끝난 뒤 기존 프로그램을 종료하고 새 실행 파일을 실행하세요. 주소·연결 코드·저장 결과는 유지됩니다. 이미 실행 중인 작업의 처리 방식은 바뀌지 않습니다. 실제 긴 영상의 처리시간 비교는 아직 측정하지 않았으므로 속도 향상 배수나 1~2분 완료를 보장하지 않습니다.

검사 범위와 배포 확인은 [번역 전용 복구·속도 설정 검증](docs/translation-repair-validation.md)을 참고하세요.

### ⚡ 1.7.1 · GPU 음성 인식 병렬 처리와 진행 시간

* **GPU에서 두 구간 병렬 처리**: 여유 메모리가 확인되는 NVIDIA GPU에서는 같은 `large-v3` 모델로 최대 두 음성 구간을 함께 처리합니다. 전체 음성 범위·단어별 시간·누락 검수와 인식 설정을 유지합니다. GPU 메모리가 부족하면 완료된 구간을 보관하고 남은 구간을 순차 처리합니다. CPU와 GPU 여유를 확인할 수 없는 환경은 순차 처리합니다.
* **실제 처리량과 단계별 예상 시간**: 인식이 끝난 음성 길이와 전체 길이를 표시합니다. 충분한 관측값이 쌓이면 현재 음성 인식 또는 재검수 단계의 예상 잔여 시간을 보여 줍니다. 검수·줄거리·번역을 포함한 전체 작업 완료 시간은 아닙니다. 대사 시각과 구간 완료율이 서로 다른 기준으로 퍼센트를 덮어쓰던 문제를 수정했습니다.
* **서버도 새 버전으로 실행**: 다른 PC의 프로그램만 교체하면 서버의 음성 인식 방식은 바뀌지 않습니다. 진행 중인 분석을 마친 뒤 분석 서버 PC도 1.7.1로 실행하세요. 기존 서버 주소·연결 코드·저장된 결과는 유지됩니다. 이미 실행 중인 분석에는 새 처리 방식이 소급 적용되지 않습니다.

실제 속도 향상은 GPU와 영상에 따라 다릅니다. 이번 검증에서는 운영 분석과 GPU 시험을 겹쳐 실행하지 않았으므로, 몇 배 빠르다거나 긴 영상이 1~2분에 끝난다는 수치를 제시하지 않습니다. 검증 범위와 재현 방법은 [음성 인식 처리 개선](docs/asr-performance-validation.md)을 참고하세요.

### 🛠️ 1.7.0 · 반복 사용을 위한 성능과 복구

* **가벼운 영상 목록**: 목록과 진행 확인에는 전체 대사·번역을 보내지 않습니다. 상세 보기를 열 때 해당 영상의 전체 내용을 읽고, 긴 대사는 200구간씩 화면에 추가합니다. 엑셀·SRT에는 전체 내용을 사용합니다.
* **중단된 선택/복구 분석 재개**: 1.7.0에서 새로 시작한 작업은 분석 전에 남은 파일 목록을 PC에 저장합니다. 프로그램을 다시 열면 **중단된 분석 작업 → 남은 영상 분석 재개**가 표시됩니다. 저장된 결과는 유지하고 미처리 파일만 현재 설정으로 다시 시작합니다. 처리 중이던 파일은 처음부터 다시 분석하며, 재개 전 원본의 크기·수정 시각을 확인합니다. 필요 없는 대기는 **이 대기 작업 취소**로 제외할 수 있고 결과·영상은 보존합니다. 사용자가 취소한 작업은 자동으로 되살리지 않습니다.
* **실제 처리 시간**: 진행 화면에 경과 시간과 현재 단계 시간을 표시하고, 완료 결과의 상세 화면에 단계별 소요 시간을 보관합니다. 예상 완료 시간으로 표시하지 않습니다.
* **환경 확인 중복 방지**: 동시에 들어온 Codex·음성 환경 확인 요청은 같은 검사 결과를 공유합니다.
* **짧은 연결 끊김 복구**: 이미 분석 서버가 접수한 같은 작업의 상태 확인만 최대 3회 다시 시도합니다. 업로드·분석 요청을 중복 제출하거나 인증·사용량 제한·분석 거절을 재시도하지 않습니다.
* **실행과 요청 안정성**: 저장 폴더의 단일 실행 소유권을 확인한 뒤 작업을 복원합니다. 비정상 스캔·재생 요청과 잘못된 JSON은 오류를 응답하고 프로그램은 계속 실행합니다.

50개 영상·각 1,000개 대사의 합성 목록에서 전송 JSON이 7,730,623바이트에서 55,973바이트로 약 99.3% 줄었습니다. 이는 목록 전송량 측정이며 영상 인식 속도나 인식률 개선 수치가 아닙니다. 자세한 검증·적용 범위는 [서비스 운영 개선 검증](docs/service-readiness-validation.md)을 참고하세요.

### 📝 영상 내용 분석 · 이미지 포함 엑셀 목록

**뽑은 영상 자동 분석**은 기본으로 켜져 있습니다. 무작위 뽑기로 당첨된 영상은 체크하거나 **선택 영상 분석**을 누르지 않아도 현재 분석 방식으로 자동 처리됩니다. 이미 분석이 완료된 영상은 저장한 결과를 재사용하며, 같은 영상이 대기 중이거나 분석 중이면 중복으로 추가하지 않습니다. 다른 분석이 진행 중이면 뽑은 순서대로 기다렸다가 한 개씩 처리합니다. 수동 선택 분석도 계속 사용할 수 있습니다.

자동 분석 대기 목록은 해당 PC에 보관됩니다. 프로그램을 다시 열면 저장된 서버 연결과 남은 대기 목록을 복원합니다. 한 번 **연결 확인**에 성공한 서버 주소와 연결 코드는 해당 PC의 사용자별 데이터 폴더에 암호화해서 보관하므로 실행 파일을 업데이트해도 다시 입력할 필요가 없습니다. 분석 방식이나 연결 준비가 되지 않았을 때는 대기 상태로 표시하며 로컬 분석으로 임의 변경하지 않습니다. 자동 분석을 끄면 새로 뽑은 영상을 추가하지 않고 대기 중인 처리를 멈추며, 이미 진행 중인 분석은 계속됩니다. 분석 중지나 오류로 멈춘 대기는 상태를 확인한 뒤 **설정 적용 · 대기 분석 계속**을 누르세요.

폴더를 스캔한 뒤 **영상 내용 목록**에서 분석할 파일을 선택하고 **선택 영상 분석**을 누릅니다. 파일명, 전체 경로, 재생 시간, 한 줄 요약, 줄거리, 대사 요약, 라벨과 대표 이미지를 함께 관리할 수 있습니다. 분석한 내용과 라벨은 직접 수정해서 저장할 수 있습니다.

목록의 **정렬 순서**에서 **분석 완료 우선**, **최근 분석순**, **파일명 오름차순·내림차순**, **경로·드라이브순**을 선택할 수 있습니다. 기본은 분석 완료 우선이며, 완료된 영상을 위로 모으고 같은 상태에서는 최근 저장한 분석부터 표시합니다. 파일명은 `영상2`가 `영상10`보다 먼저 나오도록 자연스럽게 정렬합니다. 검색과 상태 필터를 적용한 전체 목록을 정렬한 뒤 페이지로 나누며, 같은 브라우저에서 선택한 정렬 방식을 기억합니다. 정렬은 화면 표시만 바꾸므로 원본 영상과 저장된 분석 내용은 유지됩니다.

**복구 / 다시 분석**은 목록과 상세 화면에서 사용할 수 있습니다. 로컬 추출만 완료된 결과, 빈 요약, 일부 완료와 실패를 구분해서 안내합니다. 자동 요약 결과가 비어 있으면 완료로 처리하지 않습니다. 503 오류는 요약 서비스의 일시적인 응답 실패로 안내합니다. Codex / 서버 복구에서는 저장된 이미지와 시간별 대사가 온전하면 이를 재사용해 요약과 번역을 다시 요청합니다. 자료가 없거나 언어·이미지 수를 변경하거나 전체 음성 다시 인식을 선택하면 새로 추출합니다. 복구 결과는 새 기록으로 저장하며 이전 요약과 이미지는 유지합니다. 다른 분석이 진행 중이면 완료 후 복구를 실행할 수 있습니다. 자동 줄거리가 필요하면 분석 방식을 **이 PC에서 분석** 또는 **분석 서버 PC로 보내기**로 선택하세요. 서비스 사용량 제한이나 분석 거부는 원인을 표시하며 우회하거나 무한 재시도하지 않습니다.

**시간에 맞춘 자막**은 상세 화면에서 원문과 한국어 번역을 확인하고 **SRT 저장 / VTT 저장**으로 내보낼 수 있습니다. 음성 언어는 자동 감지하거나 일본어·중국어로 지정할 수 있습니다. Codex / 서버 분석의 한국어 번역 옵션은 기본으로 켜져 있으며, 원문 대사도 함께 보관합니다. 번역 자막의 시작·종료 시간은 실제 음성 인식 또는 기존 자막의 시각을 그대로 사용합니다. 번역에 실패하면 원문·줄거리·이미지를 보존하고 오류를 표시합니다. 로컬 추출은 원문 자막을 저장합니다. **긴 영상 재검수 개선이 적용되는 정확도 우선 자막은 양쪽 PC에서 1.6.6 이상을 실행해야 합니다.** 실행 파일 교체만으로 이미 실행 중인 서버가 바뀌지는 않습니다. 자동 음성 인식은 녹음 상태에 따라 시각과 대사가 부정확할 수 있어 검토가 필요합니다.

**한글 자막 정확도 우선**을 선택하면 한국어 번역을 켠 새 분석에서 전체 음성을 검수합니다. 1.8.0의 새 설정 기본값은 **속도 우선**이며, 기존에 저장한 정확도 우선 선택은 그대로 유지합니다. 정확 모드로 전체 음성 인식을 마친 자료는 복구할 때 재사용합니다. 정확도 우선은 기존 자막이 영상 초반에만 있어도 이를 전체 대사로 간주하지 않고, 원본 전체 음성을 무손실 FLAC으로 추출해 `large-v3`로 인식합니다. 전체 구간을 겹치는 창으로 읽고 발화 검출 결과와 대조해 누락 의심·낮은 신뢰도 구간을 제한된 범위에서 다시 확인합니다. 긴 무음 뒤의 말은 새 창에서 듣도록 경계를 조정하며, 발화 검출로 조용한 음성을 처음부터 버리지 않습니다. 단어 시간이 유효하면 그 경계에서 읽기 좋은 자막으로 나누고, 단어 정렬을 얻지 못한 부분은 실제 문장 구간의 시간을 사용합니다. 상세 화면에 모델·처리한 영상 길이·미해결 구간을 표시합니다. 전체 처리 완료는 모든 단어가 정확하다는 보증이 아닙니다.

한국어 번역은 줄거리 요약과 별도로 **모든 원문 자막 구간**을 번역합니다. 앞뒤 문맥·이전 번역·고유명사 표기를 함께 참고하며, 정확도 우선에서는 초안을 원문과 다시 대조해 누락·숫자·부정 표현·호칭·말투를 검수합니다. 원문의 구간 수와 시간은 변경하지 않습니다. 원어 인식과 번역 진행은 별도로 보관하므로 요약·번역 오류가 나도 대사를 잃지 않습니다. 확인할 원어 구간이 남아 있어도 인식된 대사의 검수된 한국어 번역은 **부분 자막**으로 표시하고 직접 저장할 수 있습니다. 아직 번역되지 않은 구간은 원문과 대기 표시를 유지합니다. 부분 파일 이름에는 `.ko.partial.srt` 또는 `.ko.partial.vtt`가 붙으며 자동으로 플레이어용 SRT를 교체하지 않습니다. **복구 / 다시 분석**은 같은 원문·시간·번역 버전의 검증된 앞부분을 이어 사용합니다. 새 원어 인식 결과가 달라지면 다시 번역합니다. 누락 확인이 끝나지 않았거나 번역이 실패한 자료를 완성된 한글 SRT로 자동 저장하지 않습니다.

`large-v3`는 첫 사용 시 약 3GB를 내려받으며 작은 모델보다 메모리와 처리 시간이 더 필요합니다. 호환되는 NVIDIA GPU 실행 환경이 있으면 GPU를 사용하고, 사용할 수 없으면 **같은 모델**을 CPU로 실행하며 안내합니다. CPU에서는 긴 영상에 상당한 시간이 걸릴 수 있습니다. **속도 우선**에서는 기존 자막과 `small` 모델을 사용합니다. 음성 인식 모델과 장치·연산 방식을 환경변수로 직접 지정한 경우에는 그 설정을 유지합니다. 기존 분석 결과는 자동으로 바뀌지 않으므로 원어 인식부터 개선할 영상에서 **정확도 우선 → 복구 / 다시 분석**을 선택하세요. 저장된 원문은 유지하고 한국어만 고치려면 **한국어 자막 번역만 복구**를 사용하세요. 이전 결과와 자막 파일은 보존됩니다. 재현 가능한 공개 음성 비교 방법과 한계는 [자막 품질 검증](docs/subtitle-quality-validation.md)을 참고하세요.

**1.6.1의 누락 보완**: 재인식 문장 안에 기존 문맥이 함께 있어도 실제 새 단어를 시간 단위로 보존합니다. 단어의 종료 시각이 역전되는 정렬 오류는 원래 문장의 시간을 사용하고 안내합니다. 긴 영상은 단어별 진단 정보보다 전체 원문·한국어 자막 전송을 우선합니다. 1.6.0 이전 방식으로 저장한 원문은 정확도 우선 복구에서 새 인식으로 갱신하며, 새 누락 검수를 통과한 자료만 재사용합니다. 자세한 재현과 한계는 [누락 보완 검증](docs/subtitle-omission-validation.md)을 참고하세요.

**1.6.2의 원격 환경 안내 수정**: **분석 서버 PC로 보내기**에서는 클라이언트 PC의 Codex·`faster_whisper` 설치 오류를 분석 필수 조건처럼 표시하지 않습니다. 해당 도구는 분석 서버 PC에 필요합니다. **이 PC에서 분석**을 선택하면 로컬 환경의 실제 오류를 계속 안내하고 준비되지 않은 분석을 막습니다. ‘일부 완료’의 실제 실패 사유는 해당 결과의 상세 보기에서 별도로 확인해야 합니다.

**1.6.3의 분석 설정 화면 수정**: 긴 자막 설명 때문에 오른쪽 입력칸이 사라지거나 설정 화면이 늘어나는 문제를 수정했습니다. 창이 작아지면 설명과 입력칸을 줄바꿈하며, 로컬 추출 모드로 다시 열어도 이 PC·서버 분석에서 사용할 한국어 번역 자막 선택을 유지합니다.

**1.6.4의 목록 재생 버튼**: 영상 분석 목록의 파일명 아래에서 **▶ 재생**을 누르면 해당 PC의 기본 동영상 플레이어로 바로 엽니다. 분석 전·후 영상 모두 사용할 수 있고, 재생 요청은 전체 영상 히스토리에 저장됩니다.

**1.6.5의 영상별 진행 표시**: 복구·다시 분석을 누르면 해당 영상 행과 상세 화면에 **복구 요청 중 → 복구 중**을 표시하고 현재 단계와 진행률을 갱신합니다. 선택 분석도 현재 처리 중인 파일과 대기 중인 파일을 구분합니다. 파일 경로로 작업을 연결해 같은 이름의 다른 영상에 진행 표시가 붙지 않으며, 실패·중지 후에는 이전 결과를 보존하고 다시 시도할 수 있습니다.

**1.6.6의 부분 자막 보관과 긴 영상 재검수**: 검수된 한국어 부분 자막도 원본 영상 옆에 `<영상명>.ko.partial.srt`로 자동 저장합니다. 기존 결과는 상세 화면의 **영상 폴더에 저장**으로 재분석 없이 내보낼 수 있습니다. 완성본 `.ko.srt`와 수동 수정한 자막은 보존합니다. 재검수의 고정 600초 제한을 없애 뒤쪽 불확실 구간까지 확인하고, 실제 재인식에서 정상으로 확인된 대사의 이전 저신뢰 표시와 분할·정렬 복구를 반영합니다. 전체 음성 처리, 불확실성 검수, 번역 검수 상태를 구분하며 미해결 구간은 계속 안내합니다. 자세한 검증과 한계는 [재검수 검증](docs/subtitle-recovery-validation.md)을 참고하세요.

**한국어 SRT 자동 저장**: 번역이 완성되면 영상을 선택한 PC의 원본 영상 폴더에 `<영상 파일명에서 확장자를 뺀 이름>.ko.srt`를 자동으로 저장합니다. 검수된 부분 자막은 `.ko.partial.srt`로 저장합니다. 분석 서버를 사용하는 경우에도 원본이 있는 클라이언트 PC에 저장합니다. 같은 이름의 기존 파일과 내용이 같으면 그대로 사용합니다. 프로그램이 생성한 경로와 바이트 해시가 저장 이력과 정확히 일치하면 이전 자막을 `.bak`으로 보존한 뒤 같은 이름으로 갱신합니다. 수동 작성·수정한 자막은 그대로 두고 별도 이름으로 저장하며, 이때 플레이어에서 상세 화면에 표시된 SRT 경로를 직접 불러오세요. 이미 재생 중인 플레이어는 갱신한 자막을 다시 불러오거나 영상을 다시 열어야 할 수 있습니다. 실제 저장 경로·백업·실패 사유는 상세 화면에 표시되고 재실행 후에도 확인할 수 있습니다. 영상 폴더 쓰기 권한 등의 이유로 자동 저장하지 못해도 분석 결과와 번역 자막은 프로그램에 남으며 **SRT 저장**으로 직접 내려받을 수 있습니다. 이전 기록에 자동 저장 내역이 없으면 상세 화면의 **영상 폴더에 저장**을 누르세요. 원문 인식을 새로 검수하려면 복구 / 다시 분석을 사용하세요.

* **로컬 분석**: 인터넷이나 API 키 없이 영상 전체 구간에서 대표 이미지 10장을 추출하고, 같은 이름의 SRT/VTT/ASS 자막 또는 영상 내부의 텍스트 자막을 읽습니다. AI 줄거리와 라벨은 생성하지 않으며 직접 입력할 수 있습니다.
* **이 PC의 Codex 분석**: API 키 없이 이 PC에 로그인된 Codex를 자동 실행해 실제 자막·대사와 대표 이미지를 바탕으로 한국어 줄거리, 대사 요약, 라벨, 장면 설명을 만듭니다. 정확도 우선 한글 자막은 전체 음성을 인식합니다. 속도 우선에서는 자막이 없으면 음성을 인식하며, 자막이 있어도 전체 음성을 다시 인식하도록 설정할 수 있습니다.
* **분석 서버 연결**: 다른 PC에서는 Codex 로그인과 음성 인식 도구 없이 서버 PC로 대표 이미지·자막/압축 음성을 보내 분석할 수 있습니다. 서버 PC에서 **이 PC를 분석 서버로 사용 → 서버 시작**을 누르고, 다른 PC의 **분석 서버로 보내기** 설정에 표시된 주소와 연결 코드를 입력합니다. 반환된 줄거리·전체 대사·이미지는 다른 PC에서도 수정하고 엑셀로 저장할 수 있습니다.
* **자동 캡처**: 영상 길이를 읽고 전체 구간을 같은 간격으로 나누어 대표 이미지 10장을 자동 추출합니다. 30분 영상은 약 3분 간격, 2시간 영상은 약 12분 간격입니다. 시각을 입력할 필요가 없으며 이미지 수만 1~20장으로 조절할 수 있습니다. 이전 버전에 저장한 직접 캡처 시점 설정도 적용하지 않습니다.
* **이미지 포함 Excel**: 분석한 파일을 선택하고 엑셀 저장 버튼을 누르면 `.xlsx`를 내려받습니다. **영상 목록**, 실제 이미지를 삽입한 **장면 이미지**, 시간 표시가 붙은 **전체 대사** 시트가 포함됩니다. **전체 대사**에는 원문과 같은 시각의 **한국어 자막**도 나란히 포함됩니다. 엑셀을 다른 컴퓨터로 옮겨도 이미지를 볼 수 있습니다.
* **진행률·중지·복원**: 분석은 파일별로 진행합니다. 중지하면 그때까지 얻은 결과를 저장합니다. 프로그램을 다시 실행해도 저장한 분석 결과가 표시됩니다.

Codex 분석은 API 키를 사용하지 않습니다. 음성 인식은 로컬 Whisper로 처리하고, 대표 이미지와 추출된 대사는 ChatGPT에 로그인된 Codex로 전송해 요약하므로 인터넷과 유효한 로그인, Codex 사용량이 필요합니다. 현재 열린 채팅창과는 별도의 자동 분석 작업으로 실행됩니다. 계정 사용량 한도가 적용되며 무제한 무료 분석을 의미하지 않습니다. 자동 인식·요약은 필요하면 내용을 검토하고 수정해 주세요.

랜선과 Wi-Fi 여부는 연결 조건이 아닙니다. 두 PC가 같은 공유기의 내부망에 연결돼 있으면 사용할 수 있습니다. **외부 인터넷에 공개하는 기능은 제공하지 않으며**, 내부 IP와 연결 코드로만 연결합니다. 게스트 Wi-Fi 격리나 Windows 방화벽으로 연결되지 않으면 다른 PC에서 **연결 확인**을 눌러 안내를 확인하세요. Windows 방화벽을 사용할 때는 이 프로그램의 개인 네트워크 수신을 허용해야 할 수 있습니다. 서버는 기본 3001번 포트를 사용하고, 스캔·재생·파일 열기 기능은 계속 해당 PC의 로컬 화면에서만 사용할 수 있습니다. 서버의 연결 코드와 서버 시작 설정도 PC에 보관해 프로그램을 다시 켜면 이어 사용합니다. 연결 코드는 브라우저 저장소·결과 파일·자동 분석 대기 파일에 넣지 않으며 Windows 사용자 계정의 암호화 저장소로 보호합니다. 서버 PC와 프로그램은 분석하는 동안 켜져 있어야 합니다.

1.9.0 이전 버전에서 처음 교체하거나 실행 파일을 직접 내려받아 교체할 때는 이전 VideoRandom 프로그램을 종료한 뒤 새 실행 파일로 교체하세요. 1.9.0부터는 위의 내장 업데이트로 다음 버전을 적용할 수 있습니다. 저장된 연결과 분석 결과는 `%LOCALAPPDATA%\VideoRandom\catalog`에 남습니다. 1.4.0까지의 버전은 연결 코드를 메모리에만 보관했으므로, 이미 종료한 이전 버전에서 옮기는 경우 이번 버전에서 한 번 **연결 확인**을 해야 합니다. 그 이후 업데이트에서는 저장된 연결을 자동으로 복원합니다. 다른 서버로 바꾸거나 저장된 연결을 없애려면 **저장된 연결 지우기**를 사용하세요.

서버 PC 준비: Codex에서 ChatGPT 계정으로 로그인하고, Python이 있는 환경에서 동봉한 **분석서버_준비.ps1**을 실행합니다. 속도 우선용 런타임과 작은 모델만 준비하려면 `-SubtitleQuality fast`를 붙입니다. 옵션 없이 실행하는 준비 스크립트는 정확도 우선용 `large-v3` 모델을 설치하므로 프로그램의 속도 우선 기본 설정과는 구분됩니다. 호환되는 NVIDIA GPU가 있는 서버에서는 `-NvidiaGpu`를 추가해 해당 가상 환경에 GPU 라이브러리를 설치할 수 있습니다. 다른 PC를 클라이언트로만 쓰면 이 준비 과정이 필요 없습니다. 업데이트 후 서버도 새 프로그램으로 다시 실행해야 새 자막 품질 기능이 적용됩니다. 저장한 주소·연결 코드·분석 결과는 유지됩니다.

현재 PC는 Windows에서 공용 네트워크로 분류돼 단독 실행 파일의 LAN 수신이 차단됩니다. **분석서버_시작.bat**으로 기존 Node 환경에서 실행하면 서버를 자동으로 시작하며, 현재 PC에서 내부 IP 접속을 확인했습니다. 다른 PC에서는 새 `videorandom.exe`만 실행하면 됩니다. 이 PC에서 실행 파일을 서버로 사용할 경우에는 Windows 방화벽에서 이 프로그램의 수신 허용이 별도로 필요할 수 있습니다.

영상 분석 도구 FFmpeg와 FFprobe는 npm 의존성 및 새로 빌드한 실행 파일에 포함됩니다. 분석 결과와 이미지는 기본적으로 `%LOCALAPPDATA%\VideoRandom\catalog`에 저장됩니다. `VIDEORANDOM_DATA_DIR`로 저장 폴더를 바꾸고, `FFMPEG_PATH` / `FFPROBE_PATH`로 별도의 도구 경로를 지정할 수 있습니다.

분석 서버를 이용해도 완료된 줄거리·라벨·전체 대사·대표 이미지는 **영상을 선택한 PC의 로컬 폴더**에 자동 저장됩니다. 화면에 저장 위치를 표시하며, 프로그램을 다시 실행하면 스캔 없이 저장 결과를 불러옵니다. 저장 결과를 보거나 엑셀로 내보낼 때는 분석 서버가 꺼져 있어도 됩니다. 다만 진행 중인 분석은 해당 PC가 결과 수신과 저장을 마치기 전까지 프로그램을 켜 두어야 합니다. 같은 영상을 재분석할 때도 이전 완료 파일과 이미지를 보관하며, 새 분석이 실패하거나 중지되면 이전 완료 결과를 계속 표시합니다.

기술 참고: [Codex 자동 실행](https://learn.chatgpt.com/docs/non-interactive-mode), [ChatGPT 로그인](https://learn.chatgpt.com/docs/auth), [로컬 음성 인식](https://github.com/SYSTRAN/faster-whisper).

### 1. 📂 윈도우 순정 폴더 찾아보기 (Native Folder Dialog)
* 입력창 옆 **`찾아보기(📁)` 아이콘 버튼**을 누르면, Windows 10/11의 순정 폴더 탐색기 대화상자가 즉시 실행됩니다. 
* 폴더나 디스크를 선택하는 순간 **자동으로 초고속 파일 인덱싱 스캔이 트리거**되어 극도로 편리합니다.

### ⚡ 2. 실시간 드라이브 감지 진행률 (% 표기)
* 프로그램이 켜지거나 새로고침될 때, 연결된 드라이브(C드라이브 및 외부 USB/외장하드디스크)를 **0%에서 100%까지 오르는 감속 로더와 체크 드라이브 문자(C:\, D:\ 등)**로 세련되게 알려줍니다.

### 🔗 3. 다중 디스크 묶음 일괄 스캔 (Multi-Disk scan)
* `C:\`, `D:\`, `E:\` 등 화면에 감지된 드라이브 카드를 **마우스로 중복 클릭하여 원하는 만큼 묶어서 한 번에 인덱싱**할 수 있습니다. 
* 다중 경로 병렬 BFS 스캔을 거쳐 모든 스토리지의 영상을 단 한 장의 통합 룰렛으로 돌릴 수 있습니다.

### 🎰 4. 사이버 틱 장치 & 감속 룰렛 피드백
* 클릭과 동시에 사이버 레이저 사운드 및 입자가 폭발하는 물리엔진 연출이 펼쳐집니다.
* 실제 슬롯머신처럼 **점진적 마찰력 감속 알고리즘**이 탑재되어, 룰렛의 속도가 점차 늦어지며 긴장감 넘치게 당첨 파일을 엄선합니다.

### 🛠️ 5. 원클릭 탐색기 열기 & 기본 앱 즉시 재생
* 당첨된 파일의 **`즉시 재생하기`** 버튼을 누르면 Windows 시스템에 **기본 재생 플레이어로 즉시 동영상이 팝업 재생**됩니다.
* **`폴더 위치 열기`** 버튼을 누르면 띄어쓰기가 있는 복잡한 경로명이라도 완벽히 추적하여 **폴더를 열고 당첨된 파일을 정확히 파랗게 선택(하이라이트)**해 줍니다.

### 🚫 6. 제외할 폴더명 및 경로 지정 (Folder Exclusion)
* 스캔 시 탐색에서 제외하고 싶은 **특정 폴더명**(`Cache`, `Temp` 등) 또는 **전체 경로**(`D:\huge_folder`)를 입력창에 자유롭게 지정할 수 있습니다.
* **입력 예시**: `ex) Cache, Folder\,Name, D:\huge_folder` (쉼표로 구분하며, 폴더명 자체에 콤마가 있을 경우 `\,` 입력)
* 입력된 제외 설정은 브라우저 `localStorage`에 자동 저장되어 다음 접속 시에도 그대로 유지됩니다.

### 🏷️ 7. 포맷 필터 (Format Filter)
* 스캔 완료 후 감지된 전체 동영상 중 원하는 확장자(`.mp4`, `.mkv`, `.avi` 등)를 선택하여 실시간으로 목록 및 개수를 필터링할 수 있습니다.

### 🎲 8. 선택한 포맷 제외하기 (Roulette Exclude Filter)
* 룰렛을 돌리기 전 특정 포맷을 선택한 뒤 **"선택한 포맷 제외하기"** 옵션을 체크하면, 해당 확장자의 동영상들을 룰렛 뽑기 대상에서 깔끔하게 제외하고 뽑기를 진행할 수 있습니다.

2. 실행하고 싶은 윈도우 PC 아무 곳에나 복사한 뒤, **더블 클릭하면 즉시 웹 앱과 연동되어 구동**됩니다!

npm start

* **폴더명 공백 호환성**: 모든 Windows 탐색기 연결 명령어는 파일 및 폴더 이름에 공백(띄어쓰기)이나 한글, 특수문자가 포함되어도 안전하게 따옴표 래핑 처리가 수행되어 실패 없이 견고히 작동합니다.
